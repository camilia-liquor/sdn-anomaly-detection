# Word 交付稿生成说明

本文件说明 `competition/` 下两份 Word 交付稿的来源、生成管线、校验方式，以及导出环节的已知限制与绕过办法。

## 1. 交付物

| 文件 | 来源 | 规模 |
| --- | --- | --- |
| `competition/实验报告.docx` | `docs/02_实验报告.md`（由 `tools/make_report.py` 生成） | 794 段 / 15 张表 / 5 张图 |
| `competition/技术报告.docx` | `competition/02_技术报告.md` | 1686 段 / 50 个标题 / 47 张表 / 5 段代码 |

两份 `.docx` 均已纳入版本库；同名 `.univer` 是生成它们的可编辑容器，属中间产物，已在 `.gitignore` 中排除。

## 2. 生成管线（完全由 Markdown 派生）

```
Markdown 源（docs/02_实验报告.md、competition/02_技术报告.md）
   ↓ 解析为块：标题 / 段落 / 列表（含惰性续行）/ 引用 / 代码块 / 表格 / 独立成行的图片
Univer Doc 单元（<name>.univer 的工作树 worktree）
   ↓ univer_export
<name>.docx
```

- **标题**：命名样式（`TITLE` / `HEADING_2` / `HEADING_3` / `HEADING_4`）。
- **表格**：真实表格对象；列宽按各列最长单元格文本加权分配（总宽 600~860 px，页宽 860 px），首行为表头行。
- **图片**：Markdown 的 `![alt](相对路径)` 自动内嵌——读 PNG 文件头解析像素尺寸，等比缩放到宽 600 px，并在图下自动补「图 N　alt」题注。
- **列表**：无序列表渲染为「•」，有序列表保留序号；**折行的续行并入同一条目**（见第 5 节）。

## 3. 两个已确认的导出器限制与绕过办法

Univer 当前的 `.docx` 导出器会丢弃部分样式信息，实测确认并已绕过：

| 限制 | 表现 | 绕过办法 |
| --- | --- | --- |
| 命名样式不写入 | 导出的 `document.xml` 中无 `w:pStyle`，`styles.xml` 只有 `Normal`/`TableNormal` 等 5 个样式，标题在 Word 里看不出层级 | 给标题段落同时写「直接格式」（粗体 + 字号：TITLE 22pt / H2 17pt / H3 14pt / H4 12pt），run 级直接格式能正常导出（`w:b`、`w:sz`） |
| 表级边框不写入 | `setTableBorder()` 对表格整体设置边框后，导出结果里没有 `w:tblBorders` | 改为逐单元格 `cell.setBorder({preset: Outer, color: '#BFBFBF', width: 1})`，导出为 `w:tcBorders`；并用 `cell.setBackgroundColor('#EFEFEF')` 给表头行加底色（导出为 `w:shd`） |

代价说明：命名样式丢失意味着 Word 的「导航窗格 / 自动目录」无法按标题层级生成；正文排版、表格格线、图片、代码等宽字体、引用斜体均正常。需要带真实标题样式的版本时，可用 `office_*`（zagens-office）另行导出。

## 4. 内容保真校验（每次导出后必跑）

口径：把 Markdown 的每个内容片段（正文行、表格单元格、代码行）规范化后，逐条检查是否都出现在导出稿的正文里；未命中即说明转换漏内容。

校验时有三处必须与转换器口径一致，否则会误报：

1. **XML 实体要还原**：导出器把 `<`、`>`、`&` 和 **ASCII 双引号**写成 `&lt;` `&gt;` `&amp;` `&quot;`。其中 `&quot;` 不在 `xml.sax.saxutils.unescape` 的默认范围内，必须用 `html.unescape`（这一条曾让 241 个片段误报）。
2. **链接按「文本（URL）」转写**；列表符号 `- ` / `1. ` 在正文里是「•」/「1.」；Markdown 分隔线 `---` 与表格分隔行 `| --- |` 有意丢弃、不参与比对。
3. 折行的续行已并入同一条目，比对按「片段是否为正文子串」进行。

最近一次结果：

| 交付稿 | Markdown 内容片段 | 未命中 | 字面 `**` / 反引号残留 |
| --- | --- | --- | --- |
| 实验报告 | 698 | 0 | 0 / 0 |
| 技术报告 | 1828 | 0 | 0 / 0 |

## 6. 重新生成

Markdown 源变更后（例如重跑 `python tools/make_report.py`）：

1. `univer_status` 确认 `.univer` 与工作树状态（`ready` 需先 `reopen`）；
2. 清空 Doc 单元 → 跑 Markdown→Doc 转换 → 跑样式补丁（标题直接格式 + 单元格边框 + 表头底色）；
3. `univer_inspect` 读回结构校验 → `univer_export` 覆盖同名 `.docx` → 跑第 4 节的保真校验；
4. `univer_worktree` 置回 `ready`。

注意事项：

- `.docx` 是 `.md` 的派生品，**改 Markdown 不会自动同步**，需按上述步骤重导；
- 转换脚本与校验脚本位于本地 `_tmp/`（内含本机绝对路径，按匿名化要求不入库）；其完整口径已写在第 2、4 节，可按此复现。
