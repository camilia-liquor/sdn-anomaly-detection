# AI+学科交叉：评分对标与差距清单

> 依据：赛道页 <https://www.aicomp.cn/tracks/tracks-2/3806.html>（AI+学科交叉，评分规则与技术方案大纲）。
> 对照对象：`参赛作品申报书_AI学科交叉(3).docx`（现有申报书）与本工作区的实测产物。
> **本文只做对标与差距，不修改申报书里的任何团队信息。**

## 1. 评分规则逐项对标（满分 100）

| 评分项 | 分值 | 规则要什么 | 现有申报书 | 本工作区可直接支撑的证据 | 差距 |
|---|---|---|---|---|---|
| 创新性 | 20 | 学科问题解决新方法 / 教学科研新模式 / 应用新场景，且**AI 与学科特色深度适配** | 已有三条（时空双视角建模、虚拟仿真替代真实攻防、检测—阻断闭环） | 泄漏感知评估协议、跨域迁移的系统性证伪（卷积无增益）、开集拒识 | 创新点的**证据强度**不足：现有表述依赖高精度数字 |
| 需求分析 | 15 | 明确学科专业与场景，**痛点分析有调研数据或案例支撑** | 有一节痛点梳理，但产业数据留了"请团队核实" | `results/real_datasets.md`（真实数据集可得性与质量）、安全运营侧调研引用（SANS 2025） | 缺**权威调研数据**与教学侧调研（问卷/访谈） |

| 总结与展望 | 5 | 总结准确、展望前瞻 | 有 | 诚实边界清单（`docs/06` §4、`docs/07`） | 基本达标 |

## 2. 关键风险：申报书里的精度数字与实测不符

| 申报书声明 | 本工作区实测 | 差异原因 |
|---|---|---|
| InSDN 准确率/精确率/召回率/F1 **均 99.98%** | 同文件内随机切分同样能到 **0.9998**；但 inSDN **46% 行是精确重复**、标签只有 2 个连续块（正常 68,423 行 + 攻击 275,465 行），`train_test_split(shuffle=True)` 会让训练与测试共享近重复行 | **数据泄漏**。`CBDNN_core(1).py:113` 用的正是 shuffle 随机切分 |
| 跨数据集：CIC-IDS2017 **99.96%**、CIC-DDoS2019 99.86%、KDD Cup 99 99.27% | 本项目实测同一模型**零样本**迁移到真实数据、1% 误报预算下召回仅 **0.034~0.038**（CIC-IDS2017 跨天）；即使同域无泄漏切分也只有 **0.384（kNN）/ 0.034（深度）** | 若每个数据集各自训练+随机切分，那是**同域内插值**，不能表述为"泛化/迁移"。99.9x% 与真实跨域能力矛盾 |
| 自建 SDN 数据集 **99.98%**（21 维流表特征） | 本项目控制器原生字段口径（17 维，`sdn_ctrl`）宏 F1 **0.8441 / 0.8816** | 自建小数据集样本同源、场景单一，99.98% 不可外推 |

**为什么必须处理**：评分规则对应用效果明确写了"**数据真实有效**"，
且第 8 条要求"涉及教学数据、科研成果的需提供合法授权说明"。
评委只要问一句"inSDN 有多少重复行、你怎么切的"，现有数字就会当场失守。

**建议表述方式**（既不否定已发表论文，又能站住）：

- 论文口径与证据口径**分开写**：论文报告的是 InSDN 同域内插值下的结果；本作品新增的是
  **无泄漏协议下的真实评测**（去重 + 时间/身份切分 + 阈值只看拟合段）；
- 把"99.98%"改写成"在 InSDN 原始发布划分下的同域结果（含该数据集固有的高重复率）"，
  并**并列给出**去重后、无泄漏口径的数字；
- 跨数据集改用本项目已实测的诚实口径：**1% 误报预算下的召回 + TPR@FPR=1% + 实际误报率**，
  并说明"跨域直接上线不可行，必须目标域标定"（`docs/07` 的门槛）。

## 3. 与现有技术方案不一致、必须统一的地方

| 项 | 申报书 | 本工作区 | 处理建议 |
|---|---|---|---|
| 特征维度 | 自建集 21 维、InSDN 77 维 | `insdn` schema 84 列→建模 71 维；`sdn` schema 控制器原生 17 维 | 统一写成"公开集 77 列中模型使用 71 维（去掉 6 个生成器未建模的 bulk-rate 列）；控制器原生 17 维" |
| 运行平台 | Mininet + RYU（Linux） | Ryu 真机联调 + **Windows 原生 OF1.3 编码器**（`tools/ryu_live_check.py`） | 作为**增强**写：既支持标准 Mininet/RYU，也支持无 Linux 环境下的等价联调 |
| 数据集 | 4 个公开集 + 自建 | 6 份真实数据集 + 合成生成器（含来源/许可/sha256 清单） | 用 `results/real_datasets.md` 替换，并写明每份**能/不能**支撑哪种评测 |
| 评估指标 | 准确率/F1（同域随机切分） | TPR@FPR=1%、实测误报率、片段召回、检测时延、误报/小时 | 以**运维口径**为主，同域精度降为辅助 |

## 4. 按大纲 8 节的完成度与待补

| 大纲节 | 完成度 | 待补 |
|---|---|---|
| （一）项目概述 | 90% | 补"本作品与已发表论文的关系"一句，避免被当成重复投稿 |
| （二）需求分析 | 60% | 权威调研数据（人才缺口/误报之痛）+ 教学侧调研（本校课程现状） |
| （三）解决方案设计 | 80% | 架构图（三层）；与工作区技术栈统一（§3） |
| （四）方案可行性 | 85% | 经济可行性可补具体工时/电费口径 |
| （五）项目实施 | 50% | **团队信息据实填写**；四阶段补日期与里程碑验收标准 |
| （六）应用效果 | **40%（最高优先级）** | 用无泄漏口径重写数字；补**教学试点方案与数据**（哪怕一个班的小规模） |
| （七）总结与展望 | 80% | 补"不足"（跨域仍需目标域标定、三份异构数据集未覆盖） |
| （八）附录 | 70% | 关键代码（可放 `CBDNN_core` 的无泄漏版本）、复现命令、参考文献、佐证材料 |

## 5. 建议的完善顺序（按"分值 × 可行性"）

1. **应用效果（20 分）**：把 5 个精度数字换成"论文口径 + 无泄漏口径"双栏表，并补教学试点设计；
2. **项目实施（20 分）**：填团队信息、给四阶段加日期与验收标准（工作区的验收自检可直接作为验收标准）；
3. **需求分析（15 分）**：补权威调研数据与本校课程/实训现状；
4. **创新性（20 分）**：给每个创新点配一条**本工作区已有的实测证据**（如"卷积无增益"的困难基准证伪、
   Ryu 真机 16/16、跨域预算守不住的实测），把"声称"变成"可验证"；
5. 统一技术栈表述、补架构图与附录。

## 更新：教学试点路径已取消（按用户决定）

原文档把「教学试点数据」列为补齐「应用效果」20 分的主要手段。**已取消该路径**，
理由：无真实数据支撑的试点材料无法通过核验，性质上属于虚构证据。

**替代方案（全部基于已存在的可复现产物）**：按评分规则原文"有充分的效果验证依据
（**教学试点数据、科研效率证明等**）"中的"**科研效率证明等**"作答——

1. **科研效率证明**：一条命令复现全流程；交付验收自检 130 项通过 / 0 失败；
   6 份公开数据集（约 3.5 GB）的来源/许可/校验值自动登记；无泄漏评测协议内置，单次评测约 40 秒。
2. **自我证伪效率**：困难基准复现"卷积无增益"、跨域排查出"排序反转"、时间戳可信度自动判定 —— 
   这类结论若靠人工复核需数天，本作品由平台自动完成并留痕。
3. **与传统方式的量化对比**：评测口径（同域随机切分 → 无泄漏口径 + 实际误报率 + TPR@FPR=1%）、
   运维代价（"次/小时" → 告警/天与人工工时/天）、实验方式（破坏性真实演练 → 虚拟仿真零硬件）。
4. **外部可核验**：开源仓库 + RYU 真机 16/16 验证产物 + 公开数据集清单，第三方可按命令逐项复核。

详见 `competition/应用效果_科研效率与可复现性证据.md`。
