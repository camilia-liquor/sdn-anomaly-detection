# 真实数据上线：标定门槛与处置流程

> 本文把实测结论翻译成**可执行的门槛与流程**。每条规则的括号里都标了它的实测依据；
> 依据来自 `results/real_eval.json`、`results/real_eval.md`、`results/real_dataset*.md` 与 `docs/06`。
> 原则：**达不到门槛就不许自动阻断**，只能告警 + 进观察池。

## 0. 一句话

在真实数据上，**"合成域模型 + 合成域阈值"不能直接上线**（跨天口径 TPR@FPR=1% 仅 0.03~0.05）；
必须先在目标域做标定，并且把**实际误报率**当作一等指标持续监控——实测出现过"按 1% 预算定的阈值在评估段跑到 4.7%~5.5%"的情况。

## 1. 上线前：目标域标定（必须有，且必须安静时段）

| 步骤 | 做法 | 门槛 / 拒绝条件 |
|---|---|---|
| S1 采集口径核对 | 确认特征列与模型输入一致（本工程 71 维）；列名体系不同的数据集（UNSW-NB15 / TON_IoT / CIC-IoT2023，映射 0/71）**不得**沿用现有权重 | 映射覆盖率 < 100% → 拒绝，改用该域自训模型 |
| S2 安静时段采样 | 取一段**已知无攻击**的正常流量（建议 ≥ 10 分钟或 ≥ 2 万条流）作为标定段 | 无法确认安静 → 拒绝自动阻断（含攻击的标定段会把阈值推向极端，实测 `results/calibration.md` 有反例：阈值被推到 1.0、召回只剩 4%） |
| S3 拟合正常画像 | 只用标定段的**正常窗口**拟合标准化器与正常画像（稳健中位数/MAD） | 标定段正常窗口 < 500 → 拒绝（阈值分位估计不稳） |
| S4 定阈值 | 阈值 = 标定段正常窗口分数的 1−预算 分位；预算默认 **1%** | — |
| S5 影子运行 | 用**不阻断**模式跑 ≥ 1 小时（或 ≥ 1 天），统计实际误报率与告警量 | 实际误报率 > 预算 × 3 → 拒绝自动阻断，回到 S2 |

**S5 为什么是硬门槛**：实测在 CIC-IDS2017 跨天口径下，按拟合段 1% 预算定的阈值，
在评估段**实际达到 4.7%~5.5%**（`docs/06` 第 4 节）——预算守不住是常态，不是异常。

## 2. 运行中：三层判定

| 层级 | 判定 | 动作 |
|---|---|---|
| 正常 | 分数 < 告警阈值 × 0.5 | 不动作；窗口仍写入环形缓冲（供事后回看） |
| **观察池** | 0.5×阈值 ≤ 分数 < 阈值 | 不告警、不阻断；**自动写入观察池**（窗口级摘要：分数、新颖性、源/目的 IP、窗口号），供抽样复核与"未知→已知"回流 |
| 告警 | 分数 ≥ 阈值且连续确认 N 个窗口 | 告警 + 按策略处置（见 §3） |
| 未知形态 | 新颖性分数越界（`unknown_threshold`，默认关闭，标定值见 `results/openset_thresholds.md`） | 标为「未知攻击」告警，**自动进待研判队列**；动作强制降级为限速（配置成 block 也会被降级） |

- 连续确认 N 的取值有实测依据：阈值 0.90 下确认 1 → 2.96 次误报/小时；确认 2 → 0.33；确认 3 → 0.00
  （`results/operating_point.md`）。
- 观察池是**零口径成本**的：它不改变任何告警/误报统计，只是把被判为正常的可疑窗口留痕，
  这样"漏报"才可回看（**已实现**：`src/service.py` 的 `Observation` 与 `self.observations`）。

## 3. 告警后：处置与留痕

1. **幂等处置**：同一源 IP 在封禁窗口内不重复下发规则（`integrations/ryu_guard.py`，含回归测试）；
2. **动作分级**：高置信 + 高危害（DDoS/DoS）→ 阻断；一般 → 限速；不确定 → 只告警；
3. **反复告警自动升级**：同一源在 `escalate_window_sec`（默认 300s）内告警达到 `escalate_after`（默认 3）次，
   建议动作自动上抬一级（observe→throttle→block）；**未知形态最高只到 throttle**（硬护栏）；
   流被重置（换段/重连）时升级计数归零，避免跨段误升级。见 `src/service.py::_escalate`；
4. **审计台账**：每条告警/每次下发都留痕，含判定分数、命中的真实标签（若可得）、是否幂等抑制、是否升级；
   台账与回流文件按 `CIDA_AUDIT_MAX_BYTES` 轮转并保留 `CIDA_AUDIT_BACKUPS` 个历史文件（**只追加不删除会写满磁盘**）；
5. **台账必须能反查**："这条告警对应真实攻击 / 是真误报"（`app/app.py` 的审计台账已支持）；
6. **写接口鉴权**：设置 `CIDA_API_TOKEN` 后，改策略与写研判结论必须带令牌（读接口开放，大屏不受影响）。

## 4. 未识别（漏报）复核：闭环已落地

判为正常的窗口原先**零留痕**，导致事后无法回答"这段为什么没报"。现已补齐：

```
观察池清单（低置信正常窗口，窗口级摘要；原始流记录尚未随条目留存）
   → 每日抽样复核（建议 20~50 条/天）
   → 人工判定：真正常 / 漏报（并标注攻击族）
   → 漏报样本回流训练集（形成「未知 → 已知」）
   → 每轮回流后重跑 §1 的标定门槛
```

对应的落地点（可直接调用）：

| 环节 | 实现 |
|---|---|
| 自动留痕 | `src/service.py`：未确认窗口若落在 `[observe_margin×阈值, 阈值)` 或形态新颖 → 进 `self.observations`；**每个**窗口另存 `self.recent` 供回看 |
| 查看 | `GET /api/observations`、`GET /api/review?status=pending` |
| 提升进研判队列 | `POST /api/review/promote`（值班员做漏报复盘时的动作） |
| 给结论并回流 | `POST /api/review`，`verdict` = `attack:<类别>` 或 `normal` → 追加写入 `results/review_feedback.jsonl` |
| 回归保护 | `tests/test_core.py`：观察池/回看缓冲/未知动作护栏/研判回流 共 3 项测试 |

**仍缺一步**：回流文件到重训之间没有定时任务，目前需人工触发重训。

**门槛**：若连续 3 天抽样复核的漏报率 > 5%，则触发**降级**：收紧告警阈值一级
（或增加连续确认窗口数），并重跑影子运行。

## 5. 降级与熔断规则

| 触发条件 | 动作 |
|---|---|
| 影子/在线实际误报率 > 预算 × 3 | 停止自动阻断，退回只告警 + 观察池 |
| 目标域标定 TPR@FPR=1% < 0.20（实测：跨天口径无监督基线 0.27、合成域迁移 0.05） | 不得开启自动阻断：0.2 以下的检出率不足以支撑自动封禁 |
| 逐类召回中任一类 < 0.5（实测 Botnet 确认时延 857 ms、最慢一类，见 `results/per_class_online.md`） | 该类单独降级为"只告警"，其余类别不受影响 |
| 特征缺失率 > 5%（实测 CIC-IDS2018 特征缺失会导致按缺失丢行只剩 0.002%） | 停止评测与上线，先修采集 |

## 6. 必须一起看的两个数（对外材料同样适用）

任何"召回/准确率"声明旁边，必须同时给出：
1. 该工作点的**实际误报率**（不是预算值）；2. **TPR@FPR=1%** 这类阈值无关的同口径指标。
只报其中一个都属于选择性报告——本工程实测里就出现过"预算召回 0.79"与"同口径 TPR@FPR1% 仅 0.087"并存的情况。
