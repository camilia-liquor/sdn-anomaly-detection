# SDN 流量异常检测：CNN + BiLSTM 混合模型（参赛工程版）

> 一个**开箱即跑、结果可复现**的 SDN 入侵/异常检测工程：自带仿真数据集生成器，
> 训练 CNN+BiLSTM 混合模型，输出多分类 + 二分类 + **在线告警级**三套指标，
> 并附带一个可现场演示的实时检测大屏。

本目录的起点是一份能跑但**不可复现、指标口径有误**的课程/论文 demo（`CNN_biLSTM2.py`）。
这里把它整理成了可以拿去参赛的完整工程：**同样的算法思路，正确地实现、正确地评估、正确地演示**。
原代码逐条问题清单见 [`docs/01_原始代码问题清单.md`](docs/01_原始代码问题清单.md)。

## 1. 亮点（答辩可以直接讲这五条）

| # | 亮点 | 说明 |
|---|------|------|
| 1 | **自带数据生成器，不依赖外部数据集** | 按攻击机理建模（速率、时长、标志位、到达间隔……）生成 8 类 SDN 流量；输出格式与公开数据集 inSDN/CICFlowMeter **列名逐字一致**，也与本仓库 Ryu 采集脚本**完全一致** → 赛后可直接换成真实采集数据 |
| 2 | **真正的时序建模** | 原 demo 把 1280 维特征硬切 10 个"假时间步"喂 LSTM；本工程用**滑动窗口 (T,F)**，CNN 沿时间轴提局部模式、BiLSTM 沿时间轴双向建模，才有资格叫"时序异常检测" |
| 3 | **多任务双头 + 注意力** | 多分类头（认攻击类型）+ 二分类头（判正常/异常）联合训练；Softmax 时间维注意力池化既提精度又给可解释热力图 |
| 4 | **指标体系对齐真实部署** | 除常规指标外，报告**检测时延（均值/P95）**、**误报率（次/小时）**、**攻击片段召回率**——评委最关心的"能不能用" |
| 5 | **难度可调、结论稳健** | 生成器内置"隐蔽攻击片段 / 类别重叠 / 标注噪声"旋钮，避免"自己造的数据当然 100%"；支持 `--seeds 0,1,2` 多种子重复实验，报告**均值±标准差**，说明结论不是碰运气 |

```bash

python tools/make_report.py
```

## 3. 结果速览

完整结果见 [`results/汇总报告.md`](results/汇总报告.md) 与自动生成的 [`docs/02_实验报告.md`](docs/02_实验报告.md)，
图表在 `results/figures/`。以下为**本机实跑**（Windows / Python 3.11 / TensorFlow 2.15 CPU，全程约 15 分钟）的数字。

### 3.1 主实验（86,037 条仿真流记录 → 14,062 个时间窗；窗口 T=16；3 个随机种子取均值±标准差）

| 指标 | 数值 |
|------|------|
| 多分类准确率 | **0.9959 ± 0.0007** |
| **多分类宏平均 F1** | **0.9940 ± 0.0011** |
| 多分类 Kappa / Top-2 准确率 | 0.9900 / 0.9991（seed 0） |
| 宏平均 AUC（OvR） | 0.99999（seed 0） |
| **二分类 F1** | **0.9918 ± 0.0013** |
| **二分类 ROC-AUC** | **0.9999 ± 0.0000** |
| PR-AUC / MCC | 0.9999 / 0.9870（seed 0） |
| **TPR@FPR=1%** | **1.0000**；TPR@FPR=0.1% = 0.9921（seed 0） |
| **在线攻击片段召回** | **100%（24/24）** |
| **平均检测时延** | **9.9 ms**（P95 = 37.0 ms） |
| **误报率** | **9.55 ± 3.43 次/小时** |
| 模型参数量 / 单轮训练耗时 | 151,434 / 约 1 秒（CPU） |

> 测试流长度 21,478 条流记录（约 3 小时），时序切分，测试集只在最终评估用一次。
> 逐类 F1：Botnet 1.000、DDoS 1.000、U2R 1.000、Normal 0.997、WebAttack 0.997、DoS 0.991、Probe 0.988、BruteForce 0.971。

### 3.2 消融实验与传统基线（宏 F1，3 种子均值）

| 实验组 | 宏 F1 | 参数量 | 结论 |
|--------|-------|--------|------|
| **CNN+BiLSTM 双分支（本文主模型）** | **0.9940 ± 0.0011** | 151k | 本文方案 |
| 去掉 CNN 分支（仅 BiLSTM） | 0.9966 ± 0.0003 | 96k | 与主模型持平（差异小于种子波动） |
| 去掉卷积与循环（纯 MLP） | 0.9795 ± 0.0033 | 172k | ↓1.5 个百分点 |
| 去掉 BiLSTM 分支（仅 CNN） | 0.9727 ± 0.0048 | 65k | **↓2.1 个百分点，时序分支是主力** |
| 逻辑回归 | 0.9739 | 9k | 传统基线中最强 |
| 随机森林 / 极端随机树 | 0.8767 / 0.8343 | 255k / 737k（树节点数） | 高维展平后明显劣于时序模型 |

**如实说明**：双分支混合模型与单独 BiLSTM 分支的差异小于随机种子波动，
即**时序分支是主要贡献者**；概率集成（7 个模型取平均）宏 F1 为 0.9964，同样只是与单分支持平。
但**窗口长度消融（见 3.3）给出了有价值的机理解释**：卷积分支的差距随窗口变长**单调收敛**，
说明它需要更长的上下文才能发挥作用 —— 我们把这条负面结论转化成了可验证的机理解释。

### 3.3 窗口长度消融（本轮新增，直接给出部署建议）

窗口长度 T 是本工程**最重要的超参数**——它同时决定精度与误报率（同一份数据、同一步长、25 epoch）：

| T | 混合模型宏 F1 | 仅 CNN 分支 | 仅 BiLSTM 分支 | 混合 − 最好单分支 | 误报（次/小时） |
|---|---|---|---|---|---|
| 10 | 0.9772 | 0.9415 | 0.9886 | −0.0114 | 28.31 |
| 16 | 0.9940 | 0.9670 | 0.9973 | −0.0033 | 9.22 |
| 24 | **0.9970** | 0.9813 | 0.9977 | **−0.0007** | **3.29** |

**三条可写进答辩的结论**：

1. **窗口越长越准**：宏 F1 从 0.9772（T=10）提升到 0.9970（T=24）；
2. **误报率随窗口长度断崖式下降**：28.31 → 3.29 次/小时（**降低 88%**）——
   这是部署侧最有价值的发现（多给模型一点上下文，运维少受 8 倍打扰）；
3. **CNN 分支的增益随窗口变长单调收敛**（−0.0114 → −0.0033 → −0.0007）：
   在 T=24 时混合模型与单分支的差距已小于随机种子波动，
   **印证了"卷积分支的价值需要更长窗口才能体现"这一假设**。
   这也把原先"CNN 分支没增益"的负面结论，变成了**有数据支撑的机理解释**。

> 代价与权衡：窗口越长，检测时延越大（T=24 意味着要等 24 条流记录才能出一次结论）。
> 部署时按业务的时延容忍度选择，并在报告中如实给出这条权衡曲线。
> **稳健性核对**：T=24 会出现窗口重叠（相邻窗口共享 19/24 条记录），
> 因此额外做了"决策步长加倍"的对照（T=24、step=12）：宏 F1 **0.9975**、误报 5.27 次/小时，**结论不变**。

### 3.4 分布漂移鲁棒性（`drift_strength=0.35`，模拟攻击工具换代/带宽变化）

| 模型 | 宏 F1（同分布） | 宏 F1（漂移集） | 退化 |
|------|-----------------|-----------------|------|
| **CNN+BiLSTM（主模型，3 种子）** | 0.9930 / 0.9956 / 0.9934 | 0.9934 / 0.9940 / 0.9918 | **−0.16% ~ +0.04%（基本不变）** |
| 仅 BiLSTM | 0.9964 | 0.9956 | −0.08% |
| 仅 CNN | 0.9670 | 0.9696 | +0.26% |
| 逻辑回归 | 0.9739 | 0.9739 | 0.00% |
| 随机森林 | 0.8767 | 0.7996 | **−7.7%** |
| 极端随机树 | 0.8343 | 0.7961 | **−3.8%** |

**在 T=16 的窗口下，时序深度模型对分布漂移几乎免疫（退化 ≤0.2%）**，而树模型仍退化 3.8%~7.7%。
这是"窗口化时序建模"最实用的价值：换个网络环境、换个攻击工具，模型不会突然失灵。

### 3.5 真实公开数据集验证（inSDN 衍生集，含诚实结论）

为避免"自己造的数据当然准"的质疑，我们另用一份**真实公开的 inSDN 数据集**做了独立验证：
343,889 条真实流记录 → 清洗去重后 **184,747 条**（删除 35% 完全重复行）× 65 维特征。

| 切分口径 | 多分类准确率 | 二分类 ROC-AUC | 误报（次/小时） |
|---|---|---|---|
| 分层随机切分 | 0.9998 | 1.0000 | — |
| **按会话分组切分**（同一 Flow ID 不跨子集） | **1.0000** | 1.0000 | 0.00 |
| 分组 + 近似重复去重（最严口径） | 0.9976 | 0.9996 | 0.51 |

**但我们必须把这个高分的真实原因说清楚**（这也是本工程方法学的一部分）：

| 诊断项 | 结果 |
|---|---|
| 测试样本到训练集的最近邻距离中位数（标准化空间） | 0.0004 |
| **距离 < 0.01（几乎完全相同）的测试样本占比** | **84.95%** |
| **1-最近邻分类器（纯记忆式基线）准确率** | **0.9985** |
| 单特征 + 单阈值（决策树桩）准确率 | 0.8051（最好单特征 0.8583） |

结论：该公开数据集**既冗余又高度可分**，接近满分的成绩主要反映数据本身，**不能用来区分模型优劣**。
因此我们**以自研的高难度仿真数据集作为主要评估基准**（随机森林仅 0.878、主模型 0.985），
并把公开数据集的结果定位为"验证流水线在真实数据上端到端可用"。
我们把这套诊断工具（切分口径对照 + 最近邻泄漏诊断 + 单特征基线）也留在了工程里，方便复用到其他数据集。

### 3.6 一句话总结

> 在完全可复现的仿真 SDN 流量上，CNN+BiLSTM 双分支模型取得 **宏 F1 0.9940、AUC 0.9999、
> 攻击片段召回 100%、平均检测时延 9.9 ms、误报 9.6 次/小时**；
> 消融实验表明**时序建模是性能来源**（去掉 BiLSTM 分支掉 2.1 个百分点），
> 窗口消融给出了**可直接用于部署的结论**（窗口加长能把误报再降 88%），
> 漂移实验表明它对环境变化比树模型稳健得多（退化 ≤0.2% vs 3.8%~7.7%）。

## 5. 数据：为什么可以自己生成，以及怎么换成真实数据

### 5.1 两种输出格式（都经过列名核对）

| schema | 列数 | 与谁对齐 | 用途 |
|--------|------|----------|------|
| `insdn`（默认） | 84 列 | 公开数据集 **inSDN / CIC-IDS2017**（CICFlowMeter 输出）列名逐字一致 | 与原始 demo 期望的格式对齐；方便横向对比公开数据集结果 |
| `sdn` | 22 列（+1 列多分类标注） | 本仓库 `collect_normal_traffic.py` / `collect_ddos_traffic.py`（Ryu 控制器采集 OpenFlow 流表统计）的输出 | 与自己的 SDN 实验床无缝衔接 |

```bash
python run_all.py --set schema=sdn        # 换成 Ryu 采集脚本同款 22 列格式
```

### 5.2 8 类流量（与 inSDN 类别体系对齐）

| 类别 | 机理建模要点（为什么模型能学到） |
|------|----------------------------------|
| Normal | HTTP / 大文件传输 / DNS / ICMP / UDP 流的混合，量级跨度大 |
| DDoS | 多源、**超高包速率（可达 1e4 pkt/s）**、极短持续、几乎无反向包 |
| DoS | 单源、速率中等、**持续时间长**；Slowloris 甚至几百秒的极低速率长连接 |
| Probe | 端口扫描：单流 1~3 个包、时长毫秒级、SYN/RST 标志、目标端口随机 |
| BruteForce | SSH/FTP 反复认证：等间隔小包往返、连接数中等 |
| WebAttack | HTTP 注入载荷：前向包偏大、PSH 比例高 |
| Botnet | C2 心跳：**到达间隔极其规律**（正则化系数极低）、速率极低、连接超长 |
| U2R | 极少见：载荷异常、标志位组合异常（URG/ECE/CWE 同时出现） |

生成器是**先生成物理事实、再渲染成数据集列**的：包数、字节数、时长、活跃/空闲时间、
标志位计数、到达间隔统计之间互相自洽（例如 `Flow Packets/s = 总包数 / 时长`、
`Packet Length Mean = 总字节 / 总包数`），不会出现"随机撒点导致的物理上不可能的样本"。

同时内置了**可控的难度旋钮**，保证指标不是虚高：

| 配置项 | 含义 |
|--------|------|
| `overlap_ratio` | 每类中与"最易混淆类"做几何混合的困难样本比例（默认 15%） |
| `label_noise` | 标注噪声比例（默认 1%） |
| `feature_noise` | 量测噪声强度（默认 5%） |
| `drift_strength` | 额外生成一个**分布漂移测试集**（鲁棒性实验） |

### 5.3 换成真实数据集（零改代码）

```bash
# 方式一：直接指向 inSDN / CIC-IDS2017 的 CSV 目录（自动合并该目录下所有 csv）
python run_all.py --source real --real-data-dir D:\datasets\inSDN

# 方式二：把 Mininet+Ryu 现场采集的 Normal.csv / Attacks.csv 放进目录
```

## 6. 方法

### 6.1 网络结构

```
输入 (T, F)：T 条连续流记录 × F 维流特征（默认 T=10）
  │
  ├─ CNN 分支：Conv1D(64,k=3,膨胀率1) → BN → ReLU → Conv1D(128,k=3,膨胀率2) → BN → ReLU
  │            作用：沿时间轴提取"相邻若干条流"的局部组合模式（突发 SYN、等间隔心跳）
  │            ★ 用膨胀卷积而非池化，避免把 10 个时间步压成 2 个
  │
  ├─ BiLSTM 分支：BiLSTM(64, return_sequences=True)
  │            作用：直接在原始窗口上做双向时序建模，抓整段演化趋势
  │
  ├─ 两条分支各自池化后拼接（CNN 分支全局最大池化 + 时序分支注意力池化）
  │            ★ 并行双分支，比"CNN 输出再喂 LSTM"的串行做法更稳（见 docs/02 消融讨论）
  │
  └─ 双头输出
       ├─ 多分类头 softmax(8)：认得出是哪种攻击
       └─ 二分类头 sigmoid(1)：直接回答"正常 / 异常"
     损失 = CE(多分类) + 0.3 × BCE(二分类)   ← 多任务联合训练
```

### 6.2 数据切分（这里最容易翻车，也最能体现工程严谨性）

```
时间轴 ──────────────────────────────────────────────────────────────▶
        │  训练集 60%  │purge│ 验证集 15% │purge│   测试集 25%   │
        └──────────────┘     └────────────┘     └───────────────┘
   * 严格按时间顺序切分（网络流是时序数据，随机切分 = 数据泄漏）
   * 边界留 purge 间隙，滑窗不跨集
   * StandardScaler 只在训练集 fit，再 transform 验证/测试集
   * 验证集用于早停与调参，测试集只在最终评估时用一次
```

### 6.3 评估体系（三套指标一起看）

1. **多分类**：accuracy、macro/weighted P-R-F1、逐类明细、混淆矩阵、Kappa、Top-2、macro AUC(OvR)
2. **二分类异常检测**：ROC-AUC、PR-AUC、MCC、最优阈值下的 F1、**TPR@FPR=1%/0.1%**（安全场景最常用的工作点）
3. **在线告警级**：在连续测试流上滚动取窗，统计
   - **检测时延**：攻击开始 → 第一条告警（均值 / 中位数 / P95，秒）
   - **误报率**：次/小时（工程上看这个，比 FPR 比例更直观）
   - **攻击片段召回率**：有多少个攻击片段被报出来、漏报几个

## 8. 可视化演示大屏

```bash
python app/app.py                 # http://127.0.0.1:5000

```

界面功能（现场答辩用）：

- **实时检测曲线**：异常概率随时间变化，叠加"真实攻击区间"与"告警区间"，一眼看出漏报/误报
- **当前窗口判定**：大号风险值 + 8 类概率条，实时展示模型"在想什么"
- **一键注入攻击**：点一下就跳到测试流里真实的攻击片段起点，看模型多快报警
- **流量流水表**：逐条流记录展示关键特征 + 真实标签 + 模型判定（人工可对照）
- **告警日志**：记录每一次告警的时刻、判定类别、概率、是否误报
- **实验指标与图表**：直接读取 `results/` 下的指标与图片，可点击放大

三个工程上的取舍（都可讲）：

1. **演示不依赖 TensorFlow**：推理在实验阶段就缓存成"窗口级预测"，演示服务只做回放，
   因此在评委电脑上没装 TF 也能跑；断网也能跑（前端零 CDN，图表全部原生 canvas 绘制）。
2. **回放的是留出测试集**：不是编好的动画，预测结果与 `results/metrics_*.json` 同源，**演示与论文数字一致**。
3. **"注入攻击"是诚实的**：只是把播放位置跳到真实攻击片段起点，检测时延由模型自己决定。

## 9. 与原 demo 的差异（摘要）

| 维度 | 原 demo | 本工程 |
|------|---------|--------|
| 数据来源 | 硬编码别人机器上的路径 | 自带生成器 / 一键切换真实数据集 |
| 特征选择 | `data[:, 0:77]` 硬编码（还混入了行号列、漏掉了一个特征） | 按列名自动识别 |
| 标准化 | 全量数据 fit（泄漏） | 只在训练集 fit |
| 切分 | 随机切分 + 测试集当验证集（泄漏） | 时序切分 + purge 间隙 + 独立验证集 |
| 损失 | 二分类损失训多分类 one-hot | 多分类 CE + 二分类 BCE 双头 |
| 早停/学习率 | 监控训练损失；min_lr > 初始 lr（永不衰减） | 监控 val_loss + restore_best + 正确的 lr 调度 |
| 时序建模 | 硬切假时间步 | 真实滑动窗口 (T,F) |
| AUC 计算 | 硬标签算 AUC（口径错误） | 概率矩阵 + OvR 宏平均 |
| 类别不平衡 | 不处理 | 逆频类别加权 |
| 可复现 | 无种子、不保存 scaler/编码器 | 全固定 + 全部落盘 |
| 评估维度 | 离线静态指标 | 多分类 + 二分类 + 在线告警级 |
| 演示 | 无 | 实时检测大屏 |

## 10. 常见问题

**Q：一定要装 TensorFlow 吗？**
训练与推理需要；但 `tools/smoke_test.py`（数据链路自检）和演示大屏（读缓存预测）都不需要。

**Q：没有 GPU，训练要多久？**
默认配置（约 6~7 万条流记录、T=10 窗口、约 4 万训练窗口、40 epoch，含早停）
在 8 核 CPU 上大约几十分钟。想更快就 `--smoke` 或 `--set scale=0.4`。

**Q：图里的中文变成方块？**
`src/utils.py` 会自动查找 微软雅黑/黑体/苹方/文泉驿 等字体；都没有时会自动**回退成英文标注**，
不会报错。也可以手动把任意 `.ttf` 放进系统字体目录后重跑。

**Q：Windows 控制台中文乱码？**
`src/utils.py` 会把 stdout 切到 UTF-8；若仍乱码，运行前执行 `chcp 65001`。

**Q：想换个数据规模？**
`--set scale=0.5`（数据量）、`--set window_size=16`（窗口）、`--epochs 60`（轮数）。

**Q：想复现某个结果？**
配置里固定了 `seed`，并写入 `artifacts/<tag>/config_used.json`；使用同一份配置 + 同一版本依赖即可复现。
