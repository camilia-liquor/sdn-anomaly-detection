## English summary

A reproducible, open-source **SDN intrusion/anomaly detection** project (Apache-2.0).

- **Self-contained data generator** — synthesises 8 classes of SDN flow traffic with
  inSDN / CICFlowMeter-compatible columns (84-col and 22-col schemas), physical-quantity
  consistency and difficulty knobs (class overlap, stealthy attacks, label noise).
- **CNN + BiLSTM dual-branch model** (sliding window `(T, F)`, multi-task heads for
  multi-class + binary, temporal attention), with ablations, multi-seed statistics,
  drift robustness and error analysis.
- **Deployment-oriented**: online alarm-level metrics (detection delay, false alarms per hour,
  attack-segment recall) and an **operating-point selector** that trades false alarms against
  latency — false alarms can be cut from 8.56 to **0.66 per hour** while keeping **100%**
  segment recall. In operations terms: **~36 alerts/day, ~3.6 analyst-hours/day**, mean
  detection delay **18 ms**.
- **Actually a system, not a notebook**: an online detection service (`POST /api/detect` with
  sliding buffer, threshold + N-of-M confirmation, throttling/blocking policy, whitelist,
  dry-run, JSONL audit trail, Prometheus `/metrics`), a **Ryu controller adapter**, and a
  no-Ryu controller simulator that measured **1,364–1,918 flows/s** end-to-end.
- **Reproducible**: one command (`python run_all.py`), **50-item acceptance self-check**,
  10 unit tests, offline demo dashboard, no GPU required (~0.02 ms per window batched).

Quick start: `pip install -r requirements.txt && python run_all.py --smoke` (≈25 s),
then `python app/app.py` for the live dashboard. See sections below for details.

### 3.2 方法原理：CNN 与 BiLSTM 各是什么、为什么要并行结合

判定单元是 **T=16 条时间连续的流**堆成的 `(T, F)` 张量——单条流看不出攻击形态，
因为攻击的"形状"分布在**相邻若干条流**上（连续短连接、固定间隔探测、突发洪泛）。
这同时要求两种能力，而它们对应两类**归纳偏置互补**的网络结构，所以本工程用并行两路：

**① CNN：抓"局部形状"**

- **是什么**：局部连接 + 权值共享的前馈网络，一维卷积在时间轴上滑动一个长度为 k 的核：
  `h_t = φ(Σ_τ w_τ·x_{t+τ} + b)`（φ = ReLU）。
- **为什么适合流量**：㈠ **局部性**——扫描/暴破/洪泛都有可辨识的局部形状；
  ㈡ **参数共享 → 平移不变**，攻击出现在窗口开头、中间还是结尾都能认出来（全连接层要为每个位置单独学权重）；
  ㈢ **参数效率**——本分支只 6.5 万参数，比同宽度全连接小一个数量级。
- **两个非默认选择**：**不做池化、改用膨胀卷积**（d=1/2/4），因为池化会把时间步压没、时序信息永久损失；
  三层叠加感受野覆盖 15 步，等于在不缩短序列的前提下看到整个窗口。聚合用 GlobalMaxPooling
  （"这段窗口里最强的局部响应是什么"，与"攻击只要出现过就该被抓住"的语义一致）。

**② BiLSTM：抓"长程依赖 + 双向上下文"**

- **为什么不能只用朴素 RNN**：`h_t = φ(W x_t + U h_{t-1})` 反传时梯度连乘 `U^T`，小于 1 指数衰减、大于 1 爆炸，
  **学不到长依赖**；而"某条流是不是攻击"常常取决于它前面十几条流的累积状态。
- **LSTM 的解法**：加一条**记忆单元** `c_t` 与三个 Sigmoid 软开关（遗忘门 `f_t`、输入门 `i_t`、输出门 `o_t`）：
  `c_t = f_t ⊙ c_{t-1} + i_t ⊙ c̃_t`，`h_t = o_t ⊙ tanh(c_t)`。
  关键在于**加法通路**让梯度近乎无损回传 → 网络自己学会"哪些状态长期记住、哪些马上忘掉"。
- **BiLSTM**：正反各跑一遍并拼接 `h_t = [h→_t ; h←_t]`，每个位置同时看到左右上下文。
- ⚠️ **双向算不算"用了未来"？** 不算：判定单元是**已经完整到达的窗口**，窗口之外的真正未来从未参与。
  代价是检测时延天然等于一个窗口（实测平均 18.4 ms、最快 Probe 5.5 ms），这条权衡写进了工作点选择让用户自己选。

**③ 为什么"并行"而不是"串行"**：串行（CNN → 池化 → LSTM）会让 LSTM 拿到**已经被压缩过**的序列，
本工程实测串行版本**低于任一单分支**；并行则两路都看未被破坏的原始 `(T,F)`，各自注意力池化后拼接，
由网络自己决定信任哪一路。**如实交代**：并行融合在本数据集上**没有正增益**（结构消融持平、
困难基准 6/6 配对为负、外部对标里单一 LSTM 略高），三个独立实验互相印证；
它的价值是相对纯 CNN 的压倒性优势（+0.026 宏 F1、误报 13.60→0.55 次/小时）与作为统一骨架。

**④ 注意力池化 + 多任务双头**：`α_t = softmax(tanh(W_a h_t))`、`z = Σ_t α_t h_t`
——既聚合又不丢"哪几步关键"，且 `α` 能直接出图给运维看（大屏的注意力热力图就是它）。
主干之上接两个头：多分类头（8 类，稀疏交叉熵 + 类别逆频权重）与二分类头（是否攻击，权重 0.3）；
**告警阈值挂在二分类头、类别名由多分类头给**，两者解耦后阈值标定更稳，实测二分类 ROC-AUC **0.9999**。

### 3.3 消融实验与传统基线（宏 F1，3 种子均值）

| 实验组 | 宏 F1 | 参数量 | 结论 |
|--------|-------|--------|------|
| **CNN+BiLSTM 双分支（本文主模型）** | **0.9940 ± 0.0011** | 151k | 本文方案 |
| 去掉 CNN 分支（仅 BiLSTM） | 0.9966 ± 0.0003 | 96k | 与主模型持平（差异小于种子波动） |
| 去掉卷积与循环（纯 MLP） | 0.9795 ± 0.0033 | 172k | ↓1.5 个百分点 |
| 去掉 BiLSTM 分支（仅 CNN） | 0.9727 ± 0.0048 | 65k | **↓2.1 个百分点，时序分支是主力** |
| 逻辑回归 | 0.9739 | 9k | 传统基线中最强 |
| 随机森林 / 极端随机树 | 0.8767 / 0.8343 | 255k / 737k（树节点数） | 高维展平后明显劣于时序模型 |

**如实说明**：双分支混合模型与单独 BiLSTM 分支的差异小于随机种子波动，
即**时序分支是主要贡献者**；概率集成（7 个模型取平均）宏 F1 为 0.9964，同样只是与单分支持平。
但**窗口长度消融（见 3.4）给出了有价值的机理解释**：卷积分支的差距随窗口变长**单调收敛**，
说明它需要更长的上下文才能发挥作用 —— 我们把这条负面结论转化成了可验证的机理解释。

### 3.4 窗口长度消融：把"卷积分支有没有用"这件事测穿（`results/window_ablation.md`）

窗口长度 T 是本工程**最重要的超参数**——它同时决定精度、误报率与检测时延。
我们把消融从 T=10 一路做到 **T=48**，并且对 T=16/24/32 **补足 3 个随机种子**（同一份数据、同一步长 stride=5、25 epoch）：

| T | 种子数 | 混合模型宏 F1 | 仅 CNN 分支 | 仅 BiLSTM 分支 | **混合 − 最好单分支** | 误报（次/小时） | 平均检测时延 |
|---|---|---|---|---|---|---|---|
| 10 | 1 | 0.9772 | 0.9415 | 0.9886 | −0.0114 | 28.31 | 6.6 ms |
| 16 | **3** | 0.9938 ± 0.0012 | 0.9727 ± 0.0059 | 0.9968 ± 0.0008 | **−0.0030** | 3.29 ± 5.14 | 17.1 ms |
| 24 | **3** | 0.9974 ± 0.0011 | 0.9791 ± 0.0020 | 0.9989 ± 0.0011 | **−0.0015** | 1.10 ± 1.90 | 24.3 ms |
| 32 | **3** | 0.9979 ± 0.0024 | 0.9840 ± 0.0018 | 0.9987 ± 0.0010 | **−0.0008** | **0.11 ± 0.19** | **35.4 ms** |
| 48 | 1 | 1.0000（饱和） | 0.9912 | 1.0000（饱和） | +0.0000 | 0.00 | 42.1 ms |

**结论一（负面结论，但这次是被"测穿"的）：卷积分支在流统计量特征上没有增益。**
Δ（混合 − 最好单分支）在**每一个有置信区间的窗口长度上都是负的**（−0.0030 / −0.0015 / −0.0008），
只是随 T 变长而收敛到 0，**从未转正**；到 T=48 双方都打满 1.0000（指标天花板），Δ 归零已无意义。
所以早期那句"卷积需要更长上下文才能发挥作用"**被证伪**：它不是"还在收敛"，而是**始终停在噪声内**。
（判据：Δ 与种子标准差相比，全部不超过 1σ。）

> **我们自己抓到的假阳性（诚实记录）**：T=32 最初只跑了 1 个种子，Δ 显示 **+0.0023**，看上去像"终于转正了"。
> 补齐 3 个种子后 Δ 变成 **−0.0008**（落在 σ=0.0024 之内）——那个正值**完全来自 seed 0 是三个种子里最好的那次**。
> 这正是本工程坚持"每个配置 3 个种子报均值±标准差"的原因，也说明了**单种子 + 边缘显著不能当结论**。

**结论二（正面结论，可直接用于部署）：加长窗口是**压误报最省事**的旋钮，而且让误报变得"可预测"。**

| T | 逐种子误报/小时 | 种子间波动 |
|---|---|---|
| 16 | 9.22 / 0.66 / 0.00 | **14 倍** |
| 24 | 3.29 / 0.00 / 0.00 | 很大 |
| **32** | 0.00 / 0.33 / 0.00 | **几乎为零** |

**误报不但在下降（28.31 → 0.11 次/小时），种子间波动也从 14 倍收敛到几乎为零**——
这一点对运维比"更低"更重要：**误报率本身飘 14 倍的系统，是没法标定工作点的**。

> **一句话部署建议**：若业务能接受约 **35 ms** 的检测时延，**T=32 用约 26 ms 的额外时延换掉约 84 倍的误报**
> （9.22 → 0.11 次/小时），而且**不动阈值、不动模型、不重训**，只改输入形状；
> 若时延预算只有十几毫秒，就留在 T=16，改用阈值标定与连续确认来压误报。
> ⚠️ T≥32 起分类精度已饱和（宏 F1 打满），那里的"精度对比"衡量的是**指标天花板**而不是模型能力。
> **因此我们没有停在这里**：又造了一套**困难基准**把难度推上去重测一遍，见 **3.4**——
> 结论是卷积**依然没有翻身**，"卷积需要更长上下文"这条解释在困难基准上**趋势本身也不成立**。

> **稳健性核对**：T=24 会出现窗口重叠（相邻窗口共享 19/24 条记录），
> 因此额外做了"决策步长加倍"的对照（T=24、step=12）：宏 F1 **0.9975**、误报 5.27 次/小时，**结论不变**。
> **交叉验证**：本表的 T=16 三种子（0.9938 ± 0.0012）与主实验（0.9940 ± 0.0011，不同轮数协议）互相印证。

### 3.5 困难基准复测：把难度推上去之后，卷积终于翻身了吗？（`results/hard_ablation.md`）

3.3 的结论有一个天然反驳：「T≥32 双方都打满，**是数据太简单**，不是卷积没用」。
这个反驳很合理，所以我们**另造了一套困难基准**（数据目录、产物全部隔离，主实验一行未动），
把与"可分性"直接相关的旋钮全部拉满，再用同样的流程重测一遍：

| 旋钮 | 简单基准（主实验） | 困难基准 | 作用 |
|---|---|---|---|
| `overlap_ratio`（与最易混淆类混合） | 0.35 | **0.70** | 直接模糊类别边界 |
| `stealth_ratio`（隐蔽型攻击片段占比） | 0.45 | **0.80** | 攻击必须在窗口聚合层才看得出 |
| `stealth_mix`（隐蔽片段内伪装成正常样貌的流） | 0.45 | **0.70** | 拉低单流层面的可分性 |
| `feature_noise`（特征抖动） | 0.05 | **0.15** | 3 倍测量噪声 |
| `label_noise`（行级标注噪声） | 0.01 | 0.02 | 见下方诚实声明 |

**难度确实上去了**（用与架构无关的探针证明，避免"自己说自己难"）：把 (T,F) 展平跑逻辑回归，
窗口级宏 F1 从简单基准的 **0.9807 掉到 0.8658**；而且**没有任何结构再打满**——困难基准最高宏 F1 = **0.9891 < 1.0000**。
**饱和问题解决了，这个基准能真正区分架构。**

| T | 简单 混合 | 简单 Δ | 困难 混合 | 困难 仅 CNN | 困难 仅 BiLSTM | **困难 Δ**（混合 − 最好单分支） |
|---|---|---|---|---|---|---|
| 10 | 0.9772 | −0.0114 | 0.8869 | 0.7918 | **0.8951** | −0.0082 |
| 16 | 0.9938 ± 0.0012 | −0.0030 | 0.9401 ± 0.0045 | 0.8263 ± 0.0497 | **0.9463 ± 0.0049** | −0.0061（−1.26σ） |
| 24 | 0.9974 ± 0.0011 | −0.0015 | 0.9819 | 0.8351 | **0.9851** | −0.0032 |
| 32 | 0.9979 ± 0.0024 | −0.0008 | 0.9794 ± 0.0014 | 0.8484 ± 0.0203 | **0.9891 ± 0.0049** | −0.0097（−1.99σ） |

**结论一（负面结论，且这次是"在更难的数据上"复现的）：困难基准上卷积依然没有增益。**
Δ **在每一个 T 上都 ≤ 0**，最好单分支**每一个 T 都是「仅 BiLSTM」**；
更贴题的一层证据是**逐种子配对**：同一种子下"混合 − 最好单分支"共 **6 对，6/6 为负**（符号检验双侧 **p = 0.031**），
**没有任何一个种子下混合模型更好**。所以 T≥32 的饱和**不是**卷积翻不了身的原因。

**结论二（趋势方向改变，"卷积需要更长上下文"这条解释被推翻）：**
简单基准上 Δ 随 T **上升**（斜率 +0.00043/条窗口，从 −0.0114 收敛到 −0.0008）；
困难基准上斜率变成 **−0.00003**，且 **T 最长的那一档 Δ 反而最负**。
原假设预测"T 越长 Δ 越大"，实测方向相反。

**结论三（给出可解释的原因，而不是只报一个负数）：**困难基准上**卷积单支掉得最狠**——
T=32 仅 CNN 宏 F1 0.8484，比简单基准同档 0.9840 低 **0.1356**（T=16 低 0.1464）。
同时混合模型是"**过拟合式增益**"：T=32 混合模型训练准确率 0.9992（高于仅 BiLSTM 的 0.9970）、泛化差 +0.0060，
但**测试宏 F1 反而更低**（0.9794 vs 0.9891），参数量 151,434 vs 95,882——多出来的卷积分支把训练集拟合得更满，测试集更差。
机理：流统计量输入是把"每条流的聚合量"当时间步，卷积要找的"相邻时间步局部组合模式"在特征工程阶段已被压平；
难度一上来，它能抓到的局部模式**大多是噪声**，于是负贡献被放大。
（这与"卷积应当用在原始包序列/字节输入上"的既有结论一致——**本次设定恰恰是对卷积最有利的那一种，它依然没有翻身。**）

**难度代价表**（同一结构 `cnn_bilstm`、同一 T=16，只换数据）：

| 指标 | 简单基准 | 困难基准 | 变化 |
|---|---|---|---|
| 多分类宏 F1 | 0.9938 | 0.9401 | −0.0536（−5.4%） |
| 误分类窗口数 | 14.7 | 124.0 | +109.3 |
| 在线误报（次/小时） | 3.29 | 14.88 | +11.59 |
| 平均检测时延 | 17.08 ms | 22.97 ms | +5.88 ms |
| **攻击片段召回** | 1.0000 | **1.0000** | **0** |

> **最后一行是本节的实用结论**：难度翻倍之后**分类精度掉了 5.4 个百分点、误报涨了 4.5 倍，
> 但"有没有攻击"这件事仍然 100% 没漏**——精度指标在退化，安全底线没有退化。
> 这正是我们把"片段召回"而不是"宏 F1"写成第一指标的原因（见 3.8 / 3.10）。

> **诚实声明（我们自己调整过参数，全过程留档）**：困难档的 `label_noise` 从建议的 0.05 下调到了 **0.02**。
> 原因是在**正式训练开始之前**做冒烟诊断时发现：窗口级评估用 `pure_only` 过滤（窗口内有一条记录标签不一致就整条丢弃），
> 保留率 ≈ (1−label_noise)^T，0.05 时 **T=32 只剩 18.6% 的窗口、最小类测试 support 只有 7 条**，
> 由此产生的宏 F1 颗粒度噪声（≈0.018）**大于我们要检验的 Δ 量级（0.001~0.01）**，T=32 那一档就不能再用来回答问题。
> 调到 0.02 后 T=32 仍有 2151 条测试窗口、最小类 support 30。**调整发生在 24 次训练全部开始之前，没有任何模型结果作为依据**；
> 且难度未被放松（线性探针 0.9807 → 0.8658）。调整前后的依据与结论全部写进 `results/hard_ablation.md` 第 6 节，供读者自行判断。

> **口径提醒**：两套基准**数据内容不同**（旋钮不同）、测试窗口数也不同，
> 所以"困难宏 F1 比简单低"只说明**难度上去了**，**不能**把两边绝对精度放一起排名；
> 本节真正要检验的是**架构之间的相对关系 Δ**。
> 复现：`python tools/hard_ablation.py`（幂等；困难档训练命令见该报告第 8 节，全程 `publish_summary=false`，主实验产物零污染）。

### 3.6 分布漂移鲁棒性（`drift_strength=0.35`，模拟攻击工具换代/带宽变化）

| 模型 | 宏 F1（同分布） | 宏 F1（漂移集） | 退化 |
|------|-----------------|-----------------|------|
| **CNN+BiLSTM（主模型，3 种子）** | 0.9930 / 0.9956 / 0.9934 | 0.9934 / 0.9940 / 0.9918 | **−0.16% ~ +0.04%（基本不变）** |
| 仅 BiLSTM | 0.9964 | 0.9956 | −0.08% |
| 仅 CNN | 0.9670 | 0.9696 | +0.26% |
| 逻辑回归 | 0.9739 | 0.9739 | 0.00% |
| 随机森林 | 0.8767 | 0.7996 | **−7.7%** |
| 极端随机树 | 0.8343 | 0.7961 | **−3.8%** |

**在 T=16 的窗口下，时序深度模型对分布漂移几乎免疫（退化 ≤0.2%）**，而树模型仍退化 3.8%~7.7%。
这是"窗口化时序建模"最实用的价值：换个网络环境、换个攻击工具，模型不会突然失灵。

### 3.7 真实公开数据集验证（inSDN 衍生集，含诚实结论）

为避免"自己造的数据当然准"的质疑，我们另用一份**真实公开的 inSDN 数据集**做了独立验证：
343,889 条真实流记录 → 清洗去重后 **184,747 条**（删除 35% 完全重复行）× 65 维特征。

| 切分口径 | 多分类准确率 | 二分类 ROC-AUC | 误报（次/小时） |
|---|---|---|---|
| 分层随机切分 | 0.9998 | 1.0000 | — |
| **按会话分组切分**（同一 Flow ID 不跨子集） | **1.0000** | 1.0000 | 0.00 |
| 分组 + 近似重复去重（最严口径） | 0.9976 | 0.9996 | 0.51 |

**但我们必须把这个高分的真实原因说清楚**（这也是本工程方法学的一部分）：

| 诊断项 | 结果 |
|---|---|
| 测试样本到训练集的最近邻距离中位数（标准化空间） | 0.0004 |
| **距离 < 0.01（几乎完全相同）的测试样本占比** | **84.95%** |
| **1-最近邻分类器（纯记忆式基线）准确率** | **0.9985** |
| 单特征 + 单阈值（决策树桩）准确率 | 0.8051（最好单特征 0.8583） |

结论：该公开数据集**既冗余又高度可分**，接近满分的成绩主要反映数据本身，**不能用来区分模型优劣**。
因此我们**以自研的高难度仿真数据集作为主要评估基准**（随机森林仅 0.878、主模型 0.985），
并把公开数据集的结果定位为"验证流水线在真实数据上端到端可用"。
我们把这套诊断工具（切分口径对照 + 最近邻泄漏诊断 + 单特征基线）也留在了工程里，方便复用到其他数据集。

### 3.8 错误分析（模型错在哪里）

对 3,513 个测试窗口逐条分析（`python tools/error_analysis.py` → `results/error_analysis.md`）：

| 项目 | 结果 |
|---|---|
| 总错误 | 17 个（**错误率 0.48%**） |
| **漏报（攻击→正常）** | **0** —— 8 个类别里 7 类错误率为 0，唯一错误来自 Normal |
| 误报（正常→攻击） | 17 个（Normal 错误率 0.680%） |
| 主要混淆对 | Normal→BruteForce 9 次（52.9%）、Normal→DoS 4 次、Normal→Probe 3 次、Normal→WebAttack 1 次 |
| 置信度 | 错误样本异常概率中位数 0.844，正确样本 0.008 |
| 错例特征画像 | 错例的共同特征是**包长显著偏小**（Average Packet Size / Packet Length Mean 等比同类正确样本低约 0.4~0.5 个 z） |

**读法**：错误方向全部是"误报"而非"漏报"，对安全场景是好消息；
误报集中在"小包短连接"被误判为暴力破解/扫描——这与这两类攻击的机理（小包高频）天然重叠，
属于数据本身的模糊地带，也是下一步补样本/做特征工程的着力点。

### 3.9 检测工作点选择（误报可控，直接回应行业第一痛点）

2025 SANS 调查显示 **73% 的组织把"误报"列为威胁检测的第一大挑战**。
因此我们不做"固定阈值报一个 F1"，而是把三个旋钮放进同一框架全枚举
（`python tools/operating_point.py`，**无需重训**）：

| 阈值 | 确认窗口数 | 攻击片段召回 | 误报次数 | 误报/小时 | 平均检测时延 |
|---|---|---|---|---|---|
| 0.30 | 1 | 100% | 34 | 11.19 | 9.9 ms |
| 0.50 | 1 | 100% | 26 | 8.56 | 9.9 ms |
| 0.50 | 2 | 100% | 4 | 1.32 | 14.3 ms |
| **0.50（当前默认）** | **3** | **100%** | **2** | **0.66** | **18.1 ms** |
| 0.50 | 5 | 100% | 0 | **0.00** | 32.3 ms |
| 0.90 | 3 | 100% | 0 | **0.00** | 19.5 ms |

**结论**：**召回保持 100% 不变**，仅靠"连续确认 3 个窗口"就把误报从 8.56 降到 **0.66 次/小时（−92%）**，
代价是时延 +8 ms；要求零误报可选"阈值 0.90 + 确认 3"（19.5 ms）。
运维按自己的误报预算挑点即可 —— 这是本作品对"误报痛点"的直接回应，也是相对同类工作最实用的差异点。

### 3.11 把指标翻译成运维语言：每天多少告警、要多少人工（`results/ops_impact.md`）

评委和运维真正在意的不是 F1，而是「值班室会不会被淹没」。下表由 `python tools/ops_impact.py` 生成
（误报率按 3.04 小时在线回放的**实测**值外推到天；真实告警按**每天 20 次攻击**的业务假设折算；
单条告警按 6 分钟排查、一个班次按 8 小时）：

| 工作点 | 误报/小时 | 误报/天 | **告警/天** | 误报占比 | **人工工时/天** | 平均时延 | 漏掉攻击/天 |
|---|---|---|---|---|---|---|---|
| 阈值 0.50 + 确认 **1**（不做确认） | 8.56 | 205.4 | 225.4 | 91.1% | **22.5 h**（≈2.8 个班次） | 9.9 ms | 0 |
| 阈值 0.50 + 确认 **3**（工程默认） | 0.66 | 15.8 | 35.8 | 44.1% | **3.58 h** | 18.1 ms | 0 |
| 阈值 0.90 + 确认 **2**（预算内最优） | 0.33 | 7.9 | 27.9 | 28.3% | **2.79 h** | 16.1 ms | 0 |
| 阈值 0.90 + 确认 **3**（零误报点） | 0.00 | 0.0 | 20.0 | 0.0% | **2.00 h** | 19.5 ms | 0 |

**三条可以直接讲给评委的结论**：

1. **不做「连续确认」的系统在 1× 流量下就已经超出值班人力**（22.5 人工小时/天 ≈ 2.8 个班次），
   也就是说**误报本身就会变成事故**；加上确认（3 个窗口）后降到 3.58 小时/天，占用一个班次的 45%，
   而**攻击片段召回没有任何下降**（都保持 100%）。这个几乎零成本的机制每天省下 **19 个人工小时**。
2. **响应量级差**：从攻击出现到报警平均 **18 毫秒**（P95 71 毫秒），对比人工巡检的分钟—小时级。
3. **容量预警线（诚实给出边界）**：误报量随决策窗口数线性增长，流量放大 10× 时人工占用会从 45% 升到 222%，
   因此**规模每上一个量级都必须重新标定工作点**——我们不声称"无限流量下都够用"，
   这张表本身就是给容量规划用的预警线。

### 3.12 控制器原生字段口径：字段不够时，代价是多少？（`results/summary_sdn_ctrl.md`）

上线前最难回答的问题之一是：「你的模型用了 84 列 CICFlowMeter 特征，**真实 SDN 控制器取不到这些字段怎么办**」。
本工程把这条路也走通了：用**只有 OpenFlow 流表统计能提供的 17 列**（`packet_count`/`byte_count`/
`flow_duration_sec|nsec`/`tp_src`/`tp_dst`/`ip_proto`/`flags`/各类速率……，与仓库 Ryu 采集脚本同款字段）
重新生成数据、重新训练、重新评估：

| 口径 | 特征数 | 宏 F1 | 二分类 F1 | ROC-AUC | TPR@1%FPR | 片段召回 | 平均时延 | 误报/小时（各口径推荐点） |
|---|---|---|---|---|---|---|---|---|
| 完整流特征（`insdn`，84 列） | 71 | **0.9940** | 0.9918 | 0.9999 | 1.0000 | 100% | 18.4 ms | 0.55（阈值 0.50 + 确认 3） |
| **控制器原生字段（`sdn`，17 列）** | 17 | 0.8441 | 0.8533 | 0.9951 | 0.9151 | **100%** | 40.6 ms | 0.66（阈值 **0.99** + 确认 5） |

**这个结论比"指标更高"更有价值**，因为它量化的是一条真实的上线边界：

* 只用控制器原生字段，**攻击片段召回仍然是 100%**（该发现的都发现了），但**工作点必须大幅收紧**
  （阈值 0.50 → 0.99、确认 3 → 5），代价是**检测时延从 18 ms 涨到 41 ms**，且窗口级宏 F1 从 0.994 掉到 0.844；
* 换句话说，**字段缺口转化为"工作点代价"而不是"功能失效"** —— 这决定了没有探针的纯 SDN 环境里
  这套系统能用到什么程度、以及该优先补哪几类字段；
* 想同时拿到高精度与低时延，就必须在控制器侧补齐**双向包间隔/标志位统计**这类字段
  （完整口径相对原生口径多出的正是这些）。

两个口径都已封装进同一个服务，一条参数即可切换（`--processed-dir` + `--model-tag`），
**且服务与大屏会自动同步口径**，不会出现"页面显示的模型"和"实际判定的模型"不是同一个的事故。

### 3.14 跨域适用边界：我们主动做的一次"失败实验"（`results/cross_dataset_report.md`）

把自研数据集上训练好的模型**零样本**直接拿去推理真实 inSDN（71 维特征按语义 100% 映射成功，
全程只做推理、不用真实数据训练或重拟合任何参数），再逐级加校准：

| 设定 | 需要标注 | ROC-AUC | 二分类 F1 | 1% 误报预算下的召回 |
|---|---|---|---|---|
| 同域（有目标域数据，按正常流程训练） | 全部 | 0.9996 | 0.9986 | —（准确率 0.9976） |
| 零样本跨域（自研 → 真实，直接推理） | 0 | 0.6697 | 0.5629 | 0.0006 |
| 只重新拟合标准化器（无需标签） | 0 | **0.4742** | — | 0.0002 |
| +500 个标注窗口微调分类头（3.1 s） | 500 | 0.7034 | 0.5965 | **0.4257** |
| +解冻主干再训 2 epoch（共 6.6 s） | 500 | 0.7657 | 0.6150 | **0.4453** |

**三条结论（都写进了报告，没有藏）**：

1. **零样本跨域不可用**（F1 0.5629、误报率 21%），而且**只重拟合标准化器会把 AUC 从 0.6697 打到 0.4742** ——
   零样本那点排序能力有相当部分来自"漂移幅度本身"造成的假信号（攻击行偏离合成分布更远，被误打误撞排到前面），
   把量纲拉回目标域口径就消失了。**这条反直觉结论的实用价值是：跨域 AUC 高不能被当作"模型还能用"的证据。**
2. **真正有效的是少量目标域标注**：500 个窗口、3 秒微调分类头，召回由 0.0006 提到 0.4257；
   再解冻主干 6.6 秒提到 0.4453 —— 仍远低于同域的 0.9986。逐特征漂移诊断指出根因是
   **采集口径差异**（CICFlowMeter 的流切分/超时/子流定义）而非模型结构：重定标后
   "正常流量像不像训练数据"确实修好了（|z-shift| 均值 0.4956→0.2089、超 1σ 特征 7/71→1/71），
   但"攻击长什么样"修不了（攻击行仍 |z| 均值 0.275、最大 2.94）。
3. **正确的下一步不是继续调模型，而是用目标域统计量反向标定生成器参数（域随机化）** ——
   本作品生成器的均值/方差/重尾参数都是显式可调的，这正是把它做成参数化工具的价值。
   另需说明：该公开数据的窗口并非真实时序（按攻击类型分块拼接发布），
   故上表数值应视为"**窗口级分类**"的上界参考，**不等于在线检测召回率**。

> 我们说这件事，是因为**一个能上线的东西必须知道自己在什么条件下会失效**。
> 同时请注意对照：同一个模型与流水线，在**有目标域数据**时（同域训练/评估）在该真实数据集上
> 可达 0.9976–1.0000（见 3.7），所以失效的原因是域漂移与采集口径，而不是模型或工程本身。
>
> **复现说明**：`python tools/cross_dataset.py` 需要真实数据集 `data/real/insdn/Dataset.csv`。
> 该数据集未标注许可证，依竞赛规则**不再分发**（已 gitignore），因此本实验在仓库里**默认不可一键复现**——
> 完整数值与逐特征明细已固化在 `results/cross_dataset_report.md` 与 `results/cross_dataset.json` 中，
> 拿到同源数据后 `python tools/cross_dataset.py` 一条命令即可重跑（约 42 秒）。

### 3.15 未知攻击（开集）检测：训练时没见过的新型攻击会怎样？（`results/openset_report.md`）

前 8 类都是"已知"的。真实网络里最要命的问题是：**出现训练时从未见过的新型攻击时，系统会不会盲目地
把它硬塞进某个已知类别、还给出很高置信度？** 我们做了开集实验：**把整类攻击从训练/验证中拿掉**
（留出 U2R、留出 Botnet 两个场景 × 3 个种子），测试集里保留该类作为"未知攻击"，
用只在已知类上标定的阈值来评估。

| 留出场景 | 不做拒识时会怎样（**最危险的一组数据**） | 未知检出率 UDR | 已知类宏 F1 代价 |
|---|---|---|---|
| **留出 U2R** | 100% 被安上已知标签：**84% 判成 WebAttack**、13% 判成 DoS，平均置信度 0.82、42% 置信度 ≥0.9 | 1% 误报预算 **69.8%**；0.1% 预算 30.2%（energy 分数） | 0.9931 → 0.9881（−0.5 pt） |
| **留出 Botnet** | 100% 被安上已知标签：**96% 判成 Normal** —— 意味着攻击**连告警都不会触发**，比错报成别的攻击更危险 | 1% 预算 **44.3%**；0.1% 预算 **0.9%**（energy 分数） | 0.9931 → 0.9942（**无代价**） |

**三条结论（都如实写进报告）**：

1. **不拒识的后果是"自信地把新攻击叫成老朋友"**：42% / 74% 的未知窗口被以 ≥0.9 的置信度错判。
   运维会按错误的攻击类型去处置，这比漏报更容易造成误判性事故。
2. **拒识有效，但强烈依赖"未知攻击与已知/正常流量有多像"**：机理独特的 U2R 在 1% 预算下能捞出 70%；
   而与正常流量形态接近的 Botnet（C2 心跳、低速率、长连接）**1% 预算下只能捞出 44%，0.1% 预算下几乎失效（0.9%）**。
   **AUROC 会骗人**——三个 OOD 分数的跨场景 AUROC 都在 0.978 左右，但尾部（低误报预算）表现差了一个数量级。
3. **拒识几乎不伤已知类**：加拒识后已知类宏 F1 反而略升（0.9881→0.9928 / 0.9942→0.9946），
   因为被误拒的已知攻击仍会告警（只是标签变成"未知"）。**所以正确的用法是叠加而非替代**：
   二分类头负责"是不是攻击"，OOD 分数负责"是不是已知类型"，未知告警进人工研判队列，
   确认后回流训练集，形成「未知 → 已知」的闭环。

**这条结论已经落成可用的运行时旋钮**：`tools/openset_calibrate.py` 在**正常窗口**上按误报预算标定阈值
（默认 `entropy`，1% 预算 → 0.3914；此时正常被判未知 1.00%、已知攻击被判未知 0.30%），
再把 `unknown_threshold` 通过 `/api/policy` 热更新进服务——开启后熵超阈值的窗口显示为
`Unknown（未知形态）`，**照常告警与处置**，只是不再声称具体类别；`/metrics` 同步暴露
`sdn_ids_unknown_windows_total`（未知占比本身就是一条免费的漂移指标）。

> 部署建议（报告 8.1 节）：优先用能量分数 `-logsumexp(logits)`；阈值在生产环境的正常流量上取分位数
> （1% 预算取 99 分位）；**未知告警比例本身就是一条免费的漂移指标**，突然升高通常意味着新攻击出现。
> 诚实边界：留出类样本量小（42 / 73 个窗口），且"未知"来自同一生成器，与真实新型攻击仍有差距。

**（2）真实抓包直接接入：`python tools/pcap_to_flows.py`** —— 补上"仿真数据 → 真实网络"的最后一环：

| 能力 | 说明 |
|---|---|
| 格式 | 经典 `.pcap`（微秒/纳秒、大小端 4 种组合）与 `.pcapng`（SHB/IDB/EPB、含 `if_tsresol` 二进制时基） |

| 切分 | 空闲超时（默认 15 s）+ 硬超时（默认 120 s），与 OpenFlow 流表项的 idle/hard timeout 等价 |

| 端到端 | 解析出的 CSV 可直接喂给控制器原生口径模型出告警 |

一条命令即可闭环：`tcpdump -i eth0 -s 0 -w capture.pcap` → `python tools/pcap_to_flows.py --input capture.pcap --output flows.csv` → 检测。

### 3.17 包序列复研：把「卷积到底有没有用」问到底（`results/packet_seq.md`）

3.4 的困难基准已经把"数据太简单"这个借口排除掉了，但它留下最后一个可能性：**卷积要找的"局部组合模式"
也许根本不在流级聚合量这个层次上**。于是我们做了第三次检验——**把输入换成流内的有序包序列**。

做法：用同一批 24,000 条流的物理事实（包长/方向/间隔/标志位）**反构**包序列，在**同一份数据**上
同时跑"包级表示"与"流级滑窗表示"（同数据对照），判据事前写死（GAP = 最好单分支 − 仅 CNN，
包级 GAP ≤ 0.5×流级 GAP 才算"激活"）。

| 表示 | 仅 CNN | 仅 BiLSTM | 混合 | **GAP（CNN 落后）** | Δ（混合 − 最好单分支） | 逐种子配对 |
|---|---|---|---|---|---|---|
| 流级滑窗 T=16（同数据） | 0.8325 | 0.9679 | 0.9337 | **0.1354** | −0.0342 | 3/3 负 |
| 包级 前 16 包 | 0.3004 | 0.3518 | 0.3137 | 0.0514 | −0.0381 | 3/3 负 |
| 包级 前 32 包 | 0.3535 | 0.3606 | **0.3760** | **0.0071** | **+0.0155** | **3/3 正** |
| 包级 前 64 包 | 0.3066 | 0.3623 | **0.3905** | 0.0557 | **+0.0282** | **3/3 正** |

- **卷积的落后程度在包级表示上缩小了 19 倍**（0.1354 → 0.0071）→ "局部模式在特征工程阶段被压平"
  这个解释**部分成立**；
- 更重要：流级表示上混合模型**从未**超过最好单分支（困难基准逐种子配对 6/6 为负），
  而包级 **T=32 与 T=64 两个长度都出现「混合在 3 个种子上全部优于最好单分支」**（均超 1σ）——
  **全项目第一次观察到混合结构的正增益**；
- 总判定写 **mixed** 而不是"激活"：用**全量主实验**当参照更严格时只有 T=32 通过
  （T=64 的仅 CNN 单支有一次种子崩溃，0.1506）；两个参照都报，不挑有利的那个；
- **诚实标注**：包级绝对宏 F1 只有 0.31~0.39（流级 0.968），所以这是**机理探测**，
  不能读成"包级模型更好用"。

### 3.20 域随机化跨域：我们把自己的"下一步建议"做完，结论是**不奏效**（`results/domain_randomization.md`）

3.13 的跨域失败实验给出的下一步建议是"**域随机化**"。这次把它做完：造 6 个"域"
（基准分布 / 隐蔽攻击为主 / 类别边界模糊 / 强噪声 / 老式明显攻击 / 业务构成变化，全部用生成器旋钮，
物理量自洽），逐个**留一域零样本**评估，并加一个**等预算对照**（同样本量、更多域）。

| 留出域 | multi（K−1 域） | single（单域） | 等预算（同量·多域） |
|---|---|---|---|
| D1 基准分布 | 0.4969 | 0.5112 | 0.5482 |
| D2 隐蔽攻击为主 | 0.3815 | **0.6295** | 0.2715 |
| D3 类别边界模糊 | **0.5664** | 0.4623 | 0.1484 |
| D4 强噪声+标注更乱 | 0.5451 | 0.5739 | 0.3317 |
| D5 老式明显攻击 | **0.8276** | 0.6122 | 0.1552 |
| D6 业务构成变化 | 0.5180 | 0.5083 | 0.1288 |

- **平均只 +0.0063，3 折为正 3 折为负（符号检验 p=1.0）→ 判定 `not_supported`**；
- 真正有信息量的是**结构**：域随机化对"老式明显攻击"（+0.22）与"类别边界模糊"（+0.10）**提升巨大**，
  对"隐蔽攻击为主"反而**显著变差**（−0.25）——**它强烈依赖目标域类型，不是万灵药**；
- **等预算对照**（同样本量、只增加多样性）在 5/6 折上**比单域更差** → 在这个难度范围内，
  **"每个域的数据量"比"域的数量"更重要**；
- 顺带记录一个方法论坑：最初用"把同一域复制 K−1 次"来对齐数据量，两次结果**逐位相同**——
  因为数据管线会 `drop_duplicates` 掉完全重复的行；等预算只能靠"多域 + 每域抽样"。

### 3.21 控制器原生字段扩展：17 列 → 30 列，把"字段缺口"补平（`results/ctrl_field_extension.md`）

3.11 量化过字段缺口的代价（17 列口径宏 F1 **0.8441**、须阈值 0.99 + 确认 5、时延 41 ms）。但**那 17 列并不是控制器能拿到的全部**——
本轮把控制器**真能算出来**的字段补上，17 列 → **30 列**，同一批流、同结构、同窗口、3 种子对比：

| 口径 | 特征数 | 宏 F1（3 种子） | 达误报预算 1 次/h 的工作点 | 平均时延 |
|---|---|---|---|---|
| 控制器原生 17 列 | 17 | **0.8183 ± 0.0104** | 阈值 0.985 + 确认 5 | 39.8 ms |
| **+ 可推导聚合量（本次）** | **30** | **0.9956 ± 0.0004** | 阈值 **0.3** + 确认 **2** | **14.0 ms** |
| 完整流特征口径（参照） | 71 | 0.9940 | — | 18.4 ms |

**Δ = +0.1772（σ = 0.0104，约 17σ）**：控制器原生口径**不但追平了完整流特征口径**（差距 0.1757 → **−0.0016**），
而且**工作点更宽松**（阈值 0.985→0.3、确认 5→2、时延 39.8→14.0 ms）。

新增字段全部**只用流表里本来就有的东西**算出来：`avg_pkt_size`（一步除法）+ 轮询窗口内的流表聚合——
`src_distinct_dport`（扫描）、`src_dport_entropy`、`src_short_flow_ratio`、`src_new_flow_rate`（暴破）、
`dst_distinct_src`、`dst_src_entropy`（DDoS 分布式洪泛）、`src/dst_flow_count`、`table_flow_count`、`proto_share`。

> **两条必须一起看的诚实说明**：
> ① **明确不可得**：TCP 标志位计数、包长/IAT 分布、头部长度、活跃/空闲周期、subflow/bulk 统计——
> OpenFlow 流表统计**本身不含**这些量，本工具不去伪造它们，因此这是"补可推导量"而不是"假装拿到报文信息"；
> ② **聚合窗口是因果的（只看过去 60 秒）**：最初实现用了 ±60 秒的对称窗口（含未来行），
> 那是一种**前视泄漏**、与真机行为不符，已改为 `[t−60s, t]` 并按真机语义重跑（上表即修正后的数字）。
> 另外需注意：聚合量天然携带"攻击战役级"的形态（一个源打很多端口、很多源打同一目的），
> 这在真实 SDN 里同样可算，但真实流量的这种形态会比本仿真数据更嘈杂。

### 3.22 开集拒识改进：马氏距离把未知攻击检出率从 44% 拉到 100%（`results/openset_ood_plus.md`）

3.14 的结论是"不做拒识时 100% 的未知攻击被自信错判；加拒识后 U2R 69.8%、**Botnet 只有 44.3%**"。
这次在**特征空间**上补两种分数（复用已训练的开集模型，不重训）：**马氏距离**（类条件均值 + 共享协方差）
与 **KNN 距离**。

| 场景 | 分数 | **UDR@1%** | **UDR@0.1%** | 已知攻击误拒@1% |
|---|---|---|---|---|
| **U2R** | 基线最佳（energy） | 0.6984 | 0.3016 | 0.0045 |
| | **马氏距离（新增）** | **1.0000** | **0.8730** | 0.0302 |
| | KNN / 特征范数（诊断） | 0.1984 / 0.0476 | 0.1349 / 0.0238 | — |
| **Botnet** | 基线最佳（energy） | 0.4429 | 0.0091 | 0.0053 |
| | **马氏距离（新增）** | **1.0000** | **0.9087** | 0.0606 |
| | KNN / 特征范数（诊断） | 0.3151 / 0.0411 | 0.0776 / 0.0274 | — |

- **尾部提升巨大**：最严预算（0.1%）下 Botnet 从 **0.9% → 90.9%**、U2R 从 30.2% → 87.3%；
- **自我怀疑诊断通过**：表里的 `norm`（只看特征范数偏离）UDR 仅 0.4%~5% →
  马氏距离的提升**不是**"未知类范数偏移"这种平凡信号；
- **诚实代价**：已知攻击的误拒率从约 0.5% 升到 3.0%~6.1% → 按事前判据（代价不得变差 >2 个百分点）
  判定为 **`partial`**（尾部大幅改善、但要接受已知类多一点误拒）；
- KNN 距离**没有**改善（0.20/0.32），如实列为无效方案。

### 3.23 特征选择：把一篇同领域已发表论文的方法框架补齐（`results/feature_selection.md`）

作品的方案里原来**没有"特征选择"这一环**。本轮按对标论文把框架补齐——
对象是《通信技术》2026, 59(8): 950-960 的《基于 PLO-BiLSTM 的网络异常流量检测方法》
（南京邮电大学），它的核心创新点正是**用 bPLO（二值化极光优化）从高维流量特征里挑最优子集**。

**做了什么**：按论文式(1)~(11) **独立重写** bPLO（回旋运动 / 极光椭圆漫步 + 莱维飞行 /
粒子碰撞 / Sigmoid 二值化 / 适应度 `γ·error + β·|R|/|D|`，γ=0.99、β=0.01、m 可调），
配 **同预算**的经典二值 PSO、同目标维数的 PCA、以及"不选特征"三个对照，
在 **2 个口径 × 2 个模型 × 3 个种子**上跑满 **48 次训练**，另做论文表 4 的「质量 m」敏感性。
脚本自带**离线自检**（40 维里只有 6 维有效的合成问题上验算法；并校验掩码与适应度自洽、同种子可复现）。

**结果（逐种子配对，同一套切分与评估代码）**：

| 口径 | 不选特征 | PCA | PSO | **bPLO** | bPLO 保留 |
|---|---|---|---|---|---|
| 自研（71 列）· 主模型 | 0.9940 | 0.9940（48） | 0.9934（39） | **0.9942**（48） | 48/71 |
| 自研（71 列）· BiLSTM | 0.9968 | **0.9983**（48） | 0.9962（39） | 0.9965（48） | 48/71 |
| 控制器原生（17 列）· 主模型 | 0.8148 | 0.7177（11） | 0.8223（7） | **0.8536**（11） | 11/17 |
| 控制器原生（17 列）· BiLSTM | 0.9109 | 0.8989（11） | 0.9365（7） | **0.9413**（11） | 11/17 |

（宏平均 F1，括号内为特征数；在线片段召回全部 100%）

**结论必须分开说**（这是本次实验最有信息量的地方）：

- **富特征口径（71 列）上没有增益**：逐种子配对 3 正 / 3 负，平均 Δ=−0.0001（p=1.0）——
  深度模型自己就能容忍冗余，特征选择的收益被种子噪声淹没；
- **控制器原生口径（17 列）上显著有效**：**6/6 配对为正**，平均 Δ=**+0.0346**（p=0.031），
  而且**误报同时下降**（57.1 → 36.3 次/小时；BiLSTM 口径 19.1 → 3.8 次/小时）；
- **bPLO 不劣于 PSO**：跨 12 个配对单元 9 正 / 3 负（p=0.146，样本量小，只敢说"中位数更好"）。

**混淆矩阵 / 逐类识别率对比**（对标论文图 5、图 6 的实验方法；`results/figures/confusion_fs_*.png`）：
论文最核心的视觉证据是"有/无特征选择"的混淆矩阵对比，其文字论点是**小样本攻击的识别率明显提高**。
我们按同样方式复算（**不重训**：直接加载已保存的模型、按 JSON 里的特征下标重建输入后重新预测，逐种子平均）：

| 控制器原生口径（17 列，主模型） | 不选特征 | **bPLO**（11 列） | 变化 |
|---|---|---|---|
| WebAttack 识别率 | 0.8084 | **0.9387** | **+13.0 个百分点** |
| BruteForce（最差类） | 0.8333 | **0.8822** | +4.9 pt |
| Normal 识别率 | 0.8843 | 0.9055 | +2.1 pt |
| **宏召回** | 0.9213 | **0.9436** | **+2.2 pt** |

BiLSTM 口径同向：宏召回 0.9490 → **0.9625**，DDoS 0.9655 → 0.9799。
而 PCA 是最差的一档（宏召回 0.8842，Normal 掉到 0.7239）——**"降维"不等于"挑对特征"**。
在 71 列富特征口径上四者几乎重合（宏召回 0.9977~0.9997），与上面的"无增益"结论一致。
> **这条正好复现了论文的核心论点**（特征选择让**小样本/易混淆类**受益最大），
> 而且我们给出了比论文更细的证据：不只报"准确率涨了"，而是指出**涨在哪一类上、最差类提升了多少**。

**如实保留的三条不利事实**（对齐项目的既有纪律）：

1. **适应度用代理分类器**（逻辑回归 3 折交叉验证误差率）：bPLO 一次运行要评估约 300 个候选子集，
   各训一次深度模型算力上不可行——这是工程近似，报告中明确标注，且三个对照方法**用完全相同的代理与预算**；
2. **量化披露论文式(3) 的一个性质**：`AO` 里的常数项 `LB + r1×(UB−LB)/2` 会给每个维度一个恒定正漂移，
   二值化后**每一位被选中的概率都大于 0.5**，于是子集规模系统性偏大（实测平均保留 **66%**），
   而 `β|R|/|D|` 在 β=0.01 时不足以抵消它。**这是按论文公式实现的必然结果，不是实现 bug**——
   我们的自检把它记成「观测」而不是断言，不会为了让数字好看去改实现；
3. **没观测到 m 的敏感性**：m ∈ {50,75,100,125} 收敛到同一特征子集、指标完全一致（论文表 4 显示 m 有影响）。
   原因是我们的适应度地形更光滑、且 m 只影响搜索过程而不参与随后的深度模型训练 →
   **结论：m 的取值结论不能照搬**。

**我们比论文更严的地方**：① 特征**只在训练集上搜索**（论文在全量数据上选，属选择偏差）；
② 不做 7:3 随机划分（沿用时序切分 + purge gap）；③ 同时报在线口径（片段召回/时延/误报每小时）。

### 3.24 与已发表方法的同口径对标：补齐 RNN / LSTM / Transformer（`results/published_baselines.md`）

论文的对比组是 RNN / LSTM / BiLSTM / Transformer，而我们原来只有 `cnn / bilstm / mlp` 三个
**结构消融**变体——"我们比它们好在哪"一直没有本地证据。本轮把三种结构补进
`src/model.py` 的 `VARIANTS`，并在**同一份数据、同一套切分、同一份训练与评估代码**下
逐种子跑完 6 个模型（`tools/published_baselines.py`）。

实现要点：`rnn` 用双向朴素循环（看门控结构值多少）；`lstm` 用**单向** LSTM（对应论文基线）；
`transformer` 用 2 层编码器（4 头自注意力 + FFN + **正弦位置编码**，位置编码用**自定义层**而非
`Lambda` 以保证模型可无损保存/加载，且**不可训练**——窗口只有 T=16 步，可训练位置向量会与分类任务
一起过拟合）。Transformer 参数量明显更大，因此报告表里**单列参数量**，避免结论被参数量差异污染。

> **口径声明**：论文用 CICIDS2017 / UNSW_2018_IoT_Botnet、7:3 随机划分、Min-max 归一化、Accuracy 为主指标；
> 本项目用自研数据集、时序切分 + purge gap、宏平均 F1 + 在线告警口径。
> **三处都不同，所以不能比绝对数值**，能比的只有"方法之间的相对排序"——这正是我们把三个外部对照
> 在同一口径下重跑、而不是抄论文数字的原因。

**结果（3 种子，自研 71 列 × T=16，宏平均 F1）**：

| 模型 | 参数量 | 准确率 | 宏 F1 | 平均时延 | 误报(次/h) |
|---|---|---|---|---|---|
| RNN（双向朴素） | 43,658 | 0.9969 | 0.9949 ±0.0005 | 19.1 ms | 0.11 |
| **LSTM（单向）** | 52,810 | 0.9979 | **0.9969 ±0.0019** | 23.7 ms | 0.44 |
| BiLSTM（双向） | 95,882 | 0.9979 | 0.9968 ±0.0008 | 21.5 ms | 0.22 |
| Transformer（2 层编码器） | 302,345 | 0.9968 | 0.9952 ±0.0024 | 21.2 ms | 0.44 |
| CNN（单分支对照） | 65,289 | 0.9783 | 0.9678 ±0.0049 | **18.1 ms** | 13.60 |
| **CNN‖BiLSTM 双分支（主模型）** | 151,434 | 0.9958 | 0.9940 ±0.0015 | 19.9 ms | 0.55 |

**结论里有对我们不利的一条，照实写**：**单一 LSTM / BiLSTM 的宏 F1 比我们的双分支融合略高**
（Δ≈−0.003；对 BiLSTM 是 0 正 / 3 负，但 3 个种子达不到显著，p=0.25，量级也在种子波动范围内）。
这与实验 3.4 的**困难基准复测**（"卷积无增益，6/6 配对为负"）**互相印证**：
这份数据上的性能来源是时序建模本身。**我们不调参把它做正**，双分支的价值写在别处——
相对纯 CNN 有压倒性优势（+0.026 宏 F1、误报 13.60 → 0.55 次/小时），
且注意力池化是可解释性面板的数据来源。

> 另外这张表顺带证明了**指标口径会改变结论**：只看 Accuracy，六个模型挤在 0.9783~0.9979；
> 换成宏平均 F1，CNN 掉到 0.9678；换成**误报次数/小时**，CNN 13.60 与其余 ≤0.55 相差 25 倍。
> 这正是本项目坚持用宏 F1 + 在线告警口径、而不是只报 Accuracy 的原因。

### 3.25 一句话总结

> 在完全可复现的仿真 SDN 流量上，CNN+BiLSTM 双分支模型取得 **宏 F1 0.9940、AUC 0.9999、
> 攻击片段召回 100%、平均检测时延 18.4 ms、误报 0.55 次/小时**；
> 消融表明**时序建模是性能来源**（去掉 BiLSTM 分支掉 2.1 个百分点），
> 窗口消融给出**部署结论**（窗口加长把误报再降 88%），
> **困难基准复测**则把最容易被质疑的那条负面结论测穿：把数据难度拉满之后，
> 卷积**依然没有增益**（逐种子配对 6/6 为负，p=0.031），"卷积需要更长上下文"**被证伪**——
> 而且**难度翻倍后分类精度掉 5.4 个百分点、误报涨 4.5 倍，攻击片段召回仍是 100%**，安全底线没有退化；
> 工作点分析给出**误报可控的部署方案**（召回 100% 不变，确认 3 窗口把误报再降 92%），
> 运维换算把上述指标落成工程默认工作点（0.50+确认3）的 **≈36 条告警/天、3.6 人工小时/天、漏报 0**（推荐上线工作点 0.90+确认2 为 ≈28 条/天、2.8 h/天、16 ms），
> 漂移实验表明它对环境变化比树模型稳健得多（退化 ≤0.2% vs 3.8%~7.7%），
> 性能基准与闭环实测表明**普通 CPU 即可在线部署**（批量推理 13.6 万条流/秒、端到端 1,364~1,918 条流/秒）。

## 5. 数据：为什么可以自己生成，以及怎么换成真实数据

### 5.1 两种输出格式（都经过列名核对）

| schema | 列数 | 与谁对齐 | 用途 |
|--------|------|----------|------|
| `insdn`（默认） | 84 列 | 公开数据集 **inSDN / CIC-IDS2017**（CICFlowMeter 输出）列名逐字一致 | 与原始 demo 期望的格式对齐；方便横向对比公开数据集结果 |
| `sdn` | 22 列（+1 列多分类标注） | 本仓库 `collect_normal_traffic.py` / `collect_ddos_traffic.py`（Ryu 控制器采集 OpenFlow 流表统计）的输出 | 与自己的 SDN 实验床无缝衔接 |

```bash
python run_all.py --set schema=sdn        # 换成 Ryu 采集脚本同款 22 列格式
```

### 5.2 8 类流量（与 inSDN 类别体系对齐）

| 类别 | 机理建模要点（为什么模型能学到） |
|------|----------------------------------|
| Normal | HTTP / 大文件传输 / DNS / ICMP / UDP 流的混合，量级跨度大 |
| DDoS | 多源、**超高包速率（可达 1e4 pkt/s）**、极短持续、几乎无反向包 |
| DoS | 单源、速率中等、**持续时间长**；Slowloris 甚至几百秒的极低速率长连接 |
| Probe | 端口扫描：单流 1~3 个包、时长毫秒级、SYN/RST 标志、目标端口随机 |
| BruteForce | SSH/FTP 反复认证：等间隔小包往返、连接数中等 |
| WebAttack | HTTP 注入载荷：前向包偏大、PSH 比例高 |
| Botnet | C2 心跳：**到达间隔极其规律**（正则化系数极低）、速率极低、连接超长 |
| U2R | 极少见：载荷异常、标志位组合异常（URG/ECE/CWE 同时出现） |

生成器是**先生成物理事实、再渲染成数据集列**的：包数、字节数、时长、活跃/空闲时间、
标志位计数、到达间隔统计之间互相自洽（例如 `Flow Packets/s = 总包数 / 时长`、
`Packet Length Mean = 总字节 / 总包数`），不会出现"随机撒点导致的物理上不可能的样本"。

同时内置了**可控的难度旋钮**，保证指标不是虚高：

| 配置项 | 含义 |
|--------|------|
| `overlap_ratio` | 每类中与"最易混淆类"做几何混合的困难样本比例（默认 15%） |
| `label_noise` | 标注噪声比例（默认 1%） |
| `feature_noise` | 量测噪声强度（默认 5%） |
| `drift_strength` | 额外生成一个**分布漂移测试集**（鲁棒性实验） |

## 6. 方法

### 6.1 网络结构

```
输入 (T, F)：T 条连续流记录 × F 维流特征（默认 T=10）
  │
  ├─ CNN 分支：Conv1D(64,k=3,膨胀率1) → BN → ReLU → Conv1D(128,k=3,膨胀率2) → BN → ReLU
  │            作用：沿时间轴提取"相邻若干条流"的局部组合模式（突发 SYN、等间隔心跳）
  │            ★ 用膨胀卷积而非池化，避免把 10 个时间步压成 2 个
  │
  ├─ BiLSTM 分支：BiLSTM(64, return_sequences=True)
  │            作用：直接在原始窗口上做双向时序建模，抓整段演化趋势
  │
  ├─ 两条分支各自池化后拼接（CNN 分支全局最大池化 + 时序分支注意力池化）
  │            ★ 并行双分支，比"CNN 输出再喂 LSTM"的串行做法更稳（见 docs/02 消融讨论）
  │
  └─ 双头输出
       ├─ 多分类头 softmax(8)：认得出是哪种攻击
       └─ 二分类头 sigmoid(1)：直接回答"正常 / 异常"
     损失 = CE(多分类) + 0.3 × BCE(二分类)   ← 多任务联合训练
```

### 6.2 数据切分（这里最容易翻车，也最能体现工程严谨性）

```
时间轴 ──────────────────────────────────────────────────────────────▶
        │  训练集 60%  │purge│ 验证集 15% │purge│   测试集 25%   │
        └──────────────┘     └────────────┘     └───────────────┘
   * 严格按时间顺序切分（网络流是时序数据，随机切分 = 数据泄漏）
   * 边界留 purge 间隙，滑窗不跨集
   * StandardScaler 只在训练集 fit，再 transform 验证/测试集
   * 验证集用于早停与调参，测试集只在最终评估时用一次
```

### 6.3 评估体系（三套指标一起看）

1. **多分类**：accuracy、macro/weighted P-R-F1、逐类明细、混淆矩阵、Kappa、Top-2、macro AUC(OvR)
2. **二分类异常检测**：ROC-AUC、PR-AUC、MCC、最优阈值下的 F1、**TPR@FPR=1%/0.1%**（安全场景最常用的工作点）
3. **在线告警级**：在连续测试流上滚动取窗，统计
   - **检测时延**：攻击开始 → 第一条告警（均值 / 中位数 / P95，秒）
   - **误报率**：次/小时（工程上看这个，比 FPR 比例更直观）
   - **攻击片段召回率**：有多少个攻击片段被报出来、漏报几个

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/detect` | 推一批流记录 → 逐条判定 + 新告警 + 处置建议（**控制器调这个**） |

| GET | `/api/stats` | 吞吐、时延分位、各类告警计数（可观测） |

三个工程上的取舍（都可讲）：

1. **演示不依赖 TensorFlow**：推理在实验阶段就缓存成"窗口级预测"，演示服务只做回放，

2. **回放的是留出测试集**：不是编好的动画，预测结果与 `results/metrics_*.json` 同源，**演示与论文数字一致**。
3. **"注入攻击"是诚实的**：只是把播放位置跳到真实攻击片段起点，检测时延由模型自己决定。

| 维度 | 原 demo | 本工程 |

## 10. 常见问题

**Q：一定要装 TensorFlow 吗？**
训练与推理需要；但 `tools/smoke_test.py`（数据链路自检）和演示大屏（读缓存预测）都不需要。

**Q：没有 GPU，训练要多久？**
默认配置（约 6~7 万条流记录、T=10 窗口、约 4 万训练窗口、40 epoch，含早停）
在 8 核 CPU 上大约几十分钟。想更快就 `--smoke` 或 `--set scale=0.4`。

**Q：图里的中文变成方块？**
`src/utils.py` 会自动查找 微软雅黑/黑体/苹方/文泉驿 等字体；都没有时会自动**回退成英文标注**，
不会报错。也可以手动把任意 `.ttf` 放进系统字体目录后重跑。

**Q：Windows 控制台中文乱码？**
`src/utils.py` 会把 stdout 切到 UTF-8；若仍乱码，运行前执行 `chcp 65001`。

**Q：想换个数据规模？**
`--set scale=0.5`（数据量）、`--set window_size=16`（窗口）、`--epochs 60`（轮数）。

**Q：想复现某个结果？**
配置里固定了 `seed`，并写入 `artifacts/<tag>/config_used.json`；使用同一份配置 + 同一版本依赖即可复现。
