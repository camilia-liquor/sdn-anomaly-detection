## 一、项目概述

### 1.1 背景与意义

网络空间安全已成为我国工学门类一级学科（0839），但该学科的实验实训环节长期面临一个**结构性困境**：

**网络攻防实验本身具有破坏性与高成本。** 在真实网络上做攻防演练既不安全也不现实——一次 DDoS 洪泛就可能打断校园网。结果是：学生只能"看课件、背规则"，**缺少可复现、低成本、可量化的攻防实验环境**。

与此同时，行业侧的需求是硬的。2025 年 SANS 检测与响应调查显示：**73% 的组织把"误报"列为威胁检测的第一大挑战**，且比上年显著上升，"非常频繁遇到误报"的比例一年内由 13% 涨到 20%。**告警疲劳本身已成为安全风险**。

这两个缺口指向同一件事：**网络空间安全学科需要一个"能安全地造出攻击、能自动判出攻击、能量化运维代价"的平台**——而这正是 AI 能深度适配的切入点。

### 1.2 核心目标

| 目标层次 | 具体目标 |
|---|---|
| **科研目标** | 提出高精度、可迁移的入侵检测模型，提升对复杂与**新型**攻击模式的适应能力 |
| **教学 / 实验目标** | 构建安全、可复现、低成本的 SDN 攻防实验平台，支撑《网络攻防》《入侵检测》《网络安全》等课程的实验实训 |
| **交叉目标** | 以"**数据特性 → 算法能力**"的精准映射，探索人工智能与网络空间安全学科深度融合的新方法 |

**一句话定位**：把"不可复现的研究型 demo"变成**"一条命令可复现、可现场演示、可被他人复用的学科实验平台"**，并把每一处数据泄漏与评估错误修掉、留下证据。

## 二、需求分析

### 2.1 学科专业界定

- **学科**：网络空间安全（0839）
- **核心环节覆盖**：理论研究、科研探索、**实验实训**、**教学实践**、自主学习（五个环节）
- **具体应用场景**：网络空间安全专业《入侵检测》课程的**实验实训**与**科研验证**——学生在 SDN 仿真环境中发起真实攻击手法，平台自动判定并给出处置建议，全程无破坏性

### 2.2 核心痛点梳理

| # | 学科环节痛点 | 现状证据 | 本作品的应对 |
|---|---|---|---|
| ① | **攻防实验不安全、不可复现** | 真实网络攻防演练会打断业务，高校实验多停留在规则讲解 | 自研仿真流量生成器 + Mininet/Ryu 环境，**零硬件成本、可重复运行** |
| ② | **公开数据集本身有缺陷，学生学到的是错的** | 实测 inSDN **46% 行是精确重复**、标签为"正常块+攻击块"拼接；同文件随机切分可轻松拿到 **0.9998**，而按时间切只有 **0.03~0.63**——**同一份数据换一种切分，数字差 30 倍** | 内置去重 + 时序/按组切分 + **行级近重复交集必须为 0，否则工具直接报错拒绝出结论** |
| ③ | **只看准确率，脱离运维现实** | SANS 2025：73% 组织把误报列第一挑战 | 提出**检测工作点选择**（窗口×阈值×确认次数），把误报换算成**人工工时/天** |
| ④ | **科研成果不可复现，无法用于教学传承** | 论文式 demo 换台机器就跑不起来 | 一条命令复现 + 产物全落盘 + **130 项交付自检** |

### 2.3 AI 赋能需求

本学科需要的 AI 能力不是"套一个分类器"，而是三条与**流统计量的物理特性**深度适配的能力：

1. **时序建模**：攻击特征分布在**连续多条流记录**上（扫描是一串短连接、C2 是低频心跳），因此需要滑动窗口 + 时序模型，而不是单条记录分类。
2. **未知攻击拒识**：真实攻防中**新型攻击必然出现**，模型必须能说"我不认识"——否则会自信地把未知攻击判成正常。
3. **可解释的工作点**：学科实验要能回答"**为什么这样报警**"，因此阈值、确认窗口都必须可调、可解释、可复现。

## 三、解决方案设计

### 3.1 系统架构设计（五层）

```
① 数据层    自研流量生成器（8 类，难度可控）· 公开真实数据集接入（6 份）
              ↓ 逐条流记录（时间有序）
② 算法层    无泄漏预处理（去重/切分/仅训练集拟合 scaler）
             → 滑动窗口 (T, F) → CNN + BiLSTM 双分支 → 多任务双头（8 类 + 攻击/正常）
              ↓ 三路分数：攻击概率 · 多分类置信度 · 新颖性分数
③ 服务层    在线检测服务：三态分级（已知攻击/未知形态/正常但可疑）→ 连续确认 → 处置策略
              ↓ 告警 + 处置建议
④ 应用层    Ryu 控制器适配层：真实 OpenFlow 1.3 下发（阻断/限速）· 幂等 · 审计台账
              ↓
⑤ 展示层    实时演示大屏（攻击拓扑/检测曲线/处置控制台/**复核台**）+ 评审视图
```

**关键设计**：③→④→⑤ 之间不是单向的。告警之外还有**复核台**——系统承认"不认识"的样本进入待研判队列，由人给结论并**回流成训练样本**，形成"未知 → 已知"闭环。

### 3.2 技术选型依据（与学科需求如何适配）

| 选型 | 学科需求对应 |
|---|---|
| **CNN + BiLSTM 双分支** | 卷积捕捉**局部攻击模式**（洪泛的突发、扫描的并发），BiLSTM 捕捉**时序依赖**（低频心跳、慢速攻击）；两分支并行后融合——对应"攻击分布在连续多条流上"这一数据特性 |
| **多任务双头**（8 类 + 二分类） | 教学需要"**这是什么攻击**"（细类，便于讲解机理），运维需要"**是不是攻击**"（粗判，便于处置） |
| **开集拒识**（能量分数） | 对应"新型攻击必然出现"：不做拒识时，实测 **115/115 个未知攻击窗口全部被贴上已知类标签**，留出 Botnet 时 **96% 被判成「正常」，连告警都不触发** |
| **工作点选择**（窗口×阈值×确认次数） | 对应"实验要可解释"：把误报从 8.56 压到 **0.66 次/小时**而召回保持 100%，且给出完整 Pareto 表 |
| **无泄漏评估纪律** | 对应痛点②：这是本作品与公开 demo 最本质的区别——**先把评估做对，再谈模型好坏** |

### 3.3 核心技术模块

1. **自研流量生成器**：8 类攻击、双 schema（84 列 / 22 列）、物理量自洽、三个难度旋钮（类别重叠 / 隐蔽攻击 / 标注噪声）——**让实验难度可控、可复现**。
2. **无泄漏评测流水线**：去重 → 时序/按组/跨天切分 → 仅用训练集拟合标准化器 → **漏检泄漏则拒绝出结论**。
3. **在线检测服务**：滑窗推理、连续确认去抖、三态分级、策略热更新、审计台账、Prometheus 指标。
4. **控制平面闭环**：`integrations/ryu_guard.py` 从 OpenFlow 流表统计取字段 → 判定 → 真实下发限速/阻断，**幂等 + 有效期自动解除**。
5. **复核与回流**：待研判队列 + 观察池（差一点到阈值的窗口留痕）+ 人工结论回流为训练样本。

## 四、方案可行性

### 4.1 技术可行性

| 指标 | 实测 |
|---|---|
| 交付完整性 | **130 项交付验收自检通过 / 0 失败**（含在线接口真实调用） |
| 模型性能（自研难度可控数据） | 8 类宏 F1 **0.9940**（3 种子均值）、**攻击片段召回 100%** |
| 逐类确认时延 | Probe **5.5 ms** → Botnet **857 ms**（差 **156 倍**，与攻击机理一致） |
| CPU 可跑 | 批量推理 4.5 万窗口/秒（≈13.6 万条流/秒），**无需 GPU** |
| 控制平面真机验证 | 真实 `ryu-manager` + 真实 OpenFlow 1.3 线协议 **19/19 项通过** |
| 论文同口径对标 | 补齐 RNN / LSTM / Transformer 三个外部对照，同口径复跑 |

### 4.2 经济可行性

- **零许可成本**：全栈开源（Apache-2.0），无商业 IDS 授权费
- **零硬件成本**：Mininet + Ryu 纯软件仿真，普通 CPU 即可；无需真实交换机与攻防靶场
- **运维成本可算**：把误报换算成人工工时——真实数据上 N=1 需 **22.6~35.6 工时/天**（约 3~4.5 个全职人力，**不具备上线条件**）；加上"连续确认 2 窗口"降至 **0.36~1.37 工时/天**。**一个开关压掉 96%**

### 4.3 推广价值

- **复用条件**：只要具备 Linux + Python 环境即可；数据可自生成（**不依赖任何受限数据集**），因此**没有数据授权障碍**
- **落地路径**：① 课程实验（直接用生成器造 8 类攻击流量）→ ② 科研验证（无泄漏评测流水线可直接用于他课题）→ ③ 校园网试点（在线检测服务已提供接口与部署文档）
- **同类学科适配**：同一套"数据特性 → 算法能力"的方法可迁移到物联网安全、工控安全等相邻方向

## 六、应用效果

### 6.1 效果验证依据（数据真实有效）

本作品的验证依据分三层，**全部可复现**：

**① 科研效率证明（主依据）**

- **一条命令复现全流程**：`python run_all.py`；冒烟验证 25 秒
- **130 项交付验收自检**：提交前跑一条命令，不通过不允许提交；缺依赖时**直接拒跑**而不给假结论
- **无泄漏纪律**：真实数据评测中，切分后行级近重复交集必须为 0，**实测拦下过 3,571 行泄漏**并拒绝出结论
- **口径自我修正**：发现真实数据在线误报口径与合成域不一致（落在被丢弃短片段上的告警被重复计入误报）后，**按可复现参数重跑并同步全部引用**

**② 真实数据上的量化结果（无泄漏口径）**

| 数据 / 协议 | TPR@FPR=1% |
|---|---|
| inSDN / block（深度+马氏融合） | **0.6328** |
| CIC-IDS2017 / cross_day（无监督 kNN） | **0.2851** |
| CSE-CIC-IDS2018 / cross_day | 0.2035 |
| 跨环境直接迁移（不做目标域标定） | **0.034~0.038**（如实报告不可用） |

在线告警口径（CIC-IDS2017 跨天，39 个攻击片段）：无监督 kNN **片段召回 0.9231**。

**③ 未知攻击与漏报的容错能力**

- 不做拒识时：**115/115 未知攻击窗口全被贴上已知类标签**，96% 被判"正常"（连告警都不触发）
- 加拒识后：1% 误报预算下未知检出率 U2R **69.8%** / Botnet **44.3%**，同期已知攻击被误拒仅 0.4%/0.5%
- 捞不回来的部分**有流程兜住**：进复核台 → 人工结论 → 回流成训练样本

### 6.2 成果展示

| 成果 | 量化 |
|---|---|
| 检测能力 | 8 类宏 F1 **0.9940**、片段召回 **100%**、平均时延 18.4 ms |
| 误报治理 | **8.56 → 0.66 次/小时**（召回不变）；完整 Pareto 表供选择 |
| 运维代价 | 真实数据 **22.6~35.6 → 0.36~1.37 工时/天**（-96%） |
| 未知攻击 | 拒识后 UDR **44%~70%**；不做拒识则为 0（全被误判为已知类） |
| 工程完整度 | **130 项自检 0 失败**、41 个工具、统一入口 `cida`、真机 **19/19** |
| 开放成果 | Apache-2.0 全栈开源，含 33 张图表与完整复现文档 |

**⚠️ 关于教学试点数据（主动说明）**：本作品**未采用教学试点数据**作为效果依据。原因是：真实的课程试点需要完整学期与知情同意流程，**短期内的"试点数据"难以保证真实有效**。因此我们把效果依据建立在**可复现的科研效率证明 + 真实公开数据集上的量化结果**上，并如实标注哪些结论**尚未在真实教学场景验证**。我们认为：**在这类评分中，经得起复核的数字比漂亮但无法复核的数字更有价值。**

## 七、总结与展望

### 7.1 方案总结

本作品的核心亮点：

1. **学科问题解决新方法**：把"数据特性 → 算法能力"的映射做实——时序建模对应攻击的连续性、开集拒识对应新型攻击的必然性、工作点选择对应运维的误报预算
2. **教学科研新模式**：**零硬件、零破坏性、可复现**的攻防实验平台，解决网络空间安全学科实验实训的结构性困境
3. **诚实可验证的工程**：130 项自检、无泄漏纪律、主动披露边界与能力上限

**存在的不足（客观说明）**：
- 未在真实生产网络长期运行（已用 9.1 小时等价回放缩小边界；在线误报口径的可信换算限于时间跨度 ≤7 天的数据）
- 未知攻击检出率仅 44%~70%，**并非"解决"了未知攻击**，而是把它变成可处置、可回流的流程
- 已完成的真机验证仅到"真实 ryu-manager + 真实 OF1.3 线协议"，**未覆盖物理交换机与真实攻击流量**
- 对抗鲁棒性：白盒定向扰动可把逃逸率推到 73%（对抗训练可缓解，代价约 0.7 个百分点）

### 7.2 未来展望

1. **教学侧落地**：与网络空间安全专业课程对接，形成《入侵检测》实验指导书与考核题库
2. **能力升级**：原始报文序列 / 字节级输入，进一步验证卷积分支价值
3. **平台化**：面向同类学科（物联网安全、工控安全）抽象出可复用的"仿真—检测—处置"实验框架
4. **持续维护**：补充英文文档、示例数据与 issue 模板，降低他人复用门槛
