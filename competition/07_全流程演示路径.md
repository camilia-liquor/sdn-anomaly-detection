# 全流程现场演示路径（runbook）

> 用途：现场/录屏时照着走，把**整条链路**都展示出来。
> 原则：**能展示的全展示、一个都不藏**；但每个数字都必须能对回磁盘产物。
> 本文件里每一行都给出"评委看到什么 / 这一步证明什么 / 数字出处"，**出处对不上就不要讲**。

## 0. 一句话总览（开场用）

> "这不是一份实验报告，是一条能跑通的闭环：**采集 → 检测 → 分级 → 确认 → 处置 → 留痕 → 复核 → 回流 → 评测 → 验收**。
> 下面每一步我都现场走给你看，每一步背后都有可复现的产物。"

链路全景：

```
① 环境自检 → ② 一条命令复现 + 130 项验收 → ③ 数据来源与无泄漏口径
   → ④ 检测（8 类 + 逐类时延）→ ⑤ 三态分级 → ⑥ 连续确认去抖
   → ⑦ 处置（动作矩阵/幂等/审计）→ ⑧ 真机协议实测
   → ⑨ 未知攻击：拒识 + 复核台 → ⑩ 漏报：观察池 + 回看缓冲
   → ⑪ 回流：人工结论 → 训练样本 → 候选模型
   → ⑫ 真实数据评测（无泄漏 + 在线口径 + 运维换算）
   → ⑬ 主动披露边界
```

## 2. 全程可用的四句"锚点话术"

1. **"每个数字都能对回产物"** —— 讲任何数字时顺手报出文件路径（`results/…`）。
2. **"这条口径我们修过"** —— 真实数据在线误报曾因口径不一致偏高，已按可复现参数重跑并同步全部引用。
3. **"这里我们做不到"** —— 未知攻击只能捞出 44%~70%；N=1 的真实误报代价高到不可上线。
4. **"我们用工具拦住自己"** —— 验收自检会在环境不完整时**拒绝给结论**；真实数据评测在检测到行级泄漏时**直接报错拒绝出结论**。

## 3. 录制前必须补强的地方（当前"看不到东西"的位置）

> 下面这些不是缺陷，是**演示效果**问题：功能在，但默认状态下评委看不到。

| 位置 | 现状 | 处理 |
|---|---|---|
| 复核台 | `unknown_threshold` 默认 0 → 面板为空 | **必须现场拉滑块**（已在 `04_演示视频脚本.md` 写明步骤） |
| 大屏「漂移与未知态势」 | 依赖窗口级预测缓存，回放未开始时可能为空 | 开拍前先让回放跑 20~30 秒再录 |
| `live_demo.py`（离线演示） | 会连报多次告警，幂等抑制后只下发一次 | 讲到"幂等"时正好用这个现象做例子 |
| 真机 16/16 | 是**报告**不是现场（无物理交换机） | 主动说明"仅剩物理交换机未覆盖"，不要暗示现场在真机上跑 |
| 对抗鲁棒性 / 漂移 | 只有报告与图 | 用图表讲，别声称现场测 |

## 4. 三条不许越过的线（给自己和队友看）

1. **不把合成数据说成真实数据**：合成域宏 F1 0.9940 与真实数据 TPR@FPR=1% 0.03~0.63 是两回事，必须分开讲。
2. **不把"接口存在"说成"已上线"**：处置能力有真机协议实测，但没有物理交换机与真实攻击流量。
3. **不四舍五入到"更好看"**：例如 0.034 不能讲成"约 0.1"。

> 这三条是**加分项**：评分标准要求"数据真实有效"，主动划清边界比任何漂亮数字都更能建立信任。
