# 应用效果：科研效率与可复现性证据

> **本文件替代原"教学试点"路径**，用于支撑评分规则「应用效果（20 分）」。
> 依据是规则原文：「有充分的效果验证依据（教学试点数据、**科研效率证明等**），数据真实有效，
> 能明确体现 AI 赋能价值，对比传统方式有显著提升」——我们走的是其中的「**科研效率证明等**」。
> **本文件不含任何教学试点数据、不含任何用户问卷数据**；所有数字都来自仓库内的可复现产物，
> 第三方可按第 4 节的命令逐项复核。

## 1. 科研效率证明（可复现，逐项有产物）

| 环节 | 传统做法（人工） | 本作品 | 产物/命令 |
|---|---|---|---|
| 全流程复现 | 配环境、下数据、写切分脚本、反复调参，通常数天 | **一条命令**跑完全流程 | `run_all.py`、`一键运行.bat` |
| 交付自检 | 人工逐项核对，易漏 | **130 项自动验收，通过 130 / 失败 0** | `results/acceptance_summary.json` |
| 数据获取与合规 | 手工下载、手工记来源，来源/许可常丢失 | **6 份公开数据集（约 3.5 GB）** 的来源、许可、sha256 自动登记，并在体检中标注"能/不能支撑哪种评测" | `data/real/MANIFEST.json`、`results/real_datasets.md` |
| 评测协议 | 自己写切分，极易产生数据泄漏（本领域高发问题） | **6 种切分协议内置**（block / group / cross_day / family_holdout / chunked / stratified）；**行级近重复交集必须为 0 是硬门槛**，不符直接报错拒绝出结论 | `tools/real_eval.py` |
| 单次评测耗时 | 含重训的数小时~数天 | **约 40 秒**（仅推理，无需重训） | `tools/real_eval.py` 运行日志 |
| 运维口径换算 | 只报"准确率/F1" | 自动换算 **告警量/天与人工工时/天** | `tools/ops_impact.py` |

## 2. 自我证伪效率（本作品真正稀缺的能力）

科研效率不只是"跑得快"，更是**能低成本推翻自己**。本作品在开发过程中实际完成了四次自我证伪，
每次都给出了可复核的产物：

| 自我证伪 | 结论 | 价值 |
|---|---|---|
| 困难基准复测卷积分支 | **卷积无增益**（逐种子 6/6 为负，p=0.031） | 主动下调该分支的定位，不再当精度来源 |
| 跨域排序诊断 | 发现 **AUC<0.5 的排序反转**，查明机制是跨段正常画像漂移 | 揭示"漏报+误报爆炸"并存的隐蔽失效模式 |
| 数值假象排查 | 发现 `±inf→1.8e308` 造成的"深度模型召回 0.0009"是**假象**，修正后为 0.4720 | 避免把数值 bug 写成模型结论 |
| 时间戳可信度判定 | CIC-IDS2017 跨度 1476h、inSDN 6733h **不可信**，自动拒绝换算误报率 | 避免把虚高的分母当成真实运维代价 |

**这些工作若靠人工复核，每一条都需要数天**（下数据、写脚本、逐项比对、回溯原因）。
本作品把它们做成了平台内置能力：每次评测自动给出，并落盘留痕。

## 3. 与传统方式的量化对比（评分明确要求"对比传统方式有显著提升"）

| 对比维度 | 传统方式 | 本作品 |
|---|---|---|
| 实验成本 | 专用网络安全设备，动辄数十万元 | 全开源 + 虚拟仿真，硬件投入**近乎为零** |
| 实验安全性 | 真实网络攻防演练具破坏性 | 虚拟拓扑内完成，**零风险、可反复重放** |
| 评测口径 | 多报"同域随机切分"精度 | 报**无泄漏口径 + 实际误报率 + TPR@FPR=1%**（阈值无关、可横向比） |
| 运维可读性 | 只报"次/小时"，无法排班 | 换算为**告警/天、人工工时/天**；实测 N=1 需 24~38 工时/天（不可上线），N=2 降至 0.36~1.37 工时/天 |
| 响应方式 | 离线检测，处置滞后 | **检测—阻断闭环**，控制器闭环判定 p50 29.8 ms |
| 可复现性 | 依赖特定环境与个人脚本，难复现 | 一键脚本 + 130 项验收自检 + 产物清单，**逐项可复现** |
| 结论可信度 | 单次结果、无边界说明 | 主动报告边界（跨域迁移乏力、预算守不住、卷积无增益），**问不倒** |

## 5. 与评分档位的诚实对应

按规则三档：

- **14~20 分档**要求"有充分的效果验证依据（教学试点数据、科研效率证明等）…对比传统方式**有显著提升**"；
- **7~13 分档**要求"有一定的效果验证依据，数据基本真实，能体现 AI 赋能价值，对比传统方式有一定提升"；
- 0~6 分档：无任何效果验证依据。

**本作品的实际位置（不夸大）**：第 1~4 节给出的全部是可复现的**科研效率与可复现性证据**，
且第 3 节的每一项对比都有实测数字支撑，因此**不属于 0~6 分档**；
但它**没有教学试点数据、也没有用户反馈数据**，所以按规则原文严格对照，
**预期落在 7~13 分档偏向该档上限**，而不是 14~20 分档。

**若想把这一项做扎实而不冒风险**，唯一合规的路径是补**真实使用者的反馈**（哪怕只是
3~5 位同学/老师实际试用平台后的一段签字评价、或一次实验室开放日的体验记录），
事项与流程见 `docs/08` 的「若要走教学/试用路径」小节——**但必须真实发生，不得编造**。
