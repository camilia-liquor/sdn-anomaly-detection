## 一、作品概述

### 1.1 背景与问题

SDN（软件定义网络）把控制平面集中到控制器上，控制器天然掌握全网流表统计。这带来一个机会：
**不需要在每台主机部署探针，就能在网络中枢直接观察流量级攻击**——DDoS 洪泛、端口扫描、
暴力破解、僵尸网络心跳等。

但现实中的落地障碍有三层：

1. **识别仍靠人工规则**：运维人员靠阈值与经验规则判断异常，规则更新滞后于攻击手法变化；
2. **已有研究型成果不可用**：公开的算法 demo 多数存在数据泄漏（随机切分连续流量）、
   评估口径错误（在多分类任务上用二分类损失、用硬标签计算 AUC），指标虚高且无法复现；
3. **不可复现 = 不可信**：数据集路径硬编码、随机种子不固定、标准化器与标签编码器不落盘，
   换一台机器或换一份数据就失效，评审与工程团队都无法验证。

**目标用户**：校园网/企业网中负责 SDN 控制器运维的网络与安全工程师。
**使用场景**：控制器按固定周期拉取流表统计，形成连续流记录序列，由检测服务实时判定异常并告警。
**本作品要解决的具体问题**：把"一份跑不起来的研究型 demo"变成"**一条命令可复现、可现场演示、
可被他人复用**的异常流量检测开源工程"，并把每一处数据泄漏与评估错误修掉、留下证据。

### 1.2 目标、参赛方向与作品形态

- **参赛方向**：**开源项目改进与生态贡献**（同时体现"开源赋能的 AI 应用创新"）。
  作品围绕上游研究型 demo 开展**二次开发、功能增强、测试用例与文档建设、问题修复**，
  并形成可运行、可演示、可复验的软件原型。
- **作品形态**：Python 工程 + 命令行工具链 + 本地 Web 演示服务（离线可用）。
- **核心功能**：
  1. 自研仿真流量生成器（不依赖任何外部数据集即可产出训练数据）；
  2. CNN + BiLSTM 双分支异常检测模型（多任务双头输出）；
  3. 三套评估口径与 9 类实验图表自动生成；
  4. 实时检测演示大屏（回放真实留出数据 + 一键注入攻击）；
  5. 交付验收自检（36 项）与完整文档。

### 1.3 核心亮点

| # | 亮点 | 可验证证据 |
|---|---|---|
| 1 | **上游 20 条问题清单化修复**（数据泄漏、损失错配、AUC 口径错误等） | `docs/01_原始代码问题清单.md`，逐条标注原文件行号 |
| 2 | **真正的时序建模**：连续多条流记录的滑动窗口 + CNN/BiLSTM 双分支并行 | 消融实验：去掉 BiLSTM 分支宏 F1 由 0.985 降至 0.943 |
| 3 | **窗口长度机理发现**：窗口越长精度越高、误报断崖下降，且卷积分支的增益随窗口单调上升 | 窗口消融（T=10/16/24 × 3 结构）：宏 F1 0.977→0.994→0.997，误报 28.3→3.3 次/小时 |

| 5 | **部署级评估口径**：检测时延、误报次数/小时、攻击片段召回 | 100% 片段召回、平均时延毫秒级、误报率随窗口可调 |

## 二、需求分析与总体方案

### 2.1 需求分析

**现有做法与痛点**（依据公开资料与项目实践记录）：

| 现状做法 | 痛点 | 本作品的应对 |
|---|---|---|
| 人工阈值规则 | 阈值靠经验；攻击手法变化后失效 | 用模型从流统计量学习判别边界，阈值可现场调 |
| 论文式 demo | 换机器跑不起来；指标不可复现 | 一条命令复现 + 固定随机种子 + 产物全落盘 |
| 只报准确率 | 无法回答"上线后多久报警、每小时误报几次" | 增加在线告警级指标（时延/次·小时/片段召回） |
| 自造数据评估 | 数据过于简单，指标虚高 | 内置难度旋钮；并用公开真实数据集独立验证 |

**需求优先级**：① 能跑起来并且能复现（否则一切无意义）→ ② 判得准且误报可控 →
③ 能演示、能解释（运维要看得懂）→ ④ 能被别人复用。

### 2.2 总体方案

```
                    ┌────────────────────────────────────────────┐
                    │  数据层                                     │
                    │  · 自研仿真流量生成器（8 类，双 schema 输出） │
                    │  · 公开真实数据集接入（--source real）        │
                    └───────────────┬────────────────────────────┘
                                    │ 逐条流记录（时间有序）
                    ┌───────────────▼────────────────────────────┐
                    │  预处理层                                   │
                    │  · 按列名自动识别标签/特征（无硬编码索引）    │
                    │  · 去重、去空、去无穷值                      │
                    │  · 切分：时序切分（连续采集）| 按组切分（防泄漏）│
                    │  · 仅用训练集拟合标准化器（防泄漏）           │
                    │  · 滑动窗口：T 条连续流 → (N, T, F) 张量      │
                    └───────────────┬────────────────────────────┘
                                    │
                    ┌───────────────▼────────────────────────────┐
                    │  模型层：CNN + BiLSTM 双分支并行              │
                    │  CNN 分支（膨胀卷积）→ 局部模式               │
                    │  BiLSTM 分支 → 时序依赖 → 注意力池化          │
                    │  拼接 → 多分类头 + 二分类头（多任务联合损失）  │
                    └───────────────┬────────────────────────────┘
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
┌───────────────┐        ┌──────────────────┐        ┌──────────────────┐
│ 评估层         │        │ 可视化层          │        │ 演示层            │
│ 多分类/二分类/  │        │ 9 类图表自动生成   │        │ 实时检测大屏       │
│ 在线告警级      │        │ 训练曲线/混淆矩阵/  │        │ 回放真实预测+注入  │
│ 消融/漂移/集成  │        │ ROC-PR/时间轴/注意力│        │ 攻击+阈值现场调节  │
└───────────────┘        └──────────────────┘        └──────────────────┘
```

**输入输出**：输入为逐条流记录（时间有序，含统计特征与标签）；输出为每条记录所属攻击类型、
正常/异常判定、异常概率，以及窗口级告警结论。

## 三、AI 技术与开源及第三方资源选择

### 3.1 AI 技术作用

| AI 技术 | 在作品中的具体作用 | 为什么必须用 AI | 如何验证输出 |
|---|---|---|---|
| CNN（一维膨胀卷积） | 从"相邻若干条流"中提取局部组合模式（突发 SYN、等间隔心跳） | 攻击常表现为**多步组合模式**，单条流不可判 | 消融实验（去掉时序分支指标下降） |
| BiLSTM | 对窗口内的时间依赖双向建模（攻击的起始—持续—演化） | 攻击有演化过程，单向或无序模型抓不住 | 消融实验 + 在线片段召回率 |
| 注意力池化 | 对时间步加权，输出"哪几条流最可疑"的热力图 | 运维需要告警依据，不能只给一个概率 | 注意力热力图 + 隐患样本人工核对 |
| 多任务双头 | 同时输出攻击类型（多分类）与正常/异常（二分类） | 业务既要"是不是攻击"也要"是什么攻击"；联合训练可互相正则 | 两套指标分别报告 |
| 类别加权 | 逆频加权，缓解攻击样本稀少 | 不加权模型会退化为"全判正常" | 逐类召回率明细表 |

### 3.2 开源及第三方资源选择

完整清单见附件《开源及第三方资源使用清单》。选型依据：

- **TensorFlow/Keras**：生态成熟、CPU 版即可训练本规模模型；模型可保存为 `.keras` 便于部署；
- **scikit-learn**：评估指标口径标准、便于引入传统机器学习基线做对照；
- **pandas/NumPy**：真实数据集清洗与窗口构造；
- **matplotlib/seaborn**：论文级图表；
- **Flask**：演示服务零前端依赖，**完全离线可用**（比赛现场无网络也能演示）。

**自主开发边界**：所有业务代码（生成器、清洗与滑窗、模型构建与训练、评估体系、
可视化、演示服务、工具链、文档）均为团队自主编写；第三方库仅作为依赖被调用，未修改其源码。

### 3.3 融合方式

作品不是"调用通用模型接口"或"简单部署现有项目"：**AI 模型是核心功能本身**（流量的判别边界由模型学习），
而开源生态提供了训练框架、评估工具与可视化基础。相较上游 demo 的实质改进包括：

1. **建模方式**：由"把 1280 维特征硬切成 10 个假时间步"改为**真实滑动窗口**；
2. **评测方法**：由"随机切分 + 测试集当验证集 + 硬标签算 AUC"改为
   **时序切分 + purge 间隙 + 独立验证集 + 概率矩阵 OvR 宏平均**；
3. **数据来源**：由"硬编码他人机器上的数据集路径"改为**自带生成器 + 一键接入真实公开数据**；
4. **工程能力**：新增一键复现流水线、36 项验收自检、9 类图表、离线演示大屏与 8 个工具脚本。

### 4.2 关键实现

**（1）滑动窗口与真正的时序建模。** 输入为 `(T, F)`：T 条连续流记录 × F 维流特征。
窗口只在"片段内部"构建，跨片段（标签混合）窗口被丢弃，避免把攻击起始点混进正常窗口。

**（2）双分支并行结构。** CNN 分支使用**膨胀卷积**而非池化——因为池化会把 10 个时间步压缩成 2 个，
使 BiLSTM 的时序建模名存实亡（这是开发过程中真实踩到的坑，串行结构下混合模型反而跑不过单分支）。
两分支各自池化后拼接，交给分类头自行权衡。

**（3）多任务双头损失。** `L = CE(多分类) + 0.3 × BCE(二分类)`。
多分类头用 `sparse_categorical_crossentropy`（整数标签），二分类头用 `binary_crossentropy`，
并配合逆频类别权重（通过 `sample_weight` 适配多头模型）。

**（4）防泄漏的切分与预处理。** 支持两种切分：
- **时序切分**（默认）：按时间顺序切分训练/验证/测试，边界留 purge 间隙；
- **按组切分**：对"分块发布"的公开数据集（正常块+攻击块）或需防会话泄漏的场景，
  按会话（Flow ID）分组切分，同组数据只能进同一子集。
标准化器**只在训练集拟合**。

**（5）数据生成器的物理量自洽。** 生成器先产生"流记录的物理事实"（包数、字节数、时长、
标志位、到达间隔、活跃/空闲时间），再渲染成数据集列，因此
`Flow Packets/s = 总包数 / 时长`、`平均包长 = 总字节 / 总包数` 等关系恒成立
（验收自检实测相对误差 0.00e+00）。

**（6）难度可控。** 生成器提供三个旋钮：`overlap_ratio`（与最易混类混合的困难样本比例）、
`stealth_ratio/stealth_mix`（隐蔽型攻击片段——片段内混入大量正常样貌的流，单条流不可判、
必须靠窗口聚合识别）、`label_noise`（标注噪声）。

|---|---|
| 多分类准确率 | **0.9903 ± 0.0005** |
| 多分类宏平均 F1 | **0.9849 ± 0.0009** |
| 二分类 F1 | 0.9853 ± 0.0012 |
| 二分类 ROC-AUC | **0.9994 ± 0.0002** |
| TPR@FPR=1% / 0.1% | 0.9937 / 0.9739 |
| 在线攻击片段召回 | **100%（24/24）** |
| 平均告警时延 / P95 | **6.7 ms / 25.6 ms** |
| 误报率 | **14.8 次/小时** |

**（2）消融与基线对比（宏平均 F1，3 种子均值）**

| 实验组 | 宏 F1 | 参数量 | 结论 |
|---|---|---|---|
| CNN+BiLSTM 双分支（本作品主模型） | **0.9849 ± 0.0009** | 151k | 主方案 |
| 仅 BiLSTM 分支 | 0.9876 ± 0.0013 | 96k | **与主模型持平（差异小于种子波动）** |
| 仅全连接（MLP） | 0.9644 ± 0.0025 | 118k | ↓2.1 pt |
| 仅 CNN 分支 | 0.9429 ± 0.0029 | 65k | **↓4.2 pt，时序分支是主要贡献者** |
| 逻辑回归 / 随机森林 / 极端随机树 | 0.9521 / 0.8783 / 0.8541 | — | 传统基线明显更低 |

> **如实说明**：在本数据集上，双分支混合模型与单独 BiLSTM 分支的差异小于随机种子波动，
> 即**时序分支是主要贡献者、CNN 分支增益不显著**（概率集成同样未超过单独 BiLSTM）。
> 我们认为这本身是有价值的结论：对流统计量这类"已经聚合过"的特征，循环结构比卷积结构更关键。

**（3）窗口长度消融：本作品最重要的超参数（新增实验）**

窗口长度 T 决定"模型一次判定能看到多少条历史流记录"。固定数据、固定步长（stride=5）、固定训练轮数（25 epoch），
对 3 种结构 × 3 种窗口长度做全交叉实验：

| T | 混合模型（本作品）宏 F1 | 仅 CNN 分支 | 仅 BiLSTM 分支 | 混合 − 最好单分支 | 误报（次/小时） |
|---|---|---|---|---|---|
| 10 | 0.9772 | 0.9415 | 0.9886 | −0.0114 | 28.31 |
| 16 | 0.9940 | 0.9670 | 0.9973 | −0.0033 | 9.22 |
| 24 | **0.9970** | 0.9813 | 0.9977 | **−0.0007** | **3.29** |

**三条结论（均已写成可复现实验）**：

1. **窗口越长，判别越准**：宏 F1 由 0.9772（T=10）提升到 0.9970（T=24）；
2. **误报率随窗口长度断崖式下降**：28.31 → 3.29 次/小时（**降低 88%**）。
   这是部署侧最有价值的发现：**多给模型一点上下文，运维少受 8 倍打扰**；
3. **卷积分支的增益随窗口变长单调收敛**：混合模型相对最好单分支的差距由 −0.0114（T=10）
   收敛到 −0.0007（T=24，已小于随机种子波动）。
   这**印证了"CNN 分支需要更长窗口才能体现价值"的假设**，
   也把原先"CNN 分支未体现增益"的负面结论，转化为**有数据支撑的机理解释**。

**稳健性核对**：窗口变长会带来窗口重叠（T=24、stride=5 时相邻窗口共享 19/24 条记录），
为此我们额外做了"决策步长加倍"的对照（T=24、stride=12）：宏 F1 **0.9975**、误报 5.27 次/小时，
**结论不变**，说明提升来自"更多历史上下文"而非窗口重叠。

**默认配置据此选定为 T=16**：在精度（0.994）与检测时延（需要等 16 条流记录才能出结论）之间取平衡；
T=24 可再提升约 0.3 个百分点，但时延增加 50%。这条权衡曲线已写进 README，供部署方按业务时延要求选择。

**（4）分布漂移鲁棒性（`drift_strength=0.35`）**

| 模型 | 宏 F1（同分布） | 宏 F1（漂移集） | 退化 |
|---|---|---|---|
| CNN+BiLSTM（主模型） | 0.9839 | 0.9763 | **−0.8%** |
| 仅 BiLSTM | 0.9892 | 0.9800 | −0.9% |
| 逻辑回归 | 0.9521 | 0.9400 | −1.2% |
| 随机森林 | 0.8783 | 0.8110 | **−6.7%** |
| 极端随机树 | 0.8541 | 0.8094 | **−4.5%** |

时序深度模型退化约 1%，树模型退化 4.5%~6.7%。

**（4）真实公开数据集验证（inSDN 衍生集）**

数据规模：343,889 条真实流记录 × 84 列 → 清洗去重后 **184,747 条**（删除 35% 完全重复行）、65 维特征。

| 切分口径 | 测试集规模 | 多分类准确率 | 二分类 F1 | 二分类 ROC-AUC | 误报（次/小时） |
|---|---|---|---|---|---|
| ① 分层随机切分（按行） | 45,662 | 0.9998 | 0.9998 | 1.0000 | — |
| ② **按会话分组切分**（Flow ID，84,252 组） | 46,190 | **1.0000** | 1.0000 | 1.0000 | 0.00 |
| ③ 按组切分 + 近似重复去重（4 位有效数字） | 45,658 | 1.0000 | 1.0000 | 1.0000 | 0.00 |
| ④ 按组切分 + 近似重复去重（3 位有效数字，去重 20,993 条） | 40,941 | **0.9976** | 0.9986 | 0.9996 | 0.51 |

其中口径 ②③④ 都使用了**按会话分组切分**（同一 Flow ID 的流记录只进一个子集），
排除了"同一会话跨子集"的泄漏；口径 ④ 进一步删除了 2 万余条近似重复行，
是这个数据集上最严格的评估口径。

**（5）关于真实数据集高分的原因诊断（重要，如实披露）**

我们对"近乎满分"的结果做了两项独立诊断：

| 诊断项 | 结果 | 含义 |
|---|---|---|
| 测试样本到训练集最近邻距离（标准化空间）中位数 | 0.0004 | 绝大多数测试流在训练集里有"几乎一样"的邻居 |
| 距离 < 0.01（几乎完全相同）的测试样本占比 | **84.95%** | 数据集存在**大量近似重复** |
| 1-最近邻分类器（纯记忆式基线）准确率 | **0.9985** | 仅靠"找最像的一条"就能接近满分 |
| 本作品模型准确率 | 0.9998 | 与 1-NN 差距很小 → 该数据集上的高分主要来自数据冗余 |
| 单特征 + 单阈值（决策树桩） | 0.8051（最好单特征 0.8583） | 单特征不足；但 65 维联合空间高度可分 |
| 去近似重复 + 按组切分（最严口径） | 0.9976 / AUC 0.9996 | **即使消除冗余，该数据集仍高度可分** |

**结论（两点，都如实写入报告）**：
1. 该公开数据集**既冗余又确实高度可分**——它适合用来验证"流水线在真实数据上能否端到端跑通"，
   但**不能用来区分模型优劣，也不代表真实泛化能力**；
2. 因此我们把**自研的高难度仿真数据集作为主要评估基准**：在该数据集上随机森林仅 0.878、
   主模型 0.985，存在真实且可复现的差距，并配有消融、漂移与多种子统计。
   这恰好说明：**公开数据集的"高分"往往是数据本身造成的，而不是方法更强**。

**尚未达到的目标（如实说明）**：
① CNN 分支未体现出增益，需要更长窗口或原始包序列输入才能验证其价值；
② 未做对抗样本鲁棒性测试；
③ 未在真实生产网络长期运行，误报率（14.8 次/小时）在真实环境中的表现仍需现场标定。

## 八、总结与展望

### 8.1 项目总结

本作品把一份不可复现、评估口径有误的研究型 demo，重构为一个可复现、可演示、可复用的开源工程：
以滑动窗口 + CNN/BiLSTM 双分支 + 多任务双头为核心模型，配套自研流量生成器、三套评估口径、
9 类图表与离线演示大屏，并完成 36 项交付自检。在自研难度可控数据集上取得宏平均 F1 0.985、
攻击片段召回 100%、平均告警时延 6.7 ms、误报 14.8 次/小时；
在真实公开数据集上验证了流水线的端到端可用性，并**主动诊断并披露了该数据集 85% 的近似重复问题**。

团队收获：掌握了完整的"算法研究 → 工程化 → 可复现交付"链路，以及**如何识别和避免数据泄漏**。

未完成事项：CNN 分支增益未验证；对抗鲁棒性未测试；真实生产环境部署未验证。

### 8.2 后续计划

1. 功能优化：支持更长窗口与原始包序列输入，验证卷积分支价值；
2. 测试扩展：增加对抗样本、跨数据集泛化测试；接入 CI 自动回归；
3. 开放维护：补充英文文档、示例数据与 issue 模板；
4. 应用推广：与 SDN 控制器对接，形成"采集—检测—告警"闭环演示。
