## 1. 项目定位：解决什么问题

### 1.1 四个真实存在的痛点（都不是我们编的，是行业公开共识 + 本项目实测）

| 痛点 | 具体表现 | 本项目的实测证据 |
|---|---|---|
| **告警疲劳** | 阈值型/规则型检测误报多，值班员被迫"看不过来就关掉" | 同一模型在**不做连续确认**时误报 22.5 人时/天（≈2.8 个班次）；加"连续 3 窗口确认"后降到 **3.58 人时/天**，调窗口到 T=32 再降到 **0.11 次/小时** 【实测】`results/operating_point.md` |
| **未知攻击无法处理** | 模型只在已知类别上训练，遇到新形态会"自信地归到某个已知类" | 留出整类攻击时 **100% 被安上已知标签**；换成"未知形态"标记并在 1% 误报预算下标定后，可作为"要不要人工研判"的提示 【实测】`results/openset_report.md` |
| **账实不符** | 系统台账写"已下发"，交换机上其实什么都没发生 | 我们**抓到并修掉**了 4 处同类缺陷（含"只建 Meter 不限速""幂等吃掉升级""observe 也记已执行"）；现在有**下发后回读校验 + 失败回滚** 【实测】`tests/test_ryu_guard.py`（58 项）、`results/ryu_live_check.md` |
| **落地门槛高** | 商用方案依赖专用硬件/云、闭源不可复核 | 本作品 **CPU 单机可跑**（8 核、无 GPU）、**一条命令复现**、Apache-2.0 开源、**130 项自检 0 失败** 【实测】`results/acceptance_summary.json` |

### 1.2 解决思路（一句话讲清与"又一个 IDS"的区别）

> **检出只是起点**：我们交付的是"检测 → 分级 → 连续确认 → 处置 → 留痕 → 复盘回流"的**闭环**，
> 而且闭环里每一步都能被第三方用命令复现、用产物核对。

七层闭环（详见 `competition/06_检测与处置体系.md`）：采集 → 判定 → 分级 → 确认 → 处置 → 留痕 → 复盘回流。

### 1.3 现在到了哪一步（不夸大：设计态与实现态分开列）

* **已是可运行系统【实测】**：训练/评估/在线服务/大屏/控制器适配层/统一入口 `tools/cida.py`（8 个子命令）
* **已有回归保护【实测】**：单元 22 项 + Ryu 适配层 58 项 + pcap 58 项 + 交付自检 130 项，CI 工作流
* **已实测的边界【实测】**：真实 Ryu + 真实 OF1.3 线协议 19/19；控制平面闭环 1,364~1,918 条流/秒、p50 29.8 ms
* **仍是设计态/未做【如实】**：物理交换机与真实攻击流量未覆盖；真实生产环境长期运行未验证；
  漏报代价（影响面）未折算成业务损失；回流重训已自动化但**尚无生产数据积累**

## 2. 需求分析：谁需要、为什么是现在

### 2.1 目标用户分层（按"谁最痛、谁最可能先买单"排序）

| 层级 | 典型对象 | 他们的痛 | 我们提供的价值 | 触达难度 |
|---|---|---|---|---|
| **A. 已有 SDN/云网架构的关基与行业单位** | 政务云、金融数据中心、能源/交通专网 | 控制器侧只有流表统计，看不见包级细节；缺"控制器原生字段"的检测能力 | 直接吃 OpenFlow 流表统计即可检测（**不需要**在每台机器装探针）；控制器原生口径模型已实测（宏 F1 0.8148 基线、特征选择后可到 0.8536）【实测】`results/feature_selection.md` | 中（需合规与集成） |
| **B. 安全运营中心（SOC）** | 中大型企业 SOC、MSSP 服务商 | 告警疲劳 + 未知攻击无处放 + 处置无回读 | "观察池 + 待研判队列 + 人工回流 + 自动放松"把告警变成可运营的工作流；Prometheus 指标直接进现有监控 | 中 |
| **C. 安全产品厂商（OEM/集成）** | 需要快速补"AI 检测"能力的 NDR/防火墙/态势感知厂商 | 自研 AI 检测周期长、可解释性与合规材料难做 | 可集成模块（Apache-2.0）+ 完整证据链与验收自检，缩短其合规与投标准备 | 高（但单笔价值大） |
| **D. 教学与科研** | 网络空间安全专业课程、攻防演练靶场 | 需要"可复现、可解释、有真实数据"的教学案例 | 自研生成器 + 6 份真实数据集协议 + 130 项自检，学生可一条命令复现 | 低（先做口碑） |

### 2.2 为什么是现在（三条外部驱动 + 一条内部驱动）

1. **合规压力持续加码【公开数据】**：网络安全法体系与关键信息基础设施保护要求把"检测—处置—留痕"变成硬性动作，而不是可选项（相关政策梳理见 §4 引用）。
2. **AI 进入安全运营主赛道【公开数据】**：Gartner 2025 安全运营趋势把"AI 自主化与平台生态化"列为核心方向（解读见 §4 链接）。
3. **SOC 人力缺口是行业公开共识【公开数据】**：告警量增长快于人力增长，这是"自动化 + 可复核"类方案的直接需求来源（Gartner Hype Cycle for Security Operations 2025 见 §4）。
4. **内部驱动（本项目的独特处）【实测】**：我们实测到"误报从 8.56 次/小时压到 0.66 次/小时只改一个参数（窗口长度/确认次数），但代价是时延从 9.9 ms 涨到 18.1 ms"——
   这类**可量化的取舍**正是采购与运营最需要的东西，市面上多数材料只给"准确率 99%"。

## 3. 可行性分析

### 3.1 技术可行性（这一节全部是【实测】，每条都能复核）

| 能力 | 实测结论 | 产物 |
|---|---|---|
| 检出（合成域） | 宏 F1 **0.9940±0.0011**、片段召回 **100%**、逐类召回 80/80 | `results/summary.json` |
| 检出（真实公开数据） | inSDN 融合臂 TPR@FPR=1% **0.6311**；CIC-IDS2017 跨天未见攻击族 **0.2745**；告警级片段召回 **0.9231（36/39）** | `results/real_eval.md` |
| 工作点可解释 | 阈值×确认次数×窗口长度全枚举，输出 Pareto 表；工作点 0.90+确认 2 = 27.9 条告警/天、2.79 人时/天、16.1 ms | `results/operating_point.md`、`results/ops_impact.md` |
| 处置闭环 | 真实 `ryu-manager` + 真实 OF1.3 **19/19**；含**下发后回读校验**（带源 IP 匹配的回读请求、xid 配对、判定 `ok=true`、无误回滚） | `results/ryu_live_check.md` |
| 处置可靠性 | 幂等（5 次告警只下发 1 条）、升级不被幂等吃掉、回读失败回滚并**解开幂等窗口**以便重试 | `tests/test_ryu_guard.py`（58 项） |
| 未知攻击处理 | 留出整类攻击时给出"未知"标记；未知动作**永不直接封禁**（硬护栏：最高限速） | `results/openset_report.md`、`tests/test_core.py` |
| 对抗鲁棒性 | ε=0.3 PGD 逃逸率 **73%**（宏 F1 0.9930→0.4802）；**对抗训练收益 +0.1237 > 干净代价 −0.0069**，已内建为可选（默认关） | `results/adversarial_eval.md` |
| 漂移鲁棒性 | 深度时序模型退化 **≤0.16 个百分点**；树模型退化 **3.8~7.7 个百分点** | `results/drift_report.md` |

| 可复现 | **一条命令**跑完全流程；**130 项**交付自检 0 失败；三套测试 22/58/58；CI | `results/acceptance_summary.json` |

### 3.2 技术可行性里"我们自己证伪过"的部分（诚实披露，也是本作品的方法论卖点）

| 曾经的假设 | 实测结论 | 产物 |
|---|---|---|
| "CNN 分支一定带来增益" | 窗口做到 T=48、困难基准、包级表示、与已发表方法同口径对标 **四路互相印证：卷积始终无正增益**（逐种子配对 6/6 为负） | `results/window_ablation.md`、`results/hard_ablation.md` |
| "域随机化能解决跨域" | 被实测**否定**；有效路径是少量目标域标注微调（500 窗口 → 召回 0.4257） | `results/domain_randomization.md` |
| "特征选择一定有用" | 控制器 17 列口径上有用（宏 F1 0.8148→0.8536、误报 57→36 次/小时），**富特征口径上无增益**——收益是有条件的 | `results/feature_selection.md` |
| "对抗样本可以用熵阈值拦" | 熵阈值拦不住（对抗样本熵并不显著升高） | `results/adversarial_eval.md` |

> 为什么把这些写进策划书：它们直接决定**商业承诺的边界**——如果我们不知道自己在哪儿不work，
> 就没法给客户报一个负责任的 SLA。

### 3.3 工程与交付可行性

* **算力门槛低**【实测】：训练几十分钟（8 核 CPU）、推理 CPU 单机、**不需要 GPU**，可私有化部署在隔离网内。
* **数据合规**【实测】：6 份真实公开数据集的来源与许可已自动校验登记（`results/real_datasets.md`）；
  工程**不分发**数据集本体；样例数据为自研生成器产出。
* **可维护性**【实测】：`tools/cida.py` 统一入口（doctor/status/demo/guard/verify/inventory/config/retrain），
  配置四套机制已有单一视图与"设了但没人读"的漂移检测。
* **许可与开源**【实测】：Apache-2.0 + NOTICE；第三方资源清单 `competition/01_开源及第三方资源使用清单.md`。

### 3.4 可行性结论与"还没有资格说的话"

* **可以说**：检测与处置的核心链路已具备**可交付的工程形态**，且在真实控制器与真实线协议上跑通；
  工作点、误报、时延、人力成本之间的关系是**实测可算**的。
* **还不可以说**：不可以说"可直接替换现网 IDS/NDR"、"误报率 0"、"支持任意厂商交换机"、
  "已在生产环境稳定运行"——这些都需要现场部署与长期数据，我们没有。
  详见 `competition/06_检测与处置体系.md` §8 缺口清单（剩余项：漏报代价换算、真实环境覆盖差异）。

## 4. 市场分析

> ⚠️ 本节数字均为**第三方公开口径，本项目未做一手调研、未复核**。引用只用于说明"市场存在且增长"，
> **不作为财务预测依据**。真正的市场验证动作见 §4.5。

### 4.1 行业驱动（定性，三条）

1. **合规驱动**：网络安全法与关键信息基础设施保护要求下，"检测—处置—留痕"是必答题；
   审计留痕（我们的一行一条 JSON 台账 + 轮转 + 回读校验记录）正好对上这类要求。
2. **攻防态势驱动**：攻击自动化程度提高，未知形态与逃逸手段增多 → 需要**开集/新颖性**能力与**可回滚**的处置。
3. **运营效率驱动**：SOC 人力增长跟不上告警增长 → 需要把"人看告警"变成"人只看需要判断的少数"，
   我们实测的**观察池 + 待研判队列**就是这条思路的可运行实现。

### 4.2 市场规模（第三方口径 + 链接）

| 指标 | 数值 | 来源（未复核） |
|---|---|---|
| 全球 NDR（网络检测与响应）市场 | 2030 年约 **58.2 亿美元** | MarketsandMarkets 新闻稿，经 Yahoo Finance 转载：<https://finance.yahoo.com/news/network-detection-response-ndr-market-141500475.html> |
| 中国网络安全市场规模 | 2025 年**超 170 亿美元** | 中国高新网报道：<http://www.chinahightech.com/chanye/2025-03/26/content_314487.html> |
| 全球网络安全市场 | 2025 年约 **2150 亿美元**、同比 +14.7%（亚太贡献约 28% 增量） | 第三方报告聚合站（**可信度较低，仅作趋势参考**）：<https://m.sgpjbg.com.cn/news/7218543.html> |
| 安全运营技术成熟度与 AI 化趋势 | Gartner 2025 安全趋势解读 / Hype Cycle for Security Operations 2025 | <https://www.freebuf.com/articles/container/457063.html>、<https://www.msspalert.com/whitepaper/hype-cycle-for-security-operations-2025> |

**从这些数字能得到什么、不能得到什么**：
* 能得到：NDR/检测响应是个**几十亿美元量级且在增长**的赛道，值得投入；
* **不能**得到：我们自己的可服务市场（SAM/SOM）——那需要客户访谈与渠道数据，见下。

### 4.3 目标细分与切入点

* **首选切入（P0）**：**已有 SDN/云网架构、但控制器侧缺检测能力**的单位与集成商。
  理由：我们在这个口径上**已有可运行资产**（控制器原生 17/30 列特征、真实 Ryu 适配层、回读校验），
  而通用 NDR 厂商通常要求部署探针/引流，改造成本高。
* **次选（P1）**：SOC 的"未知攻击与漏报复盘"环节（观察池/研判队列/回流），以**附加模块**形式嵌入其现有 SIEM/SOAR。
* **暂不碰**：终端安全（EDR）、邮件安全、云工作负载保护——与我们的能力不匹配，进去就是送死。

### 4.4 竞争格局与差异化

| 类别 | 代表形态 | 它们的强项 | 它们在本场景的弱项 | 我们的差异化 |
|---|---|---|---|---|
| 商业 NDR/IDS 厂商 | 私有化 NDR、流量分析一体机 | 品牌、渠道、协议覆盖、服务团队 | 部署重（探针/引流）、闭源难复核、控制器侧支持弱 | **控制器原生字段即可检测**（无需探针）；开源可复核；处置带**回读校验与回滚** |
| 开源 IDS（Suricata/Zeek 类） | 规则/协议解析 | 成熟、免费、生态大 | 规则依赖特征更新，**未知形态**乏力；不负责处置闭环 | 机器学习+开集标记；**闭环**到处置与复盘 |
| SDN 控制器厂商自带安全模块 | 控制器插件 | 与控制器天然集成 | 多为 ACL/限速策略，检测能力有限 | 检测精度有实测与公开数据验证；工作点可算 |
| 云厂商安全服务 | 云内流量分析 | 云内集成好 | 跨云/私有化弱；黑盒 | 私有化、可离线、可审计 |

### 4.5 SAM/SOM 与市场验证计划（**这一节是【假设】，必须验证后才可对外引用**）

**测算公式（显式写出，避免"拍数"）**：

```
SAM = 目标单位数 × 单点年化预算
SOM = SAM × 可获取份额（受渠道与验证案例决定的系数）
```

| 变量 | 取值 | 性质 | 验证方式 |
|---|---|---|---|
| 目标单位数（中国，有 SDN/云网且有安全运营需求） | 待调研 | 【假设】 | 检索公开招标公告/行业白皮书；统计近 12 个月"SDN/云网安全检测"类招标数量 |
| 单点年化预算 | 待调研 | 【假设】 | 对 3~5 家潜在客户做访谈；查公开中标金额区间 |
| 可获取份额 | 待验证 | 【假设】 | 由渠道合作意向与试点案例数推算，**不用"我们技术好所以能拿 X%"这种拍法** |

**验证动作（3 个月内可完成，成本低）**：
1. **招标文本检索**：统计目标关键词的公开招标数量与金额区间（公开信息，1 周内可完成）。
2. **客户访谈**：至少 5 家（2 家关基、1 家云服务商、2 家安全集成商），问三件事：现状误报怎么处理、有没有把未知告警送人工的流程、可接受的价格带。
3. **渠道询价**：2 家集成商，验证 OEM/集成模式的可行性与分成预期。
4. **权威报告订阅/公开摘要**：用 IDC/Gartner 公开摘要核对趋势（只取公开部分，不买整本报告）。

> 结论（诚实版）：**市场方向可判断，市场规模不可引用**。所以本策划书不写 TAM/SAM/SOM 的具体金额，
> 只写测算口径与验证计划——评审若追问，我们能给出"怎么验证"，而不是一个查不到出处的数字。

### 5.2 定价锚点（避免凭空定价）

## 12. 合规、伦理与诚信边界

* **数据来源**：只用公开数据集（来源与许可自动校验登记，见 `results/real_datasets.md`）与自研生成数据；
  **不分发**数据集本体；样例抓包为自研生成（`samples/sample_capture.pcap`）。
* **匿名化**：对外材料不含本机路径、学校/学院/指导教师/LOGO 信息（自查清单 `competition/05_匿名化与合规自查清单.md`）。
* **自动化处置的伦理边界**：默认演练模式；未知形态**永不直接封禁**；处置带有效期；白名单优先；
  写接口需鉴权；每次处置与每次回读校验都留痕。
* **不说的话（能力边界声明）**：不说"零误报"、不说"支持任意厂商交换机"、不说"已在生产环境长期稳定运行"、
  不说"能检出所有未知攻击"、不说"漏报代价已折算成业务损失"。
* **本策划书自身的三类标注**（实测/公开数据/假设）就是诚信边界的执行方式。
