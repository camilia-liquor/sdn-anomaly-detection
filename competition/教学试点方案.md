# 《网络攻防》实验课教学试点方案

> 用途：为申报书「（七）应用效果」提供**真实教学试点数据**（评分规则要求"教学试点数据/科研效率证明，数据真实有效"）。
> 配套材料：`教学试点问卷.md`（前测/后测 + 满意度问卷）、`教学试点数据采集表.xlsx`（数据录入）、`tools/pilot_analysis.py`（一键出统计表与图）。

## 1. 试点基本信息

| 项目 | 内容 |
|---|---|
| 试点课程 | 《网络攻防》（或《入侵检测》《网络安全》） |
| 试点对象 | 一个教学班，建议 30~40 人（同班单组前后测设计） |
| 课时 | 2 学时（90 分钟） |
| 环境 | 1 台教师机（运行平台+大屏演示）+ 学生分组使用实训机（Windows/Linux 均可，平台已支持无 Linux 环境联调） |
| 分组 | 每 2 人 1 组（18 组左右），组内分工：一人操作、一人记录 |
| 前置知识 | 已修完《计算机网络》或《网络安全基础》，了解 TCP/IP 与基本 DDoS 概念 |

## 2. 试点目标（对应评分项）

1. **教学效果**：前测/后测对比，验证平台对"入侵检测原理、DDoS 攻击特征、误报与漏报"等知识点的掌握提升；
2. **实验效率**：统计单次实验完成时间，与传统真实网络攻防实验（需专用设备、需隔离环境、常因环境问题返工）对比；
3. **平台评价**：易用性、安全性、可复现性、教学帮助程度（李克特 5 级量表）；
4. **可推广性**：采集"是否愿意在后续课程继续使用""是否推荐给其他课程"两项意向。

## 3. 课时安排（90 分钟）

| 时段 | 环节 | 内容 | 产出 |
|---|---|---|---|
| 0–10 min | 前测 | 闭卷填答《前测卷》（10 题） | 每人前测得分 |
| 10–25 min | 讲解与演示 | 教师演示：SDN 三层架构、流表统计采集、检测流程 | — |
| 25–45 min | 实验一·观察正常流量 | 学生启动拓扑，生成正常流量（ping/iperf/wget），观察控制器采集到的流表特征 | 实验记录（正常时段的特征画像） |
| 45–70 min | 实验二·发起攻击并观察闭环 | 学生用 hping3 发起 SYN Flood / UDP Flood，观察：告警产生 → 流表下发 → 攻击流量回落 | 实验记录（告警条数、处置动作、回落耗时） |
| 70–80 min | 实验三·读报告、讲边界 | 查看检测报告；教师讲解"误报/漏报""为什么同域高分不代表跨环境可用""为什么要做目标域标定" | 课堂讨论记录 |
| 80–90 min | 后测 + 问卷 | 填答《后测卷》（与前测同题）+《满意度问卷》 | 每人后测得分 + 问卷 |

**降级预案**：若实训机资源不足或 Mininet 启动异常，改为**教师机回放预生成数据**（平台内置回放功能），保证 90 分钟内一定拿到完整的"告警→处置"链路演示，学生仍可完成实验记录。

## 4. 数据采集流程（务必按此执行，否则数据不可用）

| 步骤 | 操作 | 责任人 | 备注 |
|---|---|---|---|
| S1 | 课前发放《知情同意与匿名说明》，说明数据仅用于教学研究、匿名处理 | 教师 | 不愿参与的学生仍上课，数据不纳入统计 |
| S2 | 每位学生分配一个**匿名编号**（如 S01…S40），与姓名的对应表由教师单独保管、不随数据提交 | 教师 | 满足"学习者信息脱敏"要求 |
| S3 | 前测卷收齐后**当场密封**，后测卷同题同难度 | 助教 | 防止后测受前测影响 |
| S4 | 实验期间由每组记录员填写《实验记录》（告警条数、处置动作、回落耗时） | 学生 | 教师抽查 |
| S5 | 后测与问卷当场回收 | 助教 | 问卷不留姓名，只填匿名编号 |
| S6 | 数据录入 `教学试点数据采集表.xlsx`（只录匿名编号） | 助教 | 双人核对一次 |
| S7 | 运行 `python tools/pilot_analysis.py --xlsx competition/教学试点数据采集表.xlsx` 生成统计与图表 | 队长 | 输出可直接粘进申报书 |

## 5. 伦理与合规（评分规则第 6 条硬要求）

- 自愿参与：明确告知可随时退出，不影响课程成绩；
- 匿名化：**只保留匿名编号**，姓名对照表不进提交材料、不公开；
- 数据用途：仅用于本次竞赛的教学效果统计，不作他用；
- 不采集敏感个人信息（不采集身份证号、联系方式、成绩排名等）；
- 若需公开原始数据，须再次征得学生同意，且只公开匿名化后的表格。

## 6. 预期指标与判读口径（事前写死，避免事后挑数）

| 指标 | 计算方式 | 合格线（事前约定） |
|---|---|---|
| 知识点掌握提升 | 后测均分 − 前测均分（配对） | ≥ 15 分（百分制）视为显著提升 |
| 统计显著性 | 配对 t 检验（不满足正态则用 Wilcoxon 符号秩） | p < 0.05 |
| 效应量 | Cohen's d（配对） | ≥ 0.8 视为大效应 |
| 实验完成率 | 完成实验二全部步骤的人数 / 参与人数 | ≥ 90% |
| 平均完成时间 | 实验一至实验三的总耗时（分钟） | 与传统方式对比，目标缩短 ≥ 30% |
| 平台满意度 | 满意度问卷总均分（5 级） | ≥ 4.0 |
| 继续使用意愿 | 对应题项均分 | ≥ 4.0 |

**说明**：以上合格线在试点**之前**确定，试点后不得因结果不理想而修改判读口径（与工程里"事前写死判据"的纪律一致）。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 实训机性能不足 | 降到"教师机回放 + 学生提交实验记录"；或分组轮换上台操作 |
| 攻击流量影响校园网 | 全程在虚拟拓扑内，攻击目标为虚拟主机，不出实训机房；不接入真实校园网 |
| 学生操作差异大导致耗时不可比 | 统一提供步骤清单；记录员按步骤打勾，未完成步骤单独标注 |
| 后测作弊 | 后测当场收卷；题目顺序打乱 |
| 数据不足（参与人数少） | 可跨两个班累积；报告中如实写明参与人数 |

## 8. 试点结束后要交出的三样东西

1. **统计表**（前测/后测/提升/显著性/效应量/完成率/耗时/满意度）—— 由 `pilot_analysis.py` 直接生成；
2. **学生与教师反馈摘录**（3~5 条，匿名）；
3. **实验现场照片 2~3 张**（不出现学生正脸，或经同意）。
