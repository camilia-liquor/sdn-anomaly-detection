## 一、作品概述

### 1.1 背景与问题

SDN 控制器天然掌握全网流表统计，不必部署主机探针即可观察流量级攻击（DDoS、扫描、暴破、僵尸网络心跳）。落地三层障碍：① 识别靠人工规则，阈值凭经验、滞后于手法变化；② 研究型成果不可用（数据泄漏——随机切分连续流量；口径错误——多分类用二分类损失、硬标签算 AUC）；③ 不可复现＝不可信（路径硬编码、种子不固定、标准化器不落盘）。

用户与场景：校园网/企业网中负责 SDN 控制器运维的网络与安全工程师。要解决的问题：把跑不起来的研究型 demo 变成一条命令可复现、可现场演示、可被他人复用的开源工程，并逐条修掉数据泄漏与评估错误。

### 1.2 目标、参赛方向与作品形态

方向：开源项目改进与生态贡献（兼"开源赋能的 AI 应用创新"）——对上游 demo 二次开发、功能增强、测试与文档建设、问题修复。形态：Python 工程 + 工具链 + 常驻在线检测服务 + Ryu 控制器适配层 + 离线演示大屏。

## 二、需求分析与总体方案

### 2.1 需求分析

安全运营最痛的不是"检不出"，而是"报太多"：2025 年 SANS 调查显示 73% 的组织把误报列为威胁检测第一大挑战，超过 60% 频繁遇到误报——告警疲劳本身就是安全风险。

| 需求 | 应对 |
|---|---|
| ① 误报可控：按误报预算选工作点 | 三旋钮 Pareto 表：误报 8.56 → 0.66 次/小时，召回保持 100% |
| ② 漏报要低 | 片段召回 100%（24/24），攻击类漏报 0 |
| ③ 时延可接受、普通 CPU 能落地 | 平均时延 18.4 ms、单窗口 p50 0.92 ms；批量 ≈13.6 万条流/秒；闭环 1,364~1,918 条流/秒、p50 约 30 ms |
| ④ 误报要换算成人力 | 27.9 条告警/天、2.79 人工小时/天；不做确认则超出一个班次 |
| ⑤ 要能处置，不只是报警 | observe/throttle/block + 白名单 + 演练模式 + 处置过期 + 审计台账 |
| ⑥ 可复现、可复用 | 一条命令复现 + 130 项自检（含接口实调）+ Apache-2.0 |

### 2.2 总体方案

```
① 数据层   自研仿真生成器（8 类/双 schema）｜真实数据接入（--source real）
② 预处理层 列名自动识别 → 去重去空 → 时序切分｜按会话分组切分（防泄漏）→ 仅训练集拟合标准化 → 滑窗 (N,T,F)
③ 模型层   CNN 膨胀卷积 ‖ BiLSTM + 注意力池化 → 拼接 → 多分类头 + 二分类头（多任务联合损失）
④ 评估层   三套口径 + 消融/漂移/集成 + 工作点 Pareto + 运维工时换算；12 类图表
⑤ 服务层★  在线检测：滑窗 + 阈值 + 连续确认 + 处置策略 + 白名单 + 演练 + 审计台账 + Prometheus + 策略热更新
⑥ 控制平面 Ryu 适配层：OpenFlow 流表统计 → 判定 → 下发限速/阻断（默认演练/白名单/处置过期）
```

输入输出：输入逐条流记录（时间有序）；输出攻击类型、异常概率与窗口级告警结论，服务形态下输出告警事件与处置建议并可下发带有效期的 OpenFlow 规则。两种形态、同一套代码与模型：离线 `run_all.py`；在线 `app/app.py` 常驻 `/api/detect` + `ryu_guard.py` 完成"采集—判定—处置"闭环；两者共用同一份 `data/processed` 与模型产物，演示、指标、在线判定永远同源。

**方法原理（为什么是 CNN + BiLSTM、为什么这样结合）**

判定单元是 **T=16 条时间连续的流**堆成的 (T,F) 张量（单条流看不出攻击形态，攻击的"形状"分布在相邻若干条流上）。
它同时要求两种能力，对应的两类网络归纳偏置互补，因此并行两路：

- **CNN（抓局部形状）**：局部连接 + 权值共享，一维卷积 `h_t = φ(Σ_τ w_τ·x_{t+τ} + b)` 在时间轴滑动。
  适合流量的三点理由：① 局部性——扫描/暴破/洪泛都有可辨识的局部形状；② 参数共享 → **平移不变**，
  攻击出现在窗口开头还是结尾都能认；③ 参数效率高（本分支仅 6.5 万参数）。
  工程细节：**不做池化、改用膨胀卷积**（d=1/2/4，三层感受野覆盖 15 步）——池化会把时间步压没、永久损失时序信息。
- **BiLSTM（抓长程依赖与双向上下文）**：朴素 RNN 有梯度消失/爆炸，学不到长依赖；LSTM 用**记忆单元 + 三个门**
  （遗忘 `f_t`、输入 `i_t`、输出 `o_t`），靠 `c_t = f_t⊙c_{t-1} + i_t⊙c̃_t` 这条**加法通路**让梯度近乎无损回传，
  网络自己学会"该记住什么、该忘什么"；BiLSTM 再正反各跑一遍并拼接，每个位置同时看到左右上下文。
  **双向不构成泄漏**：判定单元是**已完整到达的窗口**，窗口之外的真正未来从未参与；代价是时延等于一个窗口
  （实测平均 18.4 ms），这条权衡写进了工作点选择让用户自己选。
- **为什么"并行"而不是"串行"**：串行（CNN→池化→LSTM）会让 LSTM 拿到已经被压缩过的序列，本作品实测串行版本
  **低于任一单分支**；并行则两路都看未被破坏的原始序列，各自注意力池化后拼接，由网络自己决定信任哪一路。
  **如实交代**：并行融合在本数据集上**没有正增益**（结构消融持平、困难基准 6/6 配对为负、外部对标里单一 LSTM 略高），
  三个独立实验互相印证；它的价值是相对纯 CNN 的压倒性优势（+0.026 宏 F1、误报 13.60→0.55 次/小时）与统一骨架。
- **注意力池化**：`α_t = softmax(tanh(W_a h_t))`、`z = Σ α_t h_t`。既聚合又不丢"哪几步关键"，
  且 `α` 可直接出图给运维看（大屏的注意力热力图即它）。**多任务双头**：多分类头（8 类）+
  二分类头（是否攻击，损失权重 0.3）；告警阈值挂在二分类头、类别名由多分类头给，两者解耦后阈值标定更稳，
  实测二分类 ROC-AUC 0.9999。

| 模型环节 | 对标论文（PLO-BiLSTM） | 本作品 |
|---|---|---|
| 特征选择 | bPLO 二值化极光优化 | **已按论文复现**（含 PCA/PSO/不选对照） |
| 时序建模 | 2 层 BiLSTM(256)+FC(128) | CNN（膨胀卷积）‖ BiLSTM **并行双分支** |
| 时间轴聚合 | 取末状态 | **注意力池化**（可解释、可出图） |
| 输出头 | 单头多分类 | **多任务双头**（多分类 + 二分类） |
| 评估口径 | Accuracy/Precision/Recall/F1，7:3 随机划分 | 宏 F1 + 在线口径（片段召回/时延/误报·小时），时序切分 + purge gap |
| 处置能力 | 无（离线建模） | Ryu 适配层 + 策略/白名单/演练/审计 + Prometheus |

## 三、AI 技术与开源及第三方资源选择

### 3.1 AI 技术作用

| AI 技术 | 作用与必要性 | 如何验证 |
|---|---|---|
| CNN（膨胀卷积） | 相邻流的局部组合模式（突发 SYN、等间隔心跳）；攻击是多步组合模式，单条流不可判 | 消融（去时序分支指标下降） |
| BiLSTM | 窗口内时间依赖双向建模；无序模型抓不住演化 | 消融 + 在线片段召回 |
| 注意力池化 | 时间步加权，给出"哪几条流最可疑"；运维要依据而非单个概率 | 热力图 + 错例人工核对 |
| 多任务双头 | 同时输出攻击类型与正常/异常；既要"是不是"也要"是什么" | 两套指标分别报告 |

前两行产出实验结论，中间四行产出可被调用的服务与可直接上手的演示——
有接口、策略、白名单、演练模式、审计台账、监控指标与部署文档。

### 4.2 关键实现

1. 滑窗与防泄漏：输入 `(T,F)`；窗口只在片段内构建，跨片段窗口丢弃；时序切分（边界留 purge）或按会话 Flow ID 分组；标准化器只在训练集拟合。
2. 双分支并行：CNN 用膨胀卷积而非池化（池化会把 10 个时间步压成 2 个，使 BiLSTM 时序建模名存实亡；串行结构跑不过单分支）。
3. 多任务双头损失：`L = CE(多分类) + 0.3 × BCE(二分类)` + 逆频类别权重（`sample_weight` 适配多头）。
4. 生成器物量自洽：先产生物理事实再渲染成列，故 `Flow Packets/s = 总包数/时长`、`平均包长 = 总字节/总包数` 恒成立（自检误差 0.00e+00）。
5. 难度可控：`overlap_ratio`、`stealth_ratio/stealth_mix`（隐蔽片段：混入大量正常样貌的流，单条不可判、必须窗口聚合）、`label_noise`。
6. 在线检测服务：`src/service.py` 的 `DetectionService`：长度 T 滑窗 → 按在线步长攒批推理 → 阈值判定 → 连续 N 窗超阈值才确认告警（N 可热更新）→ 给出 observe/throttle/block 建议 → 白名单过滤 → 演练模式（只记录不改流表）→ 每条告警写 JSONL 审计台账；暴露 `/api/policy`（阈值/确认次数/动作/白名单/演练模式免重启热更新）、`/api/stats`、`/metrics`（Prometheus 文本，可直接接入现有监控）。
7. 批量推理优化（约 43~60 倍提速来源）：最初每条流调一次 `model.predict()`，实测 p50 1,261 ms、仅 32 条流/秒——瓶颈是 Keras `predict()` 每次约 36 ms 的固定包装开销而非模型计算量；改为批内合并 + 直接调用推理图（失败回退 `keras_predict`）后 p50 约 30 ms、1,364~1,918 条流/秒，提速约 43~60 倍。先解决调用开销，再谈模型压缩。
8. 口径一致性校验（上线安全阀）：`artifacts/` 并存多口径模型（71 维完整流特征、17 维控制器原生、65 维真实数据），启动按优先级 + 输入形状校验逐个尝试，全部不符则拒绝启动并打印候选清单——宁可起不来也不给错误判定。

### 4.3 分工、过程与生成式 AI 使用说明

分工：队长（算法与实验）负责上游问题诊断、模型结构设计与训练/消融/漂移/集成实验；队员甲（工程与数据）负责仿真生成器、数据管线与切分协议、真实数据接入；队员乙（可视化与文档）负责演示大屏、12 类图表、文档与自检工具。

如实说明：混合模型与单独 BiLSTM 的差异小于随机种子波动——时序分支才是主要贡献者（仅 CNN 分支 ↓2.1 pt），概率集成同样只是持平。初期我们曾用「卷积差距随窗口变长单调收敛 ⇒ 需要更长上下文」解释这条负面结论，**该解释已被下文（4）的困难基准复测证伪**。

（3）窗口长度消融：把「卷积分支有没有用」测穿（做到 T=48，关键窗口补足 3 种子）

| T | 种子数 | 混合宏 F1 | 仅 CNN | 仅 BiLSTM | **混合 − 最好单分支** | 误报/小时 | 平均时延 |
|---|---|---|---|---|---|---|---|
| 10 | 1 | 0.9772 | 0.9415 | 0.9886 | −0.0114 | 28.31 | 6.6 ms |
| 16 | **3** | 0.9938 ± 0.0012 | 0.9727 ± 0.0059 | 0.9968 ± 0.0008 | **−0.0030** | 3.29 ± 5.14 | 17.1 ms |
| 24 | **3** | 0.9974 ± 0.0011 | 0.9791 ± 0.0020 | 0.9989 ± 0.0011 | **−0.0015** | 1.10 ± 1.90 | 24.3 ms |
| 32 | **3** | 0.9979 ± 0.0024 | 0.9840 ± 0.0018 | 0.9987 ± 0.0010 | **−0.0008** | **0.11 ± 0.19** | **35.4 ms** |
| 48 | 1 | 1.0000（饱和） | 0.9912 | 1.0000（饱和） | +0.0000 | 0.00 | 42.1 ms |

① **负面结论被「测穿」**：Δ 在每一个有置信区间的 T 上都是负的（−0.0030 / −0.0015 / −0.0008），只是收敛到 0、**从未转正**；T=48 双方打满 1.0000（天花板）后 Δ 归零已无意义。早期「卷积需要更长上下文」的解释**被证伪**。
> 诚实记录：T=32 单种子时 Δ 曾显示 **+0.0023**（像「终于转正」），补齐 3 种子后变 **−0.0008**（σ=0.0024）——那个正值来自 seed 0 恰是最好的那次。**单种子 + 边缘显著不能当结论。**
② **正面结论可直接部署**：误报随 T 下降（28.31 → **0.11 ± 0.19** 次/小时），而且**种子间波动从 14 倍（T=16：9.22/0.66/0.00）收敛到几乎为零（T=32：0.00/0.33/0.00）**——误报率本身飘 14 倍的系统是没法标定工作点的。**T=32 用约 26 ms 额外时延换掉约 84 倍误报，不动阈值、不动模型、只改输入形状。**
③ T≥32 精度已饱和 ⇒ 我们**另造一套困难基准把难度拉满后复测**，见（4）。

（4）困难基准复测：把难度拉满之后，卷积终于翻身了吗（本作品新增，`results/hard_ablation.md`）

（3）有一个天然反驳：**T≥32 双方都打满，是数据太简单，不是卷积没用。** 所以我们另造一套困难基准（数据与产物均与主实验隔离），把四个旋钮拉满——`overlap_ratio` 0.35→**0.70**、`stealth_ratio` 0.45→**0.80**、`stealth_mix` 0.45→**0.70**、`feature_noise` 0.05→**0.15**——再用完全相同的流程重测。**先证明难度真的上去了**（与架构无关的线性探针）：`(T,F)` 展平跑逻辑回归，窗口级宏 F1 从 **0.9807 降到 0.8658**；且**没有任何结构再打满**（最高宏 F1 **0.9891 < 1.0000**）。

| T（3 种子） | 困难 混合 | 困难 仅 CNN | 困难 仅 BiLSTM | **困难 Δ**（混合 − 最好单分支） |
|---|---|---|---|---|
| 16 | 0.9401 ± 0.0045 | 0.8263 ± 0.0497 | **0.9463 ± 0.0049** | −0.0061（−1.26σ） |
| 32 | 0.9794 ± 0.0014 | 0.8484 ± 0.0203 | **0.9891 ± 0.0049** | −0.0097（−1.99σ） |

单种子档同样为负（T=10 −0.0082、T=24 −0.0032）。**结论**：① 卷积**依然没有增益**——四个窗长 Δ 全 ≤ 0，最好单分支都是「仅 BiLSTM」，**逐种子配对 6/6 为负**（双侧 **p = 0.031**）；② **「需要更长上下文」被推翻**——简单基准 Δ 随 T **上升**（+0.00043/条窗口），困难基准 **−0.00003**、**T 最长档 Δ 反而最负**；③ 原因可解释：仅 CNN 最脆弱（T=32 低 **0.1356**），混合模型是**过拟合式增益**（151k vs 96k 参数）——流统计量把「每条流的聚合量」当时间步，卷积要找的局部组合模式已被特征工程压平。

> **最实用的一条**：难度翻倍后（同结构同 T=16）宏 F1 0.9938→0.9401（**−5.4 pt**）、误报 3.29→14.88 次/小时，**而攻击片段召回 1.0000→1.0000 不变**——**精度在退化，安全底线没有退化**。这正是本作品把「攻击片段召回」而非「宏 F1」列为首要指标的原因。
> **诚实声明**：困难档 `label_noise` 由建议值 0.05 下调为 **0.02**（`pure_only` 过滤使 0.05 时 T=32 只剩 18.6% 窗口、宏 F1 颗粒度噪声大于待检验的 Δ 量级）；**调整发生在全部训练之前、无任何模型结果作依据**，且难度未放松（线性探针 0.9807→0.8658），依据与全部数字见报告第 6 节。

（5）分布漂移鲁棒性（`drift_strength=0.35`）：T=16 下深度模型几乎免疫漂移（退化 ≤0.2%）——主模型 −0.16% ~ +0.04%，仅 BiLSTM −0.08%，仅 CNN +0.26%，逻辑回归 0.00%；树模型显著退化——随机森林 −7.7%、极端随机树 −3.8%。

（6）错误分析：3,513 个测试窗口，错误 17 个 / 0.48%；漏报（攻击被判为正常）0 个——8 类中 7 类错误率为 0，唯一错误来自 Normal（误报 17 个）；主要混淆对 Normal→BruteForce 9 次（52.9%），另有 Normal→DoS 4 次、Probe 3 次、WebAttack 1 次；错误样本异常概率中位数 0.844，正确样本 0.008；错例共同特征是包长显著偏小（z 分数低约 0.4~0.5）。结论：错误全是误报而非漏报，方向对安全场景可接受；误报集中在"小包 + 短连接"的正常流量被判为暴破/扫描类。

（7）推理性能基准：Keras `predict()` 批量 1 为 49.98 ms（含约 36 ms 包装开销）；直接调用推理图（生产路径）批量 1 为 p50 0.92 ms（P95 1.52 ms）、批量 256 为 0.022 ms（≈13.6 万条流/秒）。模型计算量极小，`predict()` 的固定调用开销才是瓶颈，按控制器采集周期攒批即可消除；按 10 秒采集周期计单周期约 136 万条流记录，普通 CPU 即可覆盖中小型校园网/企业网。

（8）工作点选择与运维工作量换算（核心设计）

把它硬塞进某个已知类别、还给出很高置信度？** 我们把**整类攻击从训练/验证中拿掉**（留出 U2R 与
留出 Botnet 两个场景 × 3 个种子），测试集保留该类作为"未知攻击"，阈值只在已知类上标定：

| 留出场景 | 不做拒识时会怎样（最危险的一组数据） | 未知检出率 UDR | 已知类宏 F1 代价 |
|---|---|---|---|
| **留出 U2R** | 100% 被安上已知标签：84% 判成 WebAttack、13% 判成 DoS；平均置信度 0.82、**42% 置信度 ≥0.9** | 1% 误报预算 **69.8%**；0.1% 预算 30.2% | 0.9931 → 0.9881（−0.5 pt） |
| **留出 Botnet** | 100% 被安上已知标签：**96% 判成 Normal** —— 攻击**连告警都不触发**，比错报成别的攻击更危险 | 1% 预算 **44.3%**；0.1% 预算 **0.9%** | 0.9931 → 0.9942（**无代价**） |

三条结论：① **不拒识的后果是"自信地把新攻击叫成老朋友"**（42%/74% 的未知窗口以 ≥0.9 置信度错判），
运维会按错误类型处置；② **拒识有效但强烈依赖"未知攻击与已知/正常流量有多像"**——机理独特的 U2R
在 1% 预算下能捞出 70%，而与正常流量形态接近的 Botnet 仅 44%、0.1% 预算下几乎失效（0.9%）；
**AUROC 会骗人**（三种 OOD 分数跨场景 AUROC 都在 0.978 左右，但低误报预算下的尾部差一个数量级）；
③ **拒识几乎不伤已知类**（宏 F1 反而略升），所以正确用法是**叠加而非替代**：二分类头负责"是不是攻击"，
OOD 分数负责"是不是已知类型"，未知告警进人工研判队列并回流训练集，形成「未知 → 已知」闭环。

**这条结论已落成运行时能力**：`tools/openset_calibrate.py` 在**正常窗口**上按误报预算标定阈值
（1% 预算 → 熵阈值 0.3914；此时正常被判未知 1.00%、已知攻击被判未知 0.30%），
通过 `/api/policy` 热更新 `unknown_threshold` 即可开启：熵超阈值的窗口显示为 `Unknown（未知形态）`，
**照常告警与处置**（攻击的发现能力不受影响），`/metrics` 同步暴露未知窗口数与阈值。
**未知占比本身就是一条免费的漂移指标**——突然升高通常意味着新攻击出现或流量分布变化。

（17）上线边界之二：跨域迁移的量化边界（完整实验见 `results/cross_dataset_report.md`）

除字段缺口外，我们还测了**最苛刻的一种上线边界**——把自研数据训练好的模型**零样本**直接推理真实 inSDN
（71 维特征按语义 100% 映射成功，全程只做推理、不用真实数据训练或重拟合）：跨域二分类 F1 由同域的 0.9986 掉到 **0.5629**，
即**零样本跨域不可用**。逐特征漂移诊断定位根因是**采集口径差异**（CICFlowMeter 的流切分/超时/子流定义）而非模型结构。

其中一条反直觉、但对部署方很有用的发现：**只重新拟合标准化器会把 ROC-AUC 从 0.6697 打到 0.4742**——
零样本那点排序能力有相当一部分来自"漂移幅度本身"造成的假信号（攻击行偏离合成分布更远，被误打误撞排到前面），
把量纲拉回目标域口径就消失了。**结论：跨域 AUC 高不能被当作"模型还能用"的证据。**
真正有效的是少量目标域标注（500 个窗口、3 秒微调分类头，1% 误报预算下召回 0.0006→0.4257）。
上一版给出的另一条建议——**用目标域统计量反向标定生成器参数（域随机化）**——本轮已实测，结论是**否定的**（见（18）⑤）。

### 5.3 未知攻击与漏报的处置闭环

评分要的"效果验证"不只问报得准不准，还问**报出来之后怎么办、没报出来怎么办**。本作品把判定做成三态而非两态：

| 状态 | 触发 | 动作 |
|---|---|---|
| 已知攻击 | 攻击概率 ≥ 阈值且连续确认 N 个窗口 | 按攻击类型走动作矩阵（洪泛类阻断、爆破/Web 类限速、C2 类先观察取证） |
| **未知形态** | 新颖性分数越过 `unknown_threshold` | **动作强制降级为限速**并自动进待研判队列；**硬护栏：未知分支不允许升级为阻断** |
| 正常但可疑 | 分数落在 `[0.5×阈值, 阈值)` | 进观察池留痕，供事后抽样复核 |

- **未知攻击的真实风险（开集实测）**：不做拒识时 **115/115** 个未知攻击窗口会被贴上已知类标签——留出 Botnet 时 **96% 被判为 Normal**、其中 74% 置信度还 ≥0.9，**连告警都不触发**。加拒识后 UDR 达 U2R **69.8%** / Botnet **44.3%**，已知攻击被误拒仅 0.4% / 0.5%（`results/openset_report.md`）。
- **"未知 → 已知"闭环（含一个必须说清的坑）**：未知告警带 `review_id` 进待研判队列 → 大屏「复核台」点选结论（`attack:<类别>` / `normal`）→ 结论写入 `results/review_feedback.jsonl`。**但光有结论训不了模型**：该文件只有 verdict 与分数、**没有特征**。因此进队列时会把窗口特征向量落盘到 `results/review_evidence.jsonl`（**自带 `feature_names` 保证列序**，并附流级定位字段），两者按 `review_id` 关联才拼得出训练样本。一键回流：`python tools/retrain_from_feedback.py`（`--retrain` 产出隔离在 `artifacts/feedback/` 的**候选模型**，不覆盖主模型；工具只认人工 verdict，回放数据自带的真实标签一律忽略并如实报数）。
- **漏报可回看**：每个窗口都进回看缓冲（分数、判定、是否未知），低置信窗口另进观察池并随附**流级定位字段**（五元组/协议/标签）；两者均有容量上界，长期运行不吃内存。此前判为正常的窗口是**零留痕**的。
- **运行期工程面**：告警、观察池、回看缓冲、研判队列全部有界（累计量走计数器）；审计台账、回流结论、研判证据三个 JSONL 按大小轮转并留备份；写接口可用 `CIDA_API_TOKEN` 加一层应用级鉴权，读接口保持开放以便大屏轮询。这些是"能连续跑几个月"的前提。
- **诚实边界**：`unknown_threshold` 默认关闭，须按标定 SOP 在**安静时段**标定后开启（反例：含攻击时段标定会把阈值推到 1.0、召回只剩 4%）；观察池与研判证据只保留**定位字段**而非全部 71 维特征（容量取舍）；回流的**触发**未自动化，仍需人工发起；候选模型替换主模型的动作尚未脚本化。

## 六、创新性与开放价值

### 6.1 创新性

| 上线边界 | 不讨论"字段取不到怎么办" | 两种特征口径都实测，把字段缺口量化为工作点代价 |
| 方法学 | 单次运行给结论 | 多种子均值±标准差 + 泄漏诊断 + 负面结论与容量边界如实披露 |

与签名型 IDS（Snort/Suricata/Zeek）相比：不依赖载荷、从流统计量学习，天然适配加密流量，误报由工作点选择系统化管理而非人工调规则。与公开数据集上的机器学习工作相比：修掉了随机切分与会话泄漏、报告在线告警级指标并给出 Pareto 表，还主动诊断出该数据集 85% 的近似重复问题。

## 八、总结与展望

### 8.1 项目总结

把一份不可复现、评估口径有误的研究型 demo，重构为可复现、可演示、可复用的开源工程：滑动窗口 + CNN/BiLSTM 双分支 + 多任务双头为核心模型，配套自研生成器、三套评估口径、12 类图表与离线演示大屏，完成 130 项交付自检（含 18 项单元测试 + 34 项 Ryu 适配层行为测试）。自研数据集上宏平均 F1 0.9940 ± 0.0011、片段召回 100%、平均告警时延 18.4 ms、误报 0.55 次/小时；通过窗口长度消融给出可直接部署的结论（窗口加长可再把误报降低 88%）；**并主动造一套困难基准把"卷积到底有没有用"测穿——卷积始终无增益（逐种子配对 6/6 为负，p=0.031），"需要更长上下文"的解释被证伪，且难度翻倍后精度掉 5.4 pt 而攻击片段召回仍是 100%**；在真实公开数据集上验证流水线端到端可用，主动诊断并披露其 85% 近似重复问题。团队收获：掌握"算法研究 → 工程化 → 可复现交付"完整链路，以及如何识别数据泄漏、如何诊断公开数据集的隐藏陷阱、**如何用与架构无关的探针证明"数据真的变难了"并如实保留自我否定过程**。未完成事项：CNN 分支仍无正向增益（需原始包序列输入验证）、对抗鲁棒性未测试、真实生产环境部署未验证。

### 8.2 后续计划

① 原始包序列/字节级输入（困难基准复测已排除"窗口不够长"这一解释，见实验（4）），继续验证卷积分支价值；② 增加对抗样本与跨数据集泛化测试，接入 CI 自动回归；③ 补充英文文档、示例数据与 issue 模板；④ 与真实 SDN 控制器对接，形成"采集—检测—告警"闭环演示。
