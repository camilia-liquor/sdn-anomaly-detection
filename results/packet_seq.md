# 包序列输入复研：把「卷积有没有用」放到包级表示上再问一次

> 本报告由 `tools/packet_seq.py` 生成，全部数字来自磁盘上的实测产物；包序列由流记录的物理事实**反构**（非真实抓包），与主实验使用**同一批 86,037 条流**。

## 0. 结论（先回答问题）

- 判定结果：mixed —— **部分改善**：不同序列长度上结论不一致，需更大规模或更多种子复现。
- 前 16 包：GAP_pkt = 0.0514（同数据对照 GAP=0.1354 → 比值 0.38、全量主实验 GAP=0.0239 → 比值 2.15）→ `mixed`（参照间不一致）；Δ = -0.0381（σ=0.0048，超出 1σ）；逐种子配对 3/3 为负，符号检验双侧 p=0.250
- 前 32 包：GAP_pkt = 0.0071（同数据对照 GAP=0.1354 → 比值 0.05、全量主实验 GAP=0.0239 → 比值 0.30）→ `activated`（两个参照一致）；Δ = 0.0155（σ=0.0082，超出 1σ）；逐种子配对 0/3 为负，符号检验双侧 p=0.250
- 前 64 包：GAP_pkt = 0.0557（同数据对照 GAP=0.1354 → 比值 0.41、全量主实验 GAP=0.0239 → 比值 2.33）→ `mixed`（参照间不一致）；Δ = 0.0282（σ=0.0093，超出 1σ）；逐种子配对 0/3 为负，符号检验双侧 p=0.250

### 两个参照基准为什么给出不同判定（必须讲清楚，不能挑好看的）

流级 GAP 有两个口径：**同数据对照**（同一批 24,000 条流、流级滑窗 T=16）与**全量主实验**（86,037 条流）。两者差 5.7 倍（0.1354 vs 0.0239），原因不是噪声，而是**CNN 单支对数据量明显更敏感**：24,000 条流时仅 CNN 宏 F1 只有 0.8325，86,037 条流时升到 0.9727（仅 BiLSTM 分别是 0.9679 / 0.9966）。

- 用**同数据对照**当参照（与包级实验完全可比的口径）：三个长度**全部**通过激活判据（比值 0.38 / 0.05 / 0.41）；
- 用**全量主实验**当参照（更严格）：只有 T=32 通过（0.30×），T=16 与 T=64 不通过（2.16× / 2.33×）——前者是因为 T=16 时混合模型仍被 BiLSTM 压制，后者是因为 T=64 的仅 CNN 单支有一次种子崩溃（种子 2 宏 F1 仅 0.1506，使该结构标准差达 0.135）。

**因此总判定写 `mixed`**：结论对参照口径敏感，两个口径都报，不挑对自己有利的那一个。

### 与流级实验最重要的差别（本次唯一的正面发现）

在流级表示上，混合模型**从未**在任何一个窗口长度上超过最好单分支（困难基准上逐种子配对 6/6 为负）。在包级表示上，**T=32 与 T=64 两个长度都出现了「混合模型在 3 个种子上全部优于最好单分支」**（Δ = +0.0155 / +0.0282，均超出 1σ 种子噪声；逐种子配对 3/3 为正）。这是全项目第一次观察到混合结构的正增益，方向与「卷积的局部模式在包级序列上才存在」一致。

> ⚠️ **但这个正增益出现在弱信号区间**：包级表示的绝对宏 F1 只有 0.31~0.39，远低于流级聚合表示的 0.968（两种表示的信息量本就不同，不可直接排名）。正确的读法是「**机理探测**：包级表示确实让卷积不再系统性吃亏」，**不能**读成「包级模型更好用」——后者需要另一套实验（原始报文 + 更多包特征 + 部署口径）验证。

## 1. 判据（事前写死，不事后挑标准）

- 记 GAP(表示) = macroF1(最好单分支) − macroF1(仅 CNN)，即「卷积单支落后多少」。
- `activated`：GAP_pkt ≤ 0.5 × GAP_flow；`not_activated`：GAP_pkt ≥ 1.0 × GAP_flow；其余为 `partial`。
- Δ = macroF1(混合) − macroF1(最好单分支)，|Δ| < 1σ（该序列长度自己的种子噪声）记为噪声内；另外给出**逐种子配对**差值（同种子下两个结构的差，把数据噪声消掉）与符号检验双侧 p。

## 5. 包序列是怎么造的（可复现，非真实抓包）

- 每条流取**前 N 个包**（不足则 padding，并置 `valid=0`）；
- 方向序列按该流双向包数比例抽样（首包必为正向）；包长按方向的均值/标准差抽样并按真实上下界裁剪；
- 间隔 = (时长 × 取包比例 ÷ (k−1)) × 对数正态抖动，并按该流 IAT 的上下界裁剪；累计时间归一化为 `rel_time`；
- TCP 标志位按该流各标志计数分摊到首包 / 末包 / 其后各包；
- 随机数逐流确定性（`default_rng(seed × 1000003 + 流序号)`）→ 完全可复现；
- 特征 8 列：pkt_len, direction, gap_us, rel_time, rel_pos, tcp_flags, is_first, valid；标准化只对连续列 ['pkt_len', 'gap_us', 'rel_time', 'rel_pos', 'tcp_flags'] 拟合（**只用训练集**）。

## 6. 局限（写清楚，不粉饰）

- **包序列是反构的，不是真实抓包**：它保留了流级的物理量（包数/时长/包长/间隔/标志位），但不含真实报文内容与主机行为细节；本实验只回答「同一架构在两种表示下卷积的相对价值是否改变」，**不能**读成包级模型的绝对能力。
- 每条流只取前 N 个包：对包数极大的洪泛类流（DDoS/DoS）而言，前 N 包是代表性切片，但不等价于整条流的完整行为。
- 包级与流级的**样本单位不同**（前者 = 一条流，后者 = 16 条流的窗口），因此两者的绝对宏 F1 不可直接排名，只有 **GAP / Δ 这类相对量**可比。
- 结论仍建立在仿真流量上；真实数据上的复现见 `results/cross_dataset.json`。
