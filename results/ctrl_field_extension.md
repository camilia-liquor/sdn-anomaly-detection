# 控制器原生字段扩展：字段缺口能补回多少

> 由 `tools/controller_fields.py` 生成。两个口径**同一批流**（同一次生成，只切 schema），结构/窗口/种子完全一致，因此差值可归因于字段。

## 0. 结论

- 17 列口径宏 F1 **0.8183 ± 0.0104**（17 个特征）→ 扩展口径 **0.9956 ± 0.0004**（30 个特征）
- Δ = **0.1772**，σ = 0.0104 → **✅ 超出种子噪声（字段确实补回了精度）**
- 与完整流特征口径（0.9940）的差距：17 列差 **0.1757** → 扩展后差 **-0.0016**

## 1. 扩展了哪些字段（逐条说明来源）

**① OFPFlowStats 直接给的（既有 17 列，原样保留）**：duration、packet_count、byte_count、match 字段（源/目的 IP、源/目的端口、ip_proto、icmp type/code）、idle/hard timeout、flags。

**② 单流一步派生**：`avg_pkt_size = byte_count / packet_count`。

**③ 控制器按轮询窗口做流表聚合得到**（Ryu 在同一 poll 周期能拿到全部流条目，可分组统计）：

| 字段 | 含义 / 为什么可推导 |
|---|---|
| `avg_pkt_size` | 字节数 ÷ 包数，一步除法可得 |
| `src_flow_count` | 同一源 IP 在窗口内的流条目数（流表分组计数） |
| `src_distinct_dst` | 同一源打过的不同目的 IP 数（横向移动/扫描线索） |
| `src_distinct_dport` | 同一源打过的不同目的端口数（**扫描的核心指标**） |
| `src_dport_entropy` | 同一源目的端口的分布熵（扫描 = 熵高且分散） |
| `src_short_flow_ratio` | 同一源里 duration < 1 s 的流占比（暴破/扫描 = 短流多） |
| `src_pkt_per_flow_mean` | 同一源每流平均包数（心跳/长连接 = 少而规律） |
| `src_new_flow_rate` | 同一源新建流速率（流/秒，洪泛与扫描都高） |
| `dst_flow_count` | 同一目的 IP 的流条目数 |
| `dst_distinct_src` | 打同一目的 IP 的不同源数（**DDoS 的核心指标**） |
| `dst_src_entropy` | 同一目的的源分布熵（分布式洪泛 = 熵高） |
| `table_flow_count` | 窗口内流表规模（攻击强度/表压力代理量） |
| `proto_share` | 该协议在窗口内的占比（协议构成变化） |

**④ 明确不可得（不伪造）**：

- TCP 标志位计数（SYN/ACK/FIN/RST/PSH/URG）
- 包长分布（mean/std/max/min/variance）
- 到达间隔 IAT 的均值/标准差/最大最小
- 头部长度、窗口大小等报文级字段
- 活跃/空闲周期（Active/Idle）统计
- subflow / bulk 统计

> 因此本扩展**不可能**追平 CICFlowMeter 的 84 列口径 —— 这不是实现问题，而是 OpenFlow 流表统计**本身不含**这些量。**字段缺口的正确回应是补可推导的聚合量 + 调工作点，而不是假装拿到了报文级信息。**

## 2. 逐运行结果

| 口径 | 种子 | 特征数 | 宏 F1 | 二分类 AUC | 参数量 | 预算 1.0 次/h 的工作点（阈值/确认/时延） |
|---|---|---|---|---|---|---|
| ctrl17 | 0 | 17 | 0.8068 | 0.9941 | 113,418 | 0.985 / 5 / 39.8 ms |
| ctrl17 | 1 | 17 | 0.8269 | 0.9943 | 113,418 | 0.985 / 2 / 20.8 ms |
| ctrl17 | 2 | 17 | 0.8213 | 0.9897 | 113,418 | 0.960 / 5 / 39.5 ms |
| ctrl_ext | 0 | 30 | 0.9958 | 1.0000 | 122,570 | 0.300 / 2 / 14.0 ms |
| ctrl_ext | 1 | 30 | 0.9958 | 1.0000 | 122,570 | 0.660 / 1 / 9.8 ms |
| ctrl_ext | 2 | 30 | 0.9951 | 1.0000 | 122,570 | 0.775 / 1 / 12.7 ms |

## 3. 工作点代价（判据 J2）

- 17 列：阈值 **0.985** + 确认 **5** → 召回 100%、误报 0.99 次/小时、平均时延 **39.8 ms**
- 扩展：阈值 **0.300** + 确认 **2** → 召回 100%、误报 0.99 次/小时、平均时延 **14.0 ms**

> 说明：这里的工作点是「**在同一误报预算下、召回保持 100% 的前提下时延最小**」的那一个，与 `tools/operating_point.py` 同一套口径；工作点越低说明同样的安全要求付出的代价越小。

## 4. 局限（写清楚，不粉饰）

- 聚合量是在**离线数据上按 60 秒滑动窗**离线复算的；真机上受轮询周期、流表老化（idle timeout）与统计延迟影响，数值会有偏差（方向不变）。
- `idle_timeout`/`hard_timeout`/`flags` 是**控制器配置值**，在单次实验里近似常数、对模型帮助有限；真实部署里它们随策略变化，可能带来额外信息。
- 端口是特征之一：真实 SDN 里可用，但会带来「按端口记忆」的风险（本工程默认在完整口径里丢弃端口，这里保留是因为控制器原生口径本来就带端口）。
- 单一种子之外的结论强度有限：每口径 3 个种子只够判「是否超过种子噪声」。

## 5. 复现命令

```powershell
python tools/controller_fields.py --scale 1.0 --epochs 25
```
