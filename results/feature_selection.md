## 0. 结论

- 特征选择**是否值得做**：相对「不选特征」，**只有部分口径有增益**（12 个配对单元里 9 正 / 3 负，符号检验 p=0.1460，平均 Δ宏F1=0.0172）。
- **四种方法谁最好**：按各口径各模型平均，none 0.9291；pca 0.9022；pso 0.9371；bplo 0.9464。
- **与直接对比对象（PSO）**：平均 Δ=0.0093（9 正 / 3 负，p=0.1460）。
- **降维效果**：bPLO 平均保留 **66%** 的特征（71 维→48 维；17 维→11 维），PSO 平均保留 48%。注意这不是「随便选」——见下面对式(3) 的分析。

### 分口径结论（**结论必须分开说，不能一句话概括**）

- **自研数据集（完整流特征口径）**：➖ 无显著差异 —— 宏平均 F1 0.9954 → **0.9953**（平均 Δ=-0.0001，3 正 / 3 负，p=1.0000）；误报从 0.38 次/时 → **0.38 次/时**
- **控制器原生字段口径（OpenFlow 流表统计）**：✅ bPLO 有效 —— 宏平均 F1 0.8629 → **0.8975**（平均 Δ=0.0346，6 正 / 0 负，p=0.0312）；误报从 57.05 次/时 → **36.26 次/时**

> 这条分口径结论是本实验最有信息量的部分：**特征选择不是万灵药** ——当特征已经是人工挑过、维度本来就低（控制器原生 17 列）时，特征选择对结果的影响反而**很大**（挑掉近一半维度会显著改变精度与误报）；而在高维富特征口径上，深度模型自己就能处理冗余，特征选择的收益被淹没在种子噪声里。这也直接回答了「论文的方法在我们场景下值不值得用」。

## 4. 与对标论文的关系（如实说明）

- **框架一致**：预处理 → 特征选择 → 时序模型分类 → 多指标评估 + 消融，本实验补齐了我们原来缺的「特征选择」环节。
- **数字不可直接比较**：论文用 CICIDS2017 / UNSW_2018_IoT_Botnet、7:3 随机划分、Min-max 归一化、Accuracy 为主指标；本项目用自研数据集 + 控制器原生字段口径、**时序切分 + purge gap**（防泄漏）、宏平均 F1 + 在线告警指标。数据集、划分方式与指标定义三处都不同，因此只能比「方法是否有效」这个结论，不能比绝对数值。
- **我们比论文更严的地方**：① 特征**只在训练集上选**（论文在全量数据上选，属选择偏差）；② 不做随机划分；③ 同时报在线口径（片段召回/时延/误报）。
- **我们与论文不同、且更弱的地方**：论文的 bPLO 用完整分类器算适应度，这里用代理分类器（算力约束，已如实标注）。

### 4.1 我们量化到的一条方法学观察：式(3) 会让二值化选择率系统性偏高

论文式(3) 的极光椭圆漫步项写作

```
AO = levy(d) × (Xavg(j) − X(i,j)) + LB + r1 × (UB − LB) / 2
```

在连续优化里，`LB + r1×(UB−LB)/2` 是一个「向搜索空间中点靠拢」的随机偏置，用来帮助跳出局部最优；但把它逐维加到每一个粒子上之后，粒子的坐标会带上一个**恒定的正漂移**。到了二值化环节（式(10)：`sigmoid(x)` 与随机数比大小），x 被整体推高就意味着**每一位被选中的概率都大于 0.5**，于是最优子集的规模会系统性偏大。
- 本实验实测：bPLO 平均保留 **66%** 的特征；自检（40 维里只有 6 维有效）上 bPLO 也保留了约 70% 的维度。
- 与此同时，抑制「选太多」的惩罚项 `beta×|R|/|D|` 在论文给定的权重下（beta=0.01）最多只能贡献 0.01 的适应度，而误差项系数 gamma=0.99 —— 惩罚强度不足以抵消这个漂移。
- **这不是实现 bug，而是按论文公式实现的必然结果**：我们的自检（`--self-test`）专门把这一点记录成「观测」而不是断言，避免为了好看去改实现；报告里也把 |R| 单列一列，让读者自行判断降维程度。这条观察对**任何**要做二值化群智能特征选择的人都有用。
