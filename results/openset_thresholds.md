# 未知标记阈值标定（把开集结论落成运行时旋钮）

数据来源：`predictions_windows_cnn_bilstm_main_s0.csv`（3,513 个窗口：正常 2,500、攻击 1,013）；新颖性分数：**entropy**。

标定口径：**阈值只在真实标签为 Normal 的窗口上取分位数**，对应三档误报预算。

| 误报预算 | 阈值 | 正常窗口被判「未知」（新增误报） | 已知攻击被判「未知」（丢细粒度标签） |
|---|---|---|---|
| 10% | 0.0236 | 10.00%（250 条） | 2.27%（23 条） |
| 1% | 0.3914 | 1.00%（25 条） | 0.30%（3 条） |
| 0.1% | 1.1985 | 0.12%（3 条） | 0.10%（1 条） |

**推荐**：误报预算 1% → 阈值 **0.3914**。

分数分布：正常窗口均值 0.0228（中位 0.0099、99 分位 0.3914）；攻击窗口均值 0.0050（中位 0.0001）。

## 怎么用

```bash
# 方式一：起服务时通过环境变量给定阈值（见 deploy/cida-detect.env）
set CIDA_UNKNOWN_THRESHOLD=0.3914

# 方式二：运行时热更新（不用重启）
curl -X POST http://127.0.0.1:5000/api/policy -H "Content-Type: application/json" -d "{\"unknown_threshold\": 0.3914}"

# 关闭未知标记：unknown_threshold 设为 0
```

打开后，超过阈值的窗口其判定类别会变成 `Unknown（未知攻击）`，并照常产生告警与处置建议（**攻击的发现能力不受影响**，只是不再给出细分类别）。

## ⚠️ 语义边界（必须和实验报告一起看）

生产模型**见过全部 8 类**，所以这个标记的含义是「**模型没见过这种形态**」（新颖性/低置信），**不是**一个已被验证的「未知攻击检测器」。后者的能力边界见 `results/openset_report.md`：

* 把整类攻击从训练里拿掉时，该分数能把未知攻击与已知窗口分开（跨场景 AUROC ≈ 0.978）；
* 但**留出的攻击越像正常流量，低误报预算下越检不出**（留出 Botnet 时 1% 预算只有 44.3%、0.1% 预算仅 0.9%）；
* 因此**不要用未知标记替代二分类告警**，它是叠加在告警之上的一层「要不要人工研判」的提示；
* 换网络/换采集口径后阈值必须重新标定（正常流量的分数分布会变）。
