# 域随机化跨域：把「零样本跨域不可用」变成一个有解方案（或如实说它不成）

> 由 `tools/domain_randomization.py` 生成。**判据事前写死**；跨域评估严格零样本（标准化器只用训练域 fit，目标域一个样本都不参与）。

## 0. 结论

- 判定：**在本仿真框架内不成立**：多域训练没有带来显著、可归因于多样性的零样本增益。
- J1（多样性有效）：0.006318566950037842 的均值提升，逐折 3/6 折为正，符号检验 p=1.000 → ❌ 未通过
- J2（增益不只是因为数据变多）：同数据量单域对照下均值提升 0.29193245103969007，p=0.219 → ❌ 未通过
- J3（代价）：域内宏 F1 变化 -0.029172549431065276（负值表示多域训练牺牲了域内精度）

## 3. 与既有跨域失败实验的关系

`results/cross_dataset_report.md` 里的失败实验是**自研仿真 → 真实公开数据集**，诊断出的根因是采集口径/域分布不匹配，并给出下一步建议「域随机化」。本实验把那个建议**做完**：在仿真框架内造出多个采集条件并做留一域零样本。两者的区别必须讲清楚：**本实验证明的是「多域训练能否缓解域漂移」这一机制**，**不能**替代「真实目标域」上的验证（真实数据的口径差异比这里的域间差异更极端）。

## 4. 局限（写清楚，不粉饰）

- 域是**用同一生成器旋钮造出来的**，域间差异小于「仿真 vs 真实」的差异；因此这里的结论是**机制层面的**（多样性有没有用），不是「跨域问题已解决」。
- 每折只有 3 个训练设定、单一模型结构（cnn_bilstm）与单一种子：量级可信，单点数值不宜外推。
- `single` 基线固定取「其余域中的第一个」（事前写死），没有对全部单域求平均（那样会让算力翻数倍，但结论更稳）；`multi_matched` 提供了「同样本量、更多多样性」这一侧的对照。
- **等预算对照不能靠「复制同一域」实现**：数据管线会 `drop_duplicates` 掉完全重复的行，复制等于没加数据（本工具最初就踩了这个坑：两次结果逐位相同才发现）；等预算只能靠「多域 + 每域抽样」。
- 目标域评估用的是与训练相同的窗口规则与 pure_only 过滤；真实部署还需要考虑在线口径（阈值/确认次数需要按目标域重新标定，见 `tools/calibrate_online.py`）。

## 5. 复现命令

```powershell
python tools/domain_randomization.py --domain-flows 0.12 --epochs 20
```
