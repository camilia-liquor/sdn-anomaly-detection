## 四、诚实与口径说明（逐条）

1. **进程内调用**：本演示直接在本进程里调用 `src.service.DetectionService`（与 `app/app.py` 的 `/api/detect`、`tools/controller_simulator.py` 是同一个引擎），**没有**另起 HTTP 服务、**没有**联网，因此屏幕上也不存在端口。
2. **处置的性质**：服务处于 `dry_run`，给出的是**策略建议**（observe/throttle/block）；本演示中的“已加入阻断名单”由脚本内置的**本地模拟执行器**完成（带有效期），**不是**真的下发改动交换机流表。真实下发由 `integrations/ryu_guard.py` 通过 OpenFlow 完成，**本机没有 Ryu 环境、未实跑**（其接口与判定逻辑由 `tools/controller_simulator.py` 在无 Ryu 环境下验证）。另外本场白名单为空（不豁免任何源地址），即策略不会因为白名单而跳过任何源地址；上线前必须按 `deploy/cida-detect.env` 配好白名单。
3. **检测时延口径**：只取**真实流时间戳**之差（攻击片段起点 → 首个确认告警窗口的右端行），与 `src/evaluate.py` 完全一致；**不是**墙上时间，也**不**随回放倍速变化（本报告只有“回放倍速”那一行会随 `--speed` 变，检测时延、误报数、一致性核对都不变）。注意本数据集的流记录间隔在同一片段内为亚毫秒级，因此毫秒数天然很小，“折合多少条流记录”才是与离线报告可比的量。
4. **误报口径**：确认告警的窗口内若**没有任何**被标注为攻击的流记录，即计一次误报（与 `src/evaluate.py` 的注释同口径）。正常阶段出现的告警一律原样打印并在第五节列出，不做隐藏；屏幕上把连续的确认告警合并成一次“告警爆发”显示（只印首条与计数），但第五节与本报告的计数、以及 `results/live_demo_audit_DoS.jsonl` 里是**全部**条目，一条都没有被合并掉。
5. **风险回落 ≠ 处置有效**：回放的是历史数据，攻击片段结束、真实标签切回 Normal 之后风险自然回落。本报告**不**声称是阻断动作压住了攻击，也**不**声称在真实网络上验证过防护效果。
6. **数据真实**：回放 `data/processed/tensors.npz` 的留出测试流（真实标签 + 真实流时间戳），“注入攻击”只是把回放位置放到真实攻击片段起点（与 `app/app.py` 的 `/api/first_segment_of` 同性质）。
7. **源 IP**：取自 `data/raw/` 原始 CSV 的 `Source IP` / `Destination IP` 真实字段。
8. **审计台账**：本次告警写入 `results/live_demo_audit_DoS.jsonl`（每次演示重写，只反映本次），**没有**混进 `results/audit_alerts.jsonl` 那份真实闭环台账。
9. **剧本跳转**：本剧本有 **3 处位置跳转**（正常回放（攻击前）、真实攻击片段（DoS）、恢复回放（攻击后））——测试流里攻击片段密集交错（实测各攻击类**后接正常流量的中位数为 0 行**），缺少足够长的连续正常流量，无法拼出「安静基线 + 攻击 + 恢复」的单一连续区间。跳转处我们**主动重置了滑窗缓冲（本场 3 次）**，因为这等价于真实环境里的「上游数据中断」：若不重置，中断前后的行会被拼进同一个窗口，生成**现实中不存在的窗口**（它在全局行号上并不连续）。重置后本场的每一个窗口都是真实连续窗口；代价是跳转处会丢掉不足一个窗口的已积累行（已在屏幕上如实打印），且与离线评估的可比窗口会相应减少（见第三节最后一行）。
10. **可复现**：模型推理是确定性前向计算，剧本由参数唯一确定，且与离线评估共用同一批滑窗；报告里所有数字都不依赖运行时机（服务侧的墙钟推理时延只上屏幕，不入报告）。逐窗口核对中的极小概率差（见第三节最后一行）来自“反标准化 → 服务内部再标准化”的浮点往返——服务接口按**真实物理量**接收流记录（与 `tools/controller_simulator.py` 同一做法），本场没有任何窗口的判定类别因此改变。
